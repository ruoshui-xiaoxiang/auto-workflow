## 一b、运镜**词表**对账（本轮补做：外部类型清单 ↔ 现役 R2-05 十三类）

§一 那八条都是"怎么动才算对"的语法，**没往词表里加词**。加词是另一件事，必须先对账。

**先报一处现役条目的自身错误**：`R2-05` 写"受控词表 **14** 类"，同行列出的词只有 **13** 个
（`Zoom / Push / Pull / Pan / Tilt / Truck / Pedestal / Arc / Tracking / Static / Shake / Roll / POV`），
而 H3 侧两份真源（`H3提示词规则_现行合并版.md` §五、`H3提示词工程规则方案.md` §五标题）都明写"**13 类**"。
⇒ 要么计数改成 13，要么确有第 14 个词在抄写时丢了。**这条与外部检索无关，是我们自己内部的计数漂移**，
扫描器不解析这句自然语言所以没抓到；建议单独裁一次（改哪边由他定，我不擅自动现役条目）。

对账表（外部叫法 → 我们能不能写）：

| 外部运镜类型 | 我们词表里 | 结论 |
|---|---|---|
| dolly in / out（推轨推拉） | `Push` / `Pull` ✓ | 已覆盖，且 `Zoom ≠ Push` 的易混对已写在 R2-05 第 2 条 |
| pan / tilt | `Pan` / `Tilt` ✓ | 已覆盖 |
| truck（横移）／pedestal（升降，不改俯仰） | `Truck` / `Pedestal` ✓ | 已覆盖 |
| arc / orbital（环绕） | `Arc` ✓（明写 `Arc ≈ Orbital`） | 已覆盖 |
| tracking / follow | `Tracking` ✓ | 已覆盖 |
| static / locked-off | `Static` ✓ | 已覆盖 |
| handheld / 手持晃动 | `Shake` ✓（近似） | 基本覆盖，但"手持的呼吸感"与"乱晃"在词表里同一个词 ⇒ 靠幅度＋速度槽区分 |
| roll / dutch 倾斜 | `Roll` ✓ | 已覆盖 |
| POV 主观镜头 | `POV` ✓ | 已覆盖 |
| **crane / jib（升降臂：边升边改俯仰）** | ✗ **表达不了** | `Pedestal` 被定义成"不改俯仰"、`Tilt` 只转不升 ⇒ "升起同时压俯角"这类**揭示大全景／穿云镜的常用做法**没有词。而 `feedback-previz-camera-rhythm` 正好要求"上升／穿云镜中段要有停顿拍"——**我们的实测需求先于词表存在** |
| **whip pan（甩镜）** | ✗ 无词 | 我们**自己有三次独立观测**支持它（记忆层《甩镜替代切镜》），只是没进词表 ⇒ 可入库，**出处用我们自己的实测**，不借外部说法（外部正文核验不了，已列 §四） |
| **rack focus / focus pull（跟焦、焦点转移）** | ✗ **整个维度缺失** | 13 类全是"机位／镜头怎么动"，没有一条是"**焦点落在哪、什么时候换**"。而 AI 侧的实际病灶恰好在这：模型常做成"整幅糊化再变清"，不等价于真跟焦 ⇒ 这是摄影层的一个**缺维度**，不是缺一个词 |
| **dolly zoom / 眩晕变焦／crash zoom（急推）** | ✗ 有意不加 | 外部机制清楚（Vashi Visuals、ASC "zoom-dolly hybrids"），但平台能力不支持：Hailuo 官方因深度估计不可靠**不建议**，ShotVerse 把 orbit/复合几何列为 out-of-distribution ⇒ 建议登记为**"知道但禁写"**，写进去只会被渲成普通推拉（对应 §一 R3-08） |

三条新增定义的**写法草案**（都遵守 R2-05 自己的约束：写成动作＋幅度＋速度、**禁器材名词**）：

1. `Jib`（或中文形"升臂"）：非器材写法＝「镜头垂直上升同时俯仰角连续变（升起过程中俯角从 X 收向水平），幅度大、速度缓起缓收」。
   与 `Pedestal`（不改俯仰）、`Tilt`（不位移）三者互斥，写进易混对表。
2. `Whip`（甩镜）：「镜头以极快速度横向甩动，中途画面拖影不可辨认，起止各稳定 ≤0.3s」。**限定用途**：作为"两个不连续动作之间的接镜手段"，出处是我们自己的三次观测，不是外部词条。
3. `Focus`（跟焦／换焦，作为**新维度**而非第 14 个运动词）：「焦点从 A 移到 B，移焦时机与画内动作同拍；A、B 两态各自描述清楚」。
   ⚠ 建议不要塞进"运动类型 13 类"里——它和 Push/Pan 不同轴，塞进去会让词表变成混合维度，G7 判定与 `prompt_lint` 词表都要跟着改。

**为什么这三条现在还不能直接写进 R2-05**：词表是**现役机器判定的输入**。R2-05 的槽挂着 `G7` 的运镜判定、`prompt_lint.NEG` 单源词表、H3 侧 `[报]`「本项目【镜头】写中文动词、未上英文受控词表」，
以及各通道 yaml 的 `prompt_kind` 派发。加词＝改现役行为，按 `R5-15` 与本轮尺寸那批的同一套纪律走：
**先在历史批次上量影响面（有多少现成稿会因新词被判越表）→ 三重预验 → 他点头 → 才成文**。
另外还有一个未裁岔口：新增词用**英文形**（跟 H3 官方 13 类一致）还是**中文形**（跟我们现在【镜头】实际写法一致）——这个岔口和 §五 待裁-02 的"片内切镜写法口径"是同一类问题：库里同时并存两套书写形，一直没裁统一。

### 一b·补二　官方原文实读（本小节作废上面两段，以这里为准）

出处：`E:\本地工作流规范手册\02_H3提示词规则\官方模板_基础三字段_base-en.txt` §4.3
「Camera Motion: Motion Type + Amplitude + Speed」——**官方确实有一张固定表**，
所以"受控词表"这个说法成立，不是我们归纳的。但三个数都对不上，且我上面两段有错：

| 项 | 官方实际 | 我们库里 |
|---|---|---|
| 运动类型行数 | **12 行**：`Zoom In/Out`｜`Push In/Pull Out`｜`Pan Left/Right`｜`Truck Left/Right`｜`Tilt Up/Down`｜`Pedestal Up/Down`｜`Arc Shot`｜`Tracking Shot`｜`Static Shot`｜`Shake Slightly/Strongly`｜`POV`｜`Roll Clockwise/Counterclockwise` | `现行合并版:50` 与 `方案 §五` 写 **13 类**（把 `Push In`／`Pull Out` 拆成两个词根数）；`R2-05:185` 与 `硬参数速查表:170` 写 **14 类**——**两处都对不上官方** |
| 幅度 | 官方给两档：`with small amplitude`／`with large amplitude` | **档位没抄进 R2-05**，条内只出现"中幅度／大幅度"这种例子 ⇒ 库里看不见官方刻度（我上一轮据此说"没有刻度"，**错了**） |
| 速度 | 官方给两档：`at slow speed`／`at fast speed` | 同上，没抄 |
| 方向 | **内建在类型词里**（Pan/Truck/Tilt/Pedestal/Roll 都是成对方向短语）；`Arc`／`Tracking`／`Static`／`POV`／`Shake` 不带方向 | 我上一轮说"第四根轴没有词表"**不准确** ⇒ 撤回。真缺口只有一个：`Arc` 没规定顺／逆时针（官方只在 `Roll` 上给了 Clockwise/Counterclockwise） |

**顺带查出一条真冲突（比计数错更值钱）**：官方 §4.3 原话
「Add amplitude and speed **only when they are meaningful**; **medium amplitude and normal speed are usually omitted**」
——而 `R2-05` 判据是「写法＝**运动类型＋幅度＋速度**」（三件齐全）。
⇒ **我们要求填的两件，官方说通常该省略**。照我们的条写，会稳定产出 `中幅度常速 Push In` 这类官方建议丢掉的废话，
还可能挤占 R2-11 的容量。这条要裁：是三件齐全改成一型＋可选两档，还是维持（那就是明知与官方不一致而故意的，得写下理由）。

**因此候选 R3-09 改写**（原来那版本要自造三档刻度，作废——**不要自己造一套跟官方打架的刻度**）：
把官方 `2×2` 直接抄进 `R2-05` 当受控值，英文短语照官方原形（`with small amplitude`／`at slow speed`），
中文形作为项目层槽位映射（`小幅度`／`慢速`）；`Arc` 补一个顺／逆时针的写法约定。
这样 R3-09 的阈值不再是"待自标定"，而是"照官方抄"——待裁-07 里那部分可以摘掉。

**同一段还捡到两条有官方出处的条目**（比外部教科书硬，优先用它们）：
- 官方 §4.2：「A cut should introduce **new information** about the subject, space, state, viewpoint, or time.
  If only the distance or a slight angle needs to change, **prefer camera motion**.」
  ⇒ 建议入 R3 切镜段（拟 **R3-18**）：**只是距离或微角度变化就不许切，改用运镜**；
  这条正好接上我们"默认不分段"与"相邻镜必须够不同"的裁决——判据从"够不同"升级成"切点必须带来新信息"。
- 官方 §4.2：「When **explicitly requested by the user**, cross-dissolve, fade, or wipe may also be used.」

## 五、要他裁的（进 `R_作用域与例外登记表` §二 队列）
