# H3 视频生成 · 人物动作提示词规则（跨剧本通用）

> 适用范围：本地 ComfyUI MiniMax H3（含 ComfyUI_H3 实例）。规则本身与具体剧本解耦，任何项目套用同一套规则。  
> 版本 **v2.1** · 2026-09-27 修订（v2 · 2026-09-26）· 依据：H3 官方 `skills/h3-prompt-writing` 规范 + 社区实测 + 本项目多镜实测踩坑。  
> v2.1 改了什么：**只改 R5 一条的判据口径**（正向物理描述＝判据，排除句降级为"可留但不计效"），依据＝本机实测"H3 禁令即在点名、压不住"（09-22 打戏同帧 + 09-26 夜跑"枪"字泄漏），2026-09-27 经用户批准。其余逐字未动。  
> 覆盖：**对抗类（打斗）+ 通用人物动作**（走路/转身/起坐/拿道具/情绪动作），同一套规则。  
> 原则：**以下每条规则都来自实测，不是预设定理；换模型/换参数后需重测复核。**

## 一、H3 提示词的本质：结构化控制文档，不是散文

H3 用「语言作为连接所有模态的桥梁」，提示词质量直接决定输出质量。官方把视频控制拆成**六层**，写作顺序固定：

| 层      | 解决什么                    | H3 官方骨架里的落点      |
| ------ | ----------------------- | -------------- |
| 1. 目的  | 这条视频为什么存在               | 首句（横屏/秒数/一镜到底）＋ `[Shot 1]` 开头的场景定位 |
| 2. 不变量 | 什么绝不能漂移（人物身份/道具结构/品牌字）  | `integrated_multimodal_description` 里的身份/服装/武器状态句（末尾 `Throughout: …`） |
| 3. 事件  | 画面里实际发生什么（动作顺序/关系/状态变化） | `integrated_multimodal_description` 的时间线正文 |
| 4. 摄影  | 观众如何看见（景别/机位/运镜/对焦）     | `integrated_multimodal_description` 末尾的运镜句（类型＋幅度＋速度） |
| 5. 质感  | 它属于什么世界（光/色/材质/媒介）      | `integrated_multimodal_description` 开头的风格与光影句 |
| 6. 声音  | 观众如何听见（对白/音乐/环境声/音效）    | `overall_soundscape`（对白在正文 `<d>` 里，不在此重复） |

**铁律：先写不变量→事件→摄影，最后补质感。** 只写「高级、电影感、炸裂」形不成可执行镜头。

## 二、模式选择（跨剧本决策表）

| 模式     | 输入                | 用途            | 提示词结构 |
| ------ | ----------------- | ------------- | ----- |
| T2VA   | 纯文本               | 无参考、纯生成       | 三字段   |
| I2VA   | 1 张图              | 从首帧向前发展       | 三字段   |
| FL2VA  | 0–2 张图            | 首尾帧之间连续路径     | 三字段   |
| L2VA   | 1 张图（尾帧）          | 推断开头、收敛到尾帧    | 三字段   |
| Ref2VA | 图≤9 + 视频≤3 + 音频≤3 | 多参考、锁身份/风格/音频 | 六段式   |

**决策规则**：

- 锁身份/道具/场景 → 用 **Ref2VA**（多参考，4 张图起）。
- 只给一张首帧 → **I2VA**。
- 给定尾帧、要模型补开头 → **L2VA**。
- 首尾都要、中间路径由模型填 → **FL2VA**。

## 三、通用提示词模板

### 3.1 基础模式（T2VA/I2VA/FL2VA/L2VA）三字段

```
integrated_multimodal_description: <按时间线描述画面，含镜头指令>
overall_soundscape: <环境声 + 对白，用引号写台词>
non_diegetic_music: N/A
```

### 3.2 Ref2VA 六段式

```
subject_definitions: <主体定义：图1是X、负责身份；图2是Y、负责道具……>
summary: <一句话视频概要>
retention_analysis: <哪些特征必须全程保持一致>
detailed_description: <按时间线展开画面与动作>
overall_soundscape: <环境声 + 对白>
non_diegetic_music: N/A
```

### 3.3 H3 视频提示词结构：官方 I2VA 骨架（预检 G7 要求）

```
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description:
[Shot 1] …（画面内容 + 时间线动作 + 台词 <d>[中文] 原句</d> + 运镜句）
overall_soundscape:
…（环境底噪 + 动作物理声 + 非语言人声）
non_diegetic_music:
N/A
```

**硬要求**（`check_preflight.py` 的 G7，`h3_i2va` 与 `video` 同判据）：首行指令逐字一致＋空行；三个字段各恰一次且顺序不变；正文以 `[Shot 1]` 开头；只挂 `<Picture 1>`（不许 `<Picture 2>`/`<Video>`/`<Audio>`/`subject_definitions:`）；不出现运镜器材名词。

> **⚠️ 2026-09-28 变更：中文十块模板已从 H3 剥离**，改作**云端 SD 通道**（Seedance 视频／云端出图）专用格式，见 `云端SD提示词模板_十块.md`。
> 依据＝A/B 实测（`wzy/ab_tenblock.py`，5 seed × 2 臂，同首帧同 seed 同 LoRA）：**十块写法 4/5 条出现乱码，官方骨架 0/5**；乱码原文直指【保持一致】里的元叙述句（"他只说上面写出的那一句台词""其余时间没有任何说话声"）被 H3 当台词念出来。
> 一句话：**十块不是格式不兼容，是它的元信息块会给 H3 多开口子**——所以十块留给云端，H3 用官方骨架。

## 四、硬约束清单（跨剧本通用，逐条来自实测翻车）

> 这些是「写进【保持一致】或【镜头】的硬话」，不是建议。

| #   | 规则                   | 为什么（实测翻车）              | 标准写法                                       |
| --- | -------------------- | ---------------------- | ------------------------------------------ |
| R1  | **道具形态锁死**           | H09 长枪变长剑              | 「X 始终为一件、形态数量不变、不露本体/不替换」                  |
| R2  | **方位朝向锁死**           | 多人对峙敌人站到主角身后           | 「A 与 B 始终面对面、正对、绝不站到对方身后」                  |
| R3  | **一镜一主动作**           | T12 塞 5 个动作，结尾被吞       | 5 秒只放「一个主动作 + 一个收势」                        |
| R4  | **招式来回拆段**           | 多招连击漂移+丢招              | 每段一个回合，尾帧承接续下一段                            |
| R5  | **特效写实化**            | 生成式特效易画成能量波/激光         | **判据＝正向物理质感必写**：「细碎橙金色光点＋半透明银白余辉」这类看得见的材质与形状。排除句（"不要能量波/激光/爆炸"）**可留作保险、但不计效**——H3 上禁令即在点名，压不住（v2.1 改判） |
| R6  | **长片段拆 15s**         | >15s 物体变平、连续性漂移        | 官方上限 15s，长戏拆 15s 段 + 尾帧承接                  |
| R7  | **收尾留时间**            | 收势被下一动作挤掉              | 事件脚本最后 1s 明确留给「收势/定格」                      |
| R8  | **光影写实动词**           | 红光被画成激光束               | 写「光映在/洒在」，不写「流出/击中/射出」                     |
| R9  | **声音必写**             | 不写会出乱码杂音               | 【声音】写环境声+台词，明说「不要音乐」                       |
| R10 | **动作质感/能力层次**        | 只写动作动词→演成"泼妇打架"        | 点明谁高手谁菜，用章法词「马步沉腰/枪花一抖/借力打力/收放有度」，对手「蛮力乱扑」 |
| R11 | **一镜到底容量上限**         | 塞 5 个动作→「躲过/前冲」被吞、拳打中脸 | 一镜到底 ≈ **2 个核心精细动作 + 1 个惯性过渡**，超过就拆段       |
| R12 | **接打一体，避免分步衔接**      | 「侧身让过→前冲→再推」中间有断层、衔接生硬 | 设计成连续攻防：「格挡的瞬间就反击」，不写「躲过→等对方前冲→再还手」        |
| R13 | **抽象概念翻译成物理动作**      | 「借力打力/以柔克刚」是抽象词，H3 读不懂 | 落成具体动作：「按在肩背顺势一推」「抓住手腕往旁一带」，不写「借力」         |
| R14 | **动作底线写死**           | 主角躲闪时仍被演成「拳打中脸」        | 关键底线写进提示词：「拳头绝对没碰到脸、绝不用脸接这一拳」              |
| R15 | **动作容量 = 步数 × 剧烈程度** | 打斗 6 步糊+漂、单人日常 6 步却清晰  | 越剧烈越要少步（打斗 2~4 步甜点）；越从容越可多步（日常 6 步+ 仍清晰）   |
| R16 | **一镜一场景** | H01「屋内砚下留信→院墙外翻墙」跨场景，H3 串场景或丢动作 | 单镜只能在一个场景内演动作；跨场景的戏拆成多镜（每镜配对应场景锚） |
| R17 | **时长 = 信息单元 × ~1 秒（不定死 5 秒）** | P1A「4动作+3句台词」8 单元硬塞 5 秒超载，靠 H3 拖长台词+自动合并细节兜底；另实测：动作数不变光拉时长（7.3s 塞 4 步）只会拖长凑时长 | 先算信息单元（1 动作=1、1 句台词=1.5-2（口型+听者反应）、特写展示细节各 0.5），**时长 ≈ 单元数 × 0.9-1.2 秒**，向上取模型帧网格（H3 17n+5：124=5.2s / 175=7.3s / 192=8s / 209=8.7s / 243=10.1s / 362=15.1s；万相 3.0 任意 2-30s）。信息多的镜直接给长时长，信息少的镜用短时长——时长跟信息走，不跟 5 秒死档 |
| R18 | **空间一致性（敌我轴线／朝向／相机在哪一侧）** | 段2 缠身版 v2 人审"链子往侧面跑、男子站位总是背对女子"，逐帧回查**三条病灶是稿子自己写的**：镜3 顶视角拍他的背、镜2 明写"转四分之一圈"把他转开、中景只框一个人（轴线在画面里根本看不见）。另：R2 的标准写法"绝不站到对方身后"是**禁令句，H3 侧不计效**（与 R5 同判），必须换成正向朝向句 | 五件事逐镜写全，缺任一件模型就自己选边：① **声明相机在轴线哪一侧**（from in front of him／from her side／over his shoulder／top-down／three-quarter）；② 双方同框且有交接动作 → 同镜必须有 **facing／toward her** 类关系词（裸 "face-first" 不算，那是摔趴方向）；③ **取景句里不写背向词**（his back／后颈／from behind），要拍背就同时写"他正面朝她"；④ **不写把人转开的旋转词**（turned a quarter／spun around）除非同镜写"转回面对"；⑤ 投射物飞行要**两组词都在**：朝目标（toward/aimed at the man）＋沿两人连线（straight/along the line between them/between the two bodies）。机检：静态 `h3_rule_gate.py --files`（18a–18f，18c/18d 为 error）＋出片后 `技能包转H3_SOP/工具/qc_face.py`（他那一侧脸可见率；**全景镜不可用**） |
| R19 | **特写镜必补皮肤与镜头质感，否则特写自动变 CG** | 09-30 段2 v3 人审"前边真人实拍、后边变 CG"。逐镜量（脸占画面面积当景别代理，两条片各八镜 n=16）：**脸占 ≥1.5% 的镜锐度（拉普拉斯方差）均值 82、彩度 90；脸小的镜锐度 169、彩度 82**（脸面积↔彩度 Pearson +0.56、↔锐度 −0.42）。⇒ **画风漂移跟景别走、不跟时间走**：一进脸部特写 H3 就给磨皮＋高饱和。段1 同病且更重（末镜脸占 25.6%、锐度 58.9 是十六镜最低）——已交付那条也一样，只是他糙脸的动画感比年轻女性脸弱 | 凡脸／手进特写的镜，补**看得见的皮肤与镜头质感**：`pores and fine stubble across his jaw`、`sweat tracking through the dust on her temple`、`warmth showing through the skin at the nose and ears`、`grit stuck to the damp skin`、`shallow depth of field, the background falling into soft circles`、`fine film grain`。**不写 `realistic skin`／`hyperrealistic` 这类评价词**（与 R5 同判：正向物理描述才是判据）。机检：静态 `h3_rule_gate.py H3R19`（特写镜缺质感词＝warn）；出片侧 `qc_face.py` 旁边配一把"逐镜锐度＋彩度"尺（见 SOP §5 第 9 条）。**⚠️ 09-30 v5 复测：本条按"文字层"判无效**——同锚同 seed 只加三处特写质感词，镜8 整帧锐度 71.5→**55.0**（要 >100）、彩度 105.4→**106.7**（要 <95），两项预登记验收数全部未达；脸内锐度 23.4→32.1 方向对，但**同一处没改动的镜2 从 160.8 摆到 263.5**，说明这把尺子的批内噪声大过效应量，不能用于 A/B 归因。⇒ 结论：特写磨皮属**模型层**，词留着不再加分也不扣分，实拍感交给后期一层颗粒（见 SOP §6） |
| R20 | **收招要一击干脆，禁写双向拉扯／僵持** | 09-30 段2 v5 人审原话："链子缠身之后有拉扯的动作，这样反而会不好看……这种动作要干脆利落，比如缠身马上收紧、男子随即痛苦倒地；或者缠上脖子提到半空、快窒息时松开、痛苦倒地。"逐镜回查，两处都是稿子自己写的**双向受力句**：镜5「the pull **drags her toward** him … she **leans her weight back** until the coils stop her」、镜7「She **hauls back** with her whole body」。拉扯＝攻守互相抵消，观众看不到谁赢，节拍还容易被演成站着较力 | ① **不写一方把另一方这个人拖着走**（drag/haul/pull + her/him、lean one's weight back、back and forth、struggle、僵持）；受力对象只能写成**物**（链子拖过灰、绷直），不能是人。② 收招一拍完成：动作与结果写在**同一句**里，并带"同拍词"（at once／in the same motion／in one unbroken beat／snaps／随即／应声）。③ 要"腾空／击倒／窒息"这类高结果时，**同镜给出受力凭什么**（她手臂锁直、重心沉进髋、靠桩不靠臂），否则模型降成推搡。④ 声音段同步查：较力配音（boots skidding／she is dragged）会把僵住再演一遍，删。机检：静态 `h3_rule_gate.py H3R20`（20a 双向拉扯＝error，20b 全篇无同拍词＝warn；词表只收"把人拖走"，不收裸 pull／drag） |

## 五、镜头运动术语表（H3 官方 13 类 + 幅度 + 速度）

**写法 = 运动类型 + 幅度 + 速度**，每镜头只写一条相机指令。例：`中幅度慢速 Push In`、`大幅度 Truck Right`。

运动类型：`Zoom / Push / Pull / Pan / Tilt / Truck / Pedestal / Arc / Tracking / Static / Shake / Roll / POV`

关键区别：

- `Zoom` = 焦距变化（相机不动）；`Push` = 相机实体前移。二者不可混用。
- `Truck` = 横向平移；`Pedestal` = 垂直升降（不改变俯仰）。
- `Arc` = 环绕；`Orbital` 同义。

**写「镜头动作」比写「结果描述」有效**（官方实证）：

- ❌ 「人物始终完整入镜」
- ✅ 「镜头以人物步行速度大幅度 Pull Out，始终保持全身构图」

多素材时，一句话锁定主次：

```
图1 严格负责人物身份与服装；图2 只负责道具外形；
视频1 负责动作节奏；冲突部分以图1 为准。
```

规则：

- 哪份决定身份、哪份只提供姿势/光/风格 → 必须写明。

- **参考越重，文字越短**——身份/道具交给图，文字只写「真正变化的部分」（动作、方位、新增物）。

## 九、实战示例（武昭君仪 · 示范，规则本身通用）

### 双人打斗（套用 R1/R2/R3/R5）

```
武君仪全程破损深红劲装、脸上伤痕、泥污，长枪始终为一根、白麻布裹严、

两人始终面对面、绝不站到对方身后（R2）。两人无台词、不出声。
画面不得出现任何文字、字幕、水印、台标、logo。
```

### 招式来回（套用 R4）

一个 15s 战斗 = 3 个 5s 段，每段一个回合，尾帧承接：

- 段1（0–5s）：对方扑抓 → 侧身卸力 → 枪尾扫腿
- 段2（5–10s）：对方再扑 → 横扫逼退

### 特效（套用 R5）

```
【风格与光影】
火花是细小橙金色光点、气浪是半透明的银白余辉（明确物理质感）；  ← 判据，缺它必漂
不得画成能量波、激光束、爆炸（明确排除生成式特效）。                        ← 保险句，H3 上不计效
```

> v2.1：真正拦得住生成式特效的是**正向物理描述＋首帧像素**，不是排除句。排除句写成"不要 X"就是在替模型点名 X。

### 动作质感（套用 R10）

```
【主体与关系】
武君仪自幼习武、枪法娴熟、出手干净利落有章法；粗臂男是街头混混，

【事件脚本】
武君仪马步沉腰、双手端枪，枪花一抖先探对手虚实；粗臂男扑来，

【保持一致】
武君仪全程是练家子的章法——马步沉稳、出枪利落、力道收发有度，
绝不慌乱抓挠、绝不手忙脚乱；粗臂男全程是混混的蛮力——动作粗笨、
```

## 十、内容质检配合（生成后自动核查）

提示词写完 ≠ 万事大吉。生成后用 VL 抽帧核查四个维度（见实测）：

1. **道具形态**：问「武器是枪还是剑？一根还是两根？」
2. **空间关系/朝向**：问「谁面对谁？还是站到谁身后？」
3. **动作到位**：问「有没有演到某个动作？」
4. **动作质感/能力层次**：问「打斗像高手过招、有章法，还是像乱扑乱抓？」

> 这四问要写进 `vl_qc` 的 question，不要笼统问「谁在场/有没有瑕疵」——单帧识别分不清「运镜转走」和「主体消失」，会误报。

## 十一、武术动作编排（招式术语 → H3 动作描述）

> R10 的具象化。实测结论：**「专业有章法」这类抽象形容词无效，生效的只有写清楚的招式动作**。孤立浅动作（马步/横扫）只会演成「会个起手式的初学者」，需要的是**有攻防因果的招式编排**。

### 枪法招式转换表（术语 → 身体动作轨迹）

| 招式  | 含义     | H3 提示词写法        |
| --- | ------ | --------------- |
| 拦   | 枪杆横摆格挡 | 枪杆横摆，格开对方抓来的手   |
| 拿   | 枪杆下压黏住 | 枪杆下沉一压，黏住对方手臂   |
| 扎   | 直线前刺   | 枪头直线向前刺出，直指对方咽喉 |
| 崩   | 由下向上弹  | 枪杆由下往上一抖，弹起挑开对方 |
| 点   | 向下点击   | 枪头向下一沉，快速点向对方手腕 |
| 穿   | 从下穿进   | 枪头从对方手臂下方穿进     |
| 压   | 向下压    | 枪杆向下压住对方兵器      |
| 劈   | 从上向下劈  | 枪杆高高扬起、向下劈落     |
| 缠   | 绕转缠绕   | 枪杆绕对方兵器转一圈，绞住   |
| 舞花  | 身侧翻飞划圆 | 枪杆在身体两侧翻飞划圆     |
| 回马枪 | 假败回刺   | 假意转身败走，突然反身回刺   |

> 落地办法：`DEGUN` 已补 21 条显式词形（长枪/枪杆/枪头/枪尾/枪身/提枪/端枪/握枪/裹枪/收枪/背枪 ＋ 枪花/枪尖/枪法/枪缨/枪柄/回马枪/一杆枪/扎枪/拿枪/舞花），并加了**词形覆盖自检**与**坏中文报错**（裸兜底若产出"长杆花/长杆尖"这类词就 `SystemExit`）。
> 教训：**静默改坏中文比不改更糟**——"枪花"被裸兜底改成"长杆花"，"枪"字确实没了、字面闸查不出来，但中文是坏的。

### 编排原则（四拍法）

**起势（预备架势）→ 冲势（进攻发力）→ 收势（收回）→ 回势（恢复架势）**，节奏快慢相间、刚柔并济；每招之间写清**攻防因果**（对方出招 → 我化解 → 我反击）。

### 高手打混混的编排范式

对方扑来 → **拦**（格挡）→ **拿**（下压黏住）→ **扎**（前刺，收住不伤人）→ 收枪回势；对方再扑 → **崩**（上挑）→ **点**（打落兵器）→ **舞花**（震慑）→ 端枪立定。

### 动作编排五原则（比"招式"更高一层，用户示范提炼）

招式是"怎么打"，编排是"为什么这么打、打给谁看"。五条原则：

1. **反差**：高手几乎不动 vs 蛮力自取其辱——戏剧性就来自这个落差。
2. **借力打力**：不硬碰，用对方的惯性（侧身闪避 + 绊脚），省力又显智慧。
3. **完整因果链**：挥拳→落空→失衡→绊→扑倒，每个动作都有前因后果，缺一环就断。
4. **省力美学**：高手出手极省、几乎不动——高手气质的核心，越省越像高手。
5. **戏剧性收尾**：狼狈扑倒、满脸羞怒——给观众一个记忆点。

### 四两拨千斤范例（可直接套用）

**定稿版「格挡反击」（用户认可，衔接最流畅）**——一镜到底、接打一体：

主角站定不动 → 混混冲来右拳打脸 → 主角抬左臂一架、格开右拳（接拳、绝不用脸接）→ 借势右手一掌推在混混胸口/肩 → 混混踉跄摔倒、狼狈不已。

关键写法：①「格挡」与「推」写成同一瞬间的连续攻防，中间不留「等前冲」的空档（R12）；②「借力」不写抽象词，落成「架开右拳 + 顺势推一掌」（R13）；③「绝不用脸接这一拳」写死进【保持一致】（R14）。

（定稿提示词见 `prompts/wuzhaojunyi_格挡反击.txt`）

早期范本「伸脚绊倒」（拆段版，备选）：

主角站定不动 → 混混冲来挥拳 → 主角轻轻侧身 → 拳头落空、混混失衡冲过头 → 主角伸脚一绊 → 混混扑倒、狼狈不已。

（完整提示词见 `prompts/wuzhaojunyi_四两拨千斤.txt`）

### 打斗动作两个范式（唯一铁律 = 动作衔接性）

打斗戏不必死守「省力美学」，有两个可套用的范式，**共同底线是「动作衔接流畅、无空档」**：

| 范式        | 气质         | 动作特征            | 定稿范例          |
| --------- | ---------- | --------------- | ------------- |
| **A 省力版** | 高手风范、四两拨千斤 | 借力打力、省力小幅度、接打一体 | 格挡反击（架拳 + 推胸） |
| **B 爆发版** | 干脆利落、爽快    | 爆发有力、连续追击、一气呵成  | 格挡反击 + 抽射踢飞撞墙 |

**为什么爆发也「好衔接」**：发力强的动作中间没有「等对方反应」的空档，一脚接一脚连贯；省力版反而常卡在「等对方踉跄」的分步上。所以**爆发力 ≈ 衔接性**，选哪种看镜头气质，但衔接性是硬标准。

**爆发动作的翻译写法（H3 能懂）**：

- 「抽射」→ 「上前一步、正脚背用力抽射、把对方像踢球一样踢飞出去」；
- 「撞墙」→ 「在地上滑行一段、撞到墙上、瘫倒在地」；
- **衔接时机锁死** → 「趁他刚倒地、还没爬起来」（不等到对方站稳，就不断层）。

**爆发版定稿范例「格挡反击 + 抽射踢飞撞墙」**（一镜到底、4 步连贯）：

主角架拳（绝不用脸接）→ 推胸（混混倒地）→ 趁势正脚背抽射（踢飞）→ 混混滑行撞墙瘫倒。

（定稿提示词见 `prompts/wuzhaojunyi_格挡反击抽射.txt`）

### 交互打斗（从单方面碾压到攻防有来回）

打斗戏的看点在「有来回」，不是一方一直挨打。让对手**顺势反击**，形成攻防交互：

**交互打斗定稿范例**（2 回合、4 步，一镜到底、画面干净）：

混混右拳打脸 → 主角架拳+推胸（混混后仰）→ 混混**借势扑回、左拳反击** → 主角侧身躲过、反手放倒。

关键写法：

- 对手的反击要写「**借势**」：「被推后不肯就范、借势扑回来、抡起左拳反击」——不是被动挨打；
- 【保持一致】里点明「两人是真正的攻防交互、你来我往、互有攻防」。

（提示词见 `prompts/wuzhaojunyi_交互打斗.txt`）

### 动作数 vs 画质（不是硬吞，是「糊 + 漂」）

实测结论：**H3 不是「超过 N 步就硬吞」，而是「动作越多 → 模糊感和漂移越明显」**。

| 动作数   | 画质表现          | 定位       |
| ----- | ------------- | -------- |
| 2~4 步 | 清晰、干净、流畅、无漂移  | 甜点       |
| 5~6 步 | 能演出来，但开始糊、开始漂 | 上限，需接受代价 |
| 更多    | 拖长前面、压缩后面凑时长  | 建议拆段     |

**关键：时间戳是「节奏参考」，不是「动作容量」**——H3 会拖长某些动作、压缩后面的动作来凑满时长（例：4 步交互里「架拳推胸」被拖长 2.6s、「反击+放倒」被压缩到结尾 1s）。所以想要更多回合，靠「拆段 + 干净帧承接」，而不是拉长单镜秒数。

## 十二、通用人物动作（走路 / 转身 / 起坐 / 拿道具 / 情绪动作）

> 打斗只是「人物动作」里最激烈的一类。这套规则（衔接性 / 动作容量 / 抽象转具体 / 底线写死 / 首帧锁姿态）对**任何人物动作**同样成立，可直接套用。

### 关键规律：动作容量 = 步数 × 剧烈程度（R15）

- **剧烈动作**（打斗）：2~4 步甜点，6 步开始糊 + 漂。
- **从容动作**（日常）：6 步+ 仍清晰。
- 实测：单人 6 步从容动作 7.3 秒，画面清晰、无糊、无漂、无穿模。

### 通用动作的写法（同一套规则）

1. **动作链写具体**：每一步写清身体轨迹，不写抽象词；
2. **衔接流畅**：动作一气呵成、不停顿（对应 R12）；
3. **底线写死**：如「不踉跄、不扶墙、枪不脱手」（对应 R14）；
4. **首帧图锁初始姿态**（对应 R2）。

### 示例

**单人从容动作**（6 步、不剧烈，突破 4 步上限）：

站定环顾 → 缓缓转身 → 双手负到身后 → 微微仰头抬眼 → 迈步走几步 → 停下站定。

（提示词见 `prompts/wuzhaojunyi_单人从容动作.txt`）

**拔枪**（4 步、道具交互）：

右手摸向枪柄 → 一把抽出 → 抬臂端枪 → 站定。  
不写「迅速拔枪」（抽象），写「右手摸向枪柄、一把抽出、抬臂端枪」。

**起身**（3~4 步、姿态变化）：

双手撑地 → 单膝跪起 → 缓缓站直 → 站定。  
不写「缓缓起身」（抽象），写「双手撑地、单膝跪起、缓缓站直」。
