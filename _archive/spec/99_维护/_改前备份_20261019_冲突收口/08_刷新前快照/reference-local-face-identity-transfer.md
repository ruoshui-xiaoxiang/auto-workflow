
## 第九条：游戏捏脸图是可以当脸锚的（2026-09-25 实测，修正第八条的适用边界）

第八条说"风格化 CG 脸 SCRFD 检出 0＝机器判分不可用"。**那条只适用于偏卡通的 CG 脸，不适用于写实度较高的游戏捏脸/角色渲染。**
实测：《燕云十六声》捏脸截图 1911×1080，SCRFD 检出 **0.877**，脸 578×771px；两张同角色截图互判 ArcFace **0.712**（同人门槛 0.5）。拿它当 Seedream i2i 脸锚出**全身立像**，五张相似度 **0.702 / 0.801 / 0.804 / 0.809 / 0.832**，全身帧里脸只有 152×207px 时 SCRFD 仍检出 0.79–0.86。
⇒ **报"CG 脸判不了"之前先跑一次检测**，别拿旧结论套新素材。
⇒ 顺带两条：① i2i 挂这种脸锚，**参考图会连画风一起带**（明写"渲染成写实电影级"仍落到 3D CG 立绘），选脸≈选画风；② 挂参考图之后**武器变异消失了**（纯文字 36 张里 6 例"长枪变火枪"→ 挂锚 5/5 正确），**"挂参考"比"写文字"管用的范围比原先以为的宽**。

**⚠️ 但第九条这条路在《武昭君仪》项目上被否了（同日，用户判断）**：身份确实锁到 0.70–0.83，可参考图把**画风**一起带进 3D 游戏 CG 立绘，明写"渲染成写实电影级"也拉不回来。他的原话是"那看来不行，还是得用之前的"。
⇒ **结论：脸锚能锁身份，也能污染画风，两者是同一个机制。** 用非写实风格的参考图当脸锚＝隐性改全片画风。**先定画风，再按这个画风去选锚图来源**，别反过来。
⇒ 从这条实验仍要留下的两条：SCRFD 对写实度够高的渲染脸有效（推翻"CG 脸一律判不了"）；挂参考图比写文字管用、连武器形制都管（挂锚 0 例变异 vs 纯文字 6 例）。

**第九条（2026-09-25，Seedream 4.0 云端 i2i 侧的镜像结论）**：**把一张具体脸"逐条写成文字"再纯文生图，身份一定拿不到**——同一张捏脸脸，挂锚 0.70–0.83，改写成 200 字五官描述后 0.18–0.49，六张全低于 0.5 门槛。文字只承载"类"（鹅蛋脸／长眼／冷感），不承载"个体"。**推论：脸的一致性只能靠图像锚传递，任何"用文字锁脸"的方案都应直接判废，不必跑第二轮。** 同批附带：**"不要火枪／枪托／扳机"三重禁令对武器变异基本无效**（纯文字 42 张变异 11 例；挂参考图 5 张变异 0 例）——**形制类约束同理，图 > 文字**。

**第十条（2026-09-25，画风换了以后脸锚这条链完全够用）**：**"从一张成片候选里裁头肩锚 → 挂锚派生一批"在 3D 半写实国漫画风里同样成立**——从 77 号裁 374×643 头肩锚，SCRFD 0.77、与原图 ArcFace **0.987**（裁切不丢身份）；挂它派生六张，对锚 **0.853–0.905**、六张互判 0.754–0.872，全部过 0.5 门槛。**两条操作要点：① 裁切框要按脸心定量算（左右各 1.35 倍脸宽），本次正好避开了画面两侧那两根矛——锚图里绝不能留武器，否则派生会把它一起带过来；② 在"画风自带年轻脸"的风格里，别用"禁幼态"这类形容词硬顶，挂一张年龄感对的锚更有效。** 对照：同一批里纯文字写的"绝对不要幼态"在写实挂管用、在国漫挂明显变弱。

## ★第十一条：本机 `flux_redux_ref_api.json`（Redux 挂锚）**不承载身份**（2026-09-28 实测，四条条件全败）

`gen_faceA_local.py` 的设计前提是"身份靠 Redux 参考图"，**这条前提实测不成立**。

**测法**：`engine/comfy/flux_redux_ref_api.json`（StyleModelApply，`strength_type: multiply`，`REDUX_STRENGTH=0.9`）
＋ 832×1216 / 20 步 / guidance 3.5 / 同一 seed，只换参考锚与提示词形态。insightface buffalo_l（CPU）量 ArcFace，门槛 0.5。

| 产物 | 参考锚形态 | vs 该锚 | vs A01 定妆基线 |
|---|---|---|---|
| 写实风格词 + 竖图锚 | junyi_face（184×234 脸） | **0.077** | 0.214 |
| 写实风格词 + 竖图锚 | junyi_face_real（395×506 脸） | **0.195** | 0.258 |
| 无风格词 + 竖图锚 | junyi_face_real | **0.233** | 0.278 |
| 无风格词 + **方裁脸**（按工具设计：基准脸方形裁切） | junyi_face_real | **0.303** | 0.340 |
| 无风格词 + 方裁脸 | junyi_face | **0.170** | 0.192 |

**三条判据**：
1. **去掉风格词、换成方裁脸都救不回来**（最好 0.303，门槛 0.5）⇒ 不是提示词干扰，也不是裁切形状问题。
2. **两个不同锚的产物彼此 0.525，高于各自对锚的分数（0.170 / 0.303）** ⇒ **脸是 FLUX 的文字先验给的，不是锚给的**，落回"文字锁脸 0.18–0.49"那一档。
3. Redux 带过来的是**风格与光影**（产物都被带成锚的霓虹调）⇒ 它坐实是**风格适配器**，不是身份适配器。

**连带查出一条更重的**：脸A 训练集（`training/datasets/脸A/1_faceA`，125 件，正是用这套 Redux 挂锚铺的）
里 A01/A02/A03 对自己那张参考锚的 ArcFace = **0.389 / 0.377 / 0.450，三张全低于门槛**
⇒ **已训成的 `faceA_flux_v1` 是建在一份"身份没真正锁住"的训练集上的**，重训前必须先换身份机制。

**⇒ 本机要"锁身份"，Redux 这条路划掉**；现存真正身份型的手段只剩两个：
`IPAdapter FaceID`（`sdxl_faceid_ref_api.json` ＋ `ip-adapter-faceid-plusv2_sdxl.bin` ＋ 同名 SDXL LoRA ＋ insightface ＋ CLIP-ViT-H，**全都装了但从没实测**）
与 **训 LoRA**（但训练集本身必须身份正确 —— 见下）。

## ★第十一条续：FaceID 也实测了，**同样不过**（2026-09-28，同一批武君仪锚）

`sdxl_faceid_ref_api.json`（SDXL base 1.0 ＋ FaceID plusv2，`weight 1.0` / `weight_faceidv2 3.0` / `embeds_scaling "V only"`，30 步 / cfg 6.0 / dpmpp_2m karras），
参考图＝两个锚的**方裁脸**，提示词与 Redux 那条控制组一字不差：

| 产物 | vs 该锚 | vs A01 |
|---|---|---|
| FaceID 挂 锚A | **0.171** | 0.060 |
| FaceID 挂 锚B | **0.106** | 0.071 |
| ［既有］09-16 `tmp/faceA_sdxl_test/sdxl_001` 挂脸A参考锚 | **0.341** | 0.395 |
| ［既有］09-16 `tmp/faceA_sdxl_test/sdxl_002` | **0.391** | 0.279 |

**看图比看数更清楚**：Redux 那个**至少把风格带过来了**（锚B 那半边出了同款霓虹＋红衣＋耳坠），只是脸是 FLUX 的铁打先验脸（更年轻更软）；
而 **FaceID 出的图连风格都不搭**——挂锚A 出的是"高盘发现代时装像"，挂锚B 出的干脆**长出一副圆框眼镜**（该工作流的负面词里没有 glasses 这一项，而 `gen_faceA_local.py` 的尾巴里专门写过 `no glasses`，说明这毛病以前出现过）。

**⇒ 结论（两条机制、6 张图、两条既有历史数据一致）**：**本机"挂参考图锁身份"整体否掉**——
Redux 是风格适配器；FaceID 按现配置连风格都没带上。本地要脸，只剩**训 LoRA**一条，而训练集必须身份正确。

**How to apply**：凡"本地挂参考图锁脸"的需求，先按上表量一次 ArcFace 再谈；**别再把 Redux 当身份锚用**。
关键词：本机 Redux 锁不住脸 / StyleModelApply 是风格不是身份 / 脸A 训练集前提证伪。

**⚠️ 一条操作陷阱（同轮实测，且别拿它当借口）**：`flux_redux_ref_api.json` 的参考图走 `CLIPVisionEncode(crop="center")`，**喂竖图会被中心方裁**——752×1225 的锚图，中心方块落在**脖子/胸口**上，脸根本没进模型。`gen_faceA_local.py` 的设计说明写的正是"基准脸**方形裁切**"，所以**挂锚前先把锚裁成脸心正方形**（本轮按脸框 1.6 倍算，裁后对原图 ArcFace 0.978/0.982＝不丢身份）。**但本轮按方裁重跑仍只有 0.303 ⇒ 裁切形状不是主因**，别用它解释失败。

**⚠️ 别拿"06/09 类历史结论"当挡箭牌**：第九/十条记的是**云端 Seedream i2i** 挂锚能到 0.70–0.90；第十一/十一条续否掉的是**本机**两条机制。二者不矛盾——**"图 > 文字"这条规律仍然成立，但"挂参考图"这个手段只有在承载身份的模型上才成立**（Seedream i2i 是，本机 Redux/FaceID 不是）。

## ★第十二条：云端「不挂锚的纯 t2i」也锁不住（2026-09-28，即梦画布 lite 2K 实测）

规模：**9 张**（`seedream_5.0_lite` / 2K / t2i，`refs` 为空＝**没挂任何参考图**），提示词是**逐条写明五官形制**的 278 字长文；基准＝已 confirmed 的脸锚 `anchors/dingzhuang/junyi_face_jm2156.png`（SCRFD 0.851，脸 325×429）。

| 指标 | 结果 |
|---|---|
| 对锚 jm2156（门槛 0.5） | **中位 0.280**，min 0.175 / max 0.504，**只有 1/9 过** |
| 批内九张互比 | **中位 0.343**，min 0.134 / max 0.522（36 对） |
| SCRFD 可检出性 | **det 0.783–0.891，脸 367–466px**（9/9 检出） |

1. **纯文字连"同一批里是同一个人"都做不到**（批内中位 0.343 < 0.5）⇒ 第九/十一条那条"文字只承载'类'、不承载'个体'"**在云端同样成立**，不只是本地 FLUX 的毛病。**"用文字锁脸直接判废"可以跨通道套用**（[[feedback-per-channel-rules]] 的例外：这条属于机制层）。
2. **但写实档对机检是加分**：det 0.78–0.89、脸 300–470px，比资产包 A01（脸 76×91）强得多；他选写实档的理由之一"写实脸能被 SCRFD 检出"**在即梦 lite 上也成立**。

### ⚠️ 第十二条的边界（2026-09-28 当晚补测，同通道同模型，结论更精细）

同一天在同一个画布（`seedream_5.0_lite` / 2K / t2i / **零参考图**）跑通用角色库批次二，**8 个全新角色各 4 张**，用的是**320–378 字的角色句**（发型、五官、眼妆、唇、肤色、服装逐项点名）：

| 形态 | 同角色内部（同人） | 不同角色之间（换人） |
|---|---|---|
| 特写 T（脸 237–571px） | 中位 **0.528** | 0.327 |
| 全身 F（脸 82–238px） | 中位 **0.513** | 0.265 |

⇒ **纯文字 t2i 不是"一律锁不住"，而是"看角色句的具体度"**：武君仪那次 278 字但写的是"类"（清冷素净、五官精致对称这类抽象形容）→ 批内 0.343；这批逐项点名发型/眼妆/唇形/服装 → **同形态内部 0.51–0.53 过门槛，且与"换人"0.27–0.33 有明显间隔**。**判据修正：具体度足够高时，文字能锁住"同一批内的自洽"；文字锁不住的是"跨批次复用同一个体"——没有锚就没有可比对的靶子。**
**⚠️ 别用第十二条的 0.280 直接否定"文字路线"**——那条测的是"这批能不能复原**已确认的那个个体**"，两件事不同。**且跨形态比一律不算数**（全身小脸会把相似度整体压低，见 [[reference-image-consistency-qc]]）。
3. **反向用处**：做"**一批全新角色**"时，不挂锚的纯文生图**恰恰是对的**（每个角色本来就该是不同的人，批内互比越低越好）⇒ 见 [[character-scene-asset-pipeline]] 的通用角色库口径。
