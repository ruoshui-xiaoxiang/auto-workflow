**两条铁律（来自用户自己项目的复盘，不是我推的）：**
1. **不要先建"世界/系统"再谈产出。** 判据：**"要验证它，需不需要先建一堆东西？"** 需要 → 正在滑向那条路。
2. **工程连通性 ≠ 最终语义证据。** 机器跑通/指标好看，只能算 `completed`，**不能写成 `confirmed`**。

**Why（用户的项目复盘原话）：** `E:\cuf-qs-monitor-public\docs\public_project_inventory_and_disposition.md` 是 **CUF-QS 项目的公开版资产盘点与处置结论**（仓库 `github.com/ruoshui-xiaoxiang/cuf-qs.git`，本机 clone 在 `E:\6a8b0dd1b3ead574d77ceda3`）。该项目自我重定位为「复杂交互环境中的**具身动作控制与证据闭环**系统」，并明确**降权**了这些：
- 继续扩写高层理论叙事
- 用局部实验支撑更强的理论结论
- **把工程连通性结果混同为最终语义证据** ← 核心错误
- 把收敛语言当作核心产品成果

它的五个已做决定：① 重定义项目（不再扩张旧理论叙事）② **保工程、冻理论扩写** ③ **收紧结果语义**（必须区分 `accepted` / `completed` / `confirmed` / `unconfirmed`；**任何结果未经过确认语义，不得写成事实成功**）④ **实验动作不得静默进入默认正式路径**（必须显式启用、独立归档）⑤ 对外同步只用脱敏稿。保留原则：**原始日志优先于总结文字；任何结论都必须能回指到归档数据；没有原始归档支撑的结论不得继续放大。**

**How to apply（用户 2026-09-15 在影视项目上原话："怎么感觉这又有点走上了之前游戏虚拟具身QS项目的路子"）：**

**同族陷阱二（2026-09-15 新增）：用"规模/组合"替代判断，也是同一个坑。**

用户提出「**把所有运镜组合、生成尽量多分镜，再组合出最合适的片段**」（他的推理是"AI 最擅长海量数据组合"）。直觉方向对（多拍再挑是正经工艺＝coverage），**但装反了**。

**Why:** **AI 擅长"给定目标做大规模搜索"，不擅长"自己定义目标"。** 组合需要一个**目标函数**；没有目标函数，一万条也只是**一盘更大的散沙** —— 跟现在的问题一模一样，只是更贵。成本账：按本项目现价（15s 镜 ≈¥12–16），一集 50 镜 ×5 候选 ≈ ¥3000/集。"最合适"由谁判？由人判则人是瓶颈，由 AI 判则 AI 得先知道这场戏要什么——**那正是缺的那个东西，绕一圈回到原点**。

**How to apply:** 用户提"枚举/海量生成/组合出最优"时，**先问目标函数在哪**，而不是先讨论组合规模。正确装法＝**意图先定死 → 只在意图附近做局部搜索（best-of-N）**；它省的是"选的功夫"，省不掉"想的功夫"。

> **这句话，能不能从一个没看过我们片子的人嘴里说出来？**
> 能 → 是轮子，直接用现成的（别人已经有的说法/书/工具），不要自己造。
> 不能说 → 是你自己的尺子（只有量过自己素材才说得出），值得沉淀。

**Why:** 电影工业一百年的方法论（McKee 价值翻转、Swain scene-sequel、Save the Cat 百分比、ASL 3–6s）**全是现成的**，写成流程文档只是把常识换包装，产出看着专业却一条也改不动成片；而"我们二幕 13 镜里 0 个全景"这种数据只有自己量得出来。混淆这两类＝既重复造轮子、又拿不到真东西。

**How to apply:** 沉淀任何 pass/规则前先过这条判据筛。**配套的落地方式＝先跑完一集、只产两页纸（一页导演 pass 决策记录 + 一页剪辑 pass 改动表），再拿判据筛；筛不出来就当场作废、不做成 skill。** 关键不是"一开始就判对"，而是"跑完能诚实地删" —— 真正的风险是从"造出轮子"滑向"舍不得删"。

## 同族⑦：别拿"度量方式的借口"给没达标的数找台阶（2026-09-24 自己犯的，当场推翻）

镜2 运动量从 0.91 提到 2.27，我说的目标档（spectacle 段 7.76）远没到。第一反应是**给这个数找解释**："全帧均值把窄带动作摊薄了"——听起来很专业。然后按中央动作区（x 33–67%）重新量：v3 0.78 → v4 **2.51**，镜B **6.67**。**换了尺子，结论反而更难看**，"摊薄"不成立，真相就是这一镜天生是窄带动作、够不上那一档观感。我随即向用户公开更正了上一条说法。

## 同族⑨：共享底座之下，"两台机器结论一致"不是证据（2026-09-28 自己犯的，当场收回一条已报出的结论）

我把审计脚本和规则闸**同时**报出的"C 线 P3C 超载、建议 124→209 帧"当成结论**报给了用户**。
真相：两条链都调同一个 `prompt_format.dialogues()`，而它在稿内没有 `<d>` 标签时退回"中文引号＝台词"，
于是骨架正文里的**拟声词**（"铮"的一声／"轰"的一声）被数成 3 句台词 ⇒ 信息单元虚高 ⇒ 两台机器一起算出同一个假数。

- **Why:** 一致性只证明"两份实现没写错"，**不证明口径对**——同源的多个机器件本质是**一个**证据源，被我当成了两个。这是"别把工程连通性当语义证据"的又一变种。
- **How to apply:** ① 引用"N 台机器都这么说"之前先查它们**是否吃同一个底座/同一份常量**，同源就按 1 条证据算；
  ② 要成证据至少得有一条链不吃这个底座（人审、或独立测法如 ASR／光流／像素）；
  ③ **改了判定口径就要回头核自己以前报出去的结论**，能证伪的当场收回并说明根因，别让旧结论继续被下游引用；
  ④ 同族形状还出现在自写校验上：`build_manual.py --check` 与它自己的文件地图同源，"报 0 落后"不等于真源没被漏收。

1. **落盘只写了 1/4。**转换器主循环在同一个源文件的多条之间用了 `open(dst,"w")`，后一条把前一条覆盖掉 ⇒ 盘上每份只剩最后 1 条，**1,080 条静默丢失**。而索引里报的 1,400 条／中位 884 字**全是内存里的数**，所以自查看起来全绿。
2. **我写进文档的"原件未改动"哈希是凭印象造的。**`d6f7b07c756f` 按七种切法复算都得不到它——那条自证当时就不成立，是我"记得算过"。

- **Why:** 两个错误同一个形状——**拿"我算过"当"盘上有"**。内存数与磁盘数是两个事实源，批处理写文件时最容易把前者当后者；而写进交付文档的校验值如果没留复算入口，它就退化成一个装饰性数字，比没有更危险（它让人以为已经查过）。
- **How to apply:**
  ① 任何"N 份／N 条／N 字"的交付声明，**必须有一行是从盘上重新读出来数的**（我现在在索引生成器里加"盘上实到"行，与内存数并排显示，两者不等就当场炸）；
  ② 写文件的循环**先按目标聚合再落盘**，别在 item 循环里 `"w"`；同一目标要写多次就用 `"a"` 或攒齐一次写；
  ③ 交付文档里的自证一律换成**可复跑的脚本＋打印口径**（mtime 扫描／全树计数／代码级只有一处写句），不写单个哈希值让人只能信我；
  ④ 上一轮报过的结论如果被证伪，**同一轮里公开收回**——"上一版只有改写规则是对的，落盘是不全的"这句话必须出现在交付物里，不能只在对话里说。
- 关联：[[reference-baidu-character-library]]（同批的挖掘结论）、上面 ⑧"自写校验脚本≠真闸"、⑨"两台机器同源只算一条证据"、[[feedback-review-production-prompts]]。

## 同族⑪：写进库档的量化数字，必须连**配方**一起钉在留在盘上的脚本里（2026-10-01 自己犯的）

10-01 白天我把四个色温数（亮部 R−B：52.0／3.0／36.2／13.5）写进了《角色提示词写法卡》§九 当"本次最可用的一格数"。
当晚想复用时发现：**盘上那 32 张原图还在，但那四个数用十种合理算法（阈值 0.70/0.75/0.80/0.85/0.90、灰度 ≥230/245、百分位 90/93/95/97/99、逐图中位取均值／取中位／像素池化）都复现不出来**——它们当时是"算得出来、跑不出来"的数，脚本没留、配方没写。
⇒ 只能**作废重算并公开更正**（真值 27.5／−0.7／37.2／7.0；方向结论没变，反而更干净），并在卡里明写"那四个数作废"。

**Why:** 同族⑩ 是"拿我算过当盘上有"（内存数 vs 磁盘数）；这次是它的孪生形态——**拿"我算过"当"以后还能算出来"**。数字一旦进了库档就会被下游引用和当作决策依据，而它背后的算法是不可回忆的（"亮部"三个字有十种合法实现）。

**How to apply:**
1. **任何要进库档／交付文档的量化数字，落笔同时把配方写进一个留在盘上的脚本文件头**（阈值定义、聚合方式、噪声底），文档里指回该脚本；做不到就别写那个数。
2. **顺手量出并写下噪声底**（同 prompt 重跑差多少、组内极差多少），否则下一个数字会被当成信号——这次"补光格 +7.3"就是靠噪声底 7.5 判掉的。
3. **发现旧数字不可复现时，在同一轮里作废＋重算＋在原文里留更正横幅**，不要悄悄替换（同族⑩ 第④条）。
4. 关联：[[reference-image-consistency-qc]]（这次钉死的两把尺子与"缩略图判不了单张"）、[[feedback-prompt-iteration-priors]] ㉑㉒。

## 同族⑫：测量自身的卫生——**探针会被我写的解释文字污染，单位错配会造出假缺口**（2026-10-02 一天内连犯五次，全是我自己造的）

10-02 建"若水AI电影"架构盘点（见 [[project-ruoshui-ai-film-architecture]]）时，一天里查出五个**我的测量本身**的错，
每一个都会把假事实写进会被下游引用的清单：

1. **从源码刮字符串字面量的探针，会被自己写的注释/docstring 污染。**
   我在 `channel_of()` 的 docstring 里举实证：`channel_of('qianwen'|'qwen'|'bailian', 'local') -> h3`。
   扫描器判"机器认得几条通道"用的正是 `str_literals(函数体)` ⇒ 那三个词被当成已登记 kind，
   输出从"认得 4 条"变"认得 5 条"，**而 GAP-C2（千问通道机器不认）被连带判成不存在**。
   ⇒ 改成只解析 `if k in (...)` 的成员元组；判"兜底是否还在"改成看**最后一条 return 是不是"我不知道"记号**（那行 `return "cloud" if … else "h3"` 拆完后仍在，但已被关进合法泛称分支）。
   **通则：解释性文字写得越详细，越容易把基于文本匹配的测量带偏——测量面与说明面必须分离。**
2. **单位错配会造出一个根本不存在的缺口。** 我报"注释自称 107 项 vs 实测 74 项"——
   74 是 `def test_` **函数个数**，107 是 pytest **用例数**（`@parametrize` 一对多展开成 108）。
   真实差异只有 1 项。**判据改成现跑 `--collect-only` 取用例数**，三种单位分开列、实跑通过数一律写"未测量"。
3. **语义分类的作用域：更正可以跨格看，断言必须就地看。** 判"文档里哪句状态断言过期了"时，
   markdown 表格**一行＝一个逻辑单元**（🔴「当前关闭」在第 2 格、✅「已裁＝开闸」在最后一格），只看 ±60 字符会把已更正的报成未更正；
   但我第一版把窗口整行放宽，结果同一行别处的「可临时…关掉」把第 2 格那句真·现在时断言**整个吞成条件句**
   ⇒ **从假阳变成假阴（把过期说成没问题），比假阳更坏**。终态＝只有"本行有没有更正"看整行，其余判据一律留局部窗口。
   另：勘误按惯例写在下一行，所以"有没有更正"还要往下看 N 行，且**只认明确写着「勘误／更正」的字样**，不认泛化的"已裁"（免得隔壁不相干的行替它背书）。
4. **行号是脆的：往一个键上方插注释，就会把别人引用的锚推走。**
   我把测试数勘误写在 `preflight:` 那段注释旁边，**加 2 行就使 `:71` 变成 `:73`**——而规则层此刻正按 `:71` 引它。已回退，改写文件末尾并在文末注明原因。
   ⇒ **追加更正一律引"键名/节名"，不写行号**；要写就同时写"行号会漂，只作辅定位"。
5. **拆一个"危险的默认值"之前，先把合法用法和意外用法分开，并量爆炸半径。**
   方案写"把 `channel_of()` 的无条件兜底整行拆掉"。实测：`video`/空**是文档明写的合法泛称**（"只定通道不定格式"），
   且三条现役测试依赖它给出真通道；整行拆会连坐。真正危险的只有"非空且不认识"那一类
   （实测 `qianwen`/`qwen`/`bailian`、`jimeng`/`dreamina` 全被悄悄判成 `h3` ⇒ 用错通道的判据审，还显示 ✓）。
   ⇒ 先补 yaml 的显式声明、证明通道不变（真源 15 份逐字比对 G7 整份报告），再拆兜底；顺序反了会把主力出片通道当场拦死。
6. **读"代码里的默认值/兜底列表"当成"现役配置"——同一天的第二次单位式错配。**
   我据此报出"GAP-G2：error 级 G11 默认不执行"。真相：`run_checks` 那个 `["G1"…"G8"]` 只是**没传 `only` 时的兜底**，
   引擎是拿 workflow yaml 的 `auto_gates` **显式传 `only`** 的 ⇒ 实测 14 份带闸流**全部含 G11**，
   G11 对引擎主路一直在跑。**用户已经基于我这条错报裁了"G11 要放进子集"**——我没有照假前提动工，
   而是先更正（裁定的真实落点只剩"没传 only 的调用"：裸 CLI、`run_h3.py`），再执行那半条。
   ⇒ 报"某开关/集合没生效"前，先量**谁在真正调用时传什么**；兜底清单不是现状。
7. **正则漏匹配造成"静默不报"（比误报危险）**：判 yaml 里的步骤我写 `^\s*task:`，而 yaml 步骤是列表项 `- task:`，
   前面有 `- ` ⇒ 一条都配不上 ⇒ 那条 gap **永远不触发、缺口数看着没变**，靠"数字没动"才发现。
   同一形状的另一次：把"有没有更正"的判据放宽到整行时，顺手把"是不是现状断言/是不是条件句"也放宽，
   结果同一行别处的词把真断言吞成条件句 ⇒ **假阳变假阴**。
8. **gap 文案里不许出现减法凑出来的数**：我写"已补 N 份"用的是 `len(剩下的) - 2`，读数变成"补了 0 份"。
   要么直接量，要么只报扫描器真看得见的两个端点（现有多少／缺多少）。

**改判据口径时的两条卫生**：① **测试红了先分清"夹具缺口"还是"判据错"**——把 G11 加进兜底后唯一红的
`test_good_spec_passes`，是它的 spec 没有 `output_root`（G11 报"没有 output_root，产物无处归档"是对的）
⇒ **补夹具、不放宽判据**。② 任何从 high 降/升到 low/mid 的结论，**note 里写死"这是现状变了还是我改了口径"**。

**给现役流加闸/改行为前的三重预验**（10-02 靠它抓到两次当场拦停）：
① 先用**同一份判据函数**跑该流的真实默认参数（发现 `h3_one_click_movie` 输出 1920×1080 → G5 判"不是 32 倍数" error，
   而 G5 管的是**模型输入**尺寸、量的是**输出容器**，本就不该套 ⇒ 只补不需要提示词的 G11）；
② 按真调用方构造 spec 的**同款口径**预判整份报告 error/warn 数；
③ 端到端用一个**必然失败且零成本**的输入证明闸真的在位置上（`--set prompt=` 空 → G7 error、流程第一步就停、
   绝不碰显存；或自带 `dry_run` 的流用 `dry_run=true`）。
⚠ 有些验不了：manifest 驱动的流会在 `resolve_pick` 就失败（在步骤循环**之前**），闸没机会执行 ⇒
**如实写"这条只证到 yaml 可解析＋闸在第一步＋与已验证的流同机制"，不含糊说成端到端验过。**

**还有一条同族的"收回"**：我上一轮报"`selftest_gates` 现在跑不过（exit 1）"，当场复核发现是**我裸跑没传 `refs`**
（yaml 默认空，G7b 拦停是设计意图），测试本身用合成 PNG 传 refs、拿退出码 3，合法。
⇒ **报出的怀疑一旦发现是我看错，必须在同一轮明文收回**，不要留着让它被下游当成"已知缺陷"。

**Why:** 用户 2026-10-02 明确交代「**按1-2-3往下走吧，多复核一下，尽量保证准确**」。
这一天里最危险的五个错没有一个来自被测系统，**全部来自我的测量方式**——而建机器的人最容易只复核系统、不复核尺子。
证据自检机制确实抓住了其中一个（`evidence` 路径自检报出 `!! 证据路径失效：D、D、D…`，根因是 Windows 盘符自带冒号，
`split(":")[0]` 把 `D:\…\x.py:88` 切成 `D`），所以"自检"要留在流程里；**但它抓不到单位错配和注释污染那两类**——那两类只能靠"报出去之前先复核自己怎么量的"。

**How to apply:** ① 任何"扫源码/扫文档得出的计数"，落笔前先问**这个数是从字面量刮的还是从结构解析的**，刮字面量的一律先确认注释与 docstring 不贡献匹配；
② 两个数对比前先确认**同一单位**（函数数≠用例数、文件数≠条目数、路径数≠去重后的安装数）；
③ 给"已裁/已闭"的结论降级或升级时，**必须说清是现状变了还是我改了口径**——本轮 GAP-R3 从 high→low、GAP-C2 从 high→mid 都是代码现状决定的，我同步在 note 里写死了这句话；
④ 改判定链前先量基线（实跑通过数＋派发对照＋人审标定），改完逐项对齐，不等价就回滚；
⑤ 一次只动一处判据，并在汇报里点名"这条数字来自哪把尺子"。

## 同族⑬：探针与静态刮法都会**静默失效**——示例文字算成违规、代码重构让刮法归零（2026-10-02 夜）

同族⑫ 记的是"探针被我写的解释污染"。这一晚又补三种**同类不同形**：

1. **关键词残留扫描会把文档里的"反例／讲解示例"算成违规（假阳）**。
   扫去本机化副本的敏感残留：6 处命中里 4 处是误报——"单价"光出现字样不算漏网
   （口径本来就是"删数字、留计价方式"），`[[...]]` 那处是《去本机化说明》里**举的反例本身**。
   ⇒ 收紧办法：**要求数值／金额符号邻近**才报；方括号里须有实际内容。
   **报"漏网 N 处"之前先读一遍**，分不清示例与真漏网就交人判，既不自动放行也不自动定罪。
2. **静态刮代码的判据会在重构后刮到空集，而输出看起来像"量到了 0"**。
   词表迁进注册表后，`channel_of()` 函数体里不再有 `if k in (...)` 元组 ⇒ 扫描器那条正则**刮到 0 个词**，
   会把"机器认得 20 个词"报成"一个都不认"，连带 GAP-C2／C4 误判。
   ⇒ 换成**黑盒行为探针**（真的 import 再调用），并**只留一份实现**（扫描器当消费者，不再抄一份）。
   通则：**测行为就测行为，别测写法**；写法变了而判据没变，就是假阴在路上。
3. **新增字段/新算子会悄悄改变"待裁"集合**——这是最坏的一种，因为它制造出用户从没提过的问题。
   探针一换，即梦的认得词变空 ⇒ 差点被列成"待你裁"，而"即梦稿不进任何机检"是他 09-28 就裁过的（C82）。
   ⇒ 把"**该不该**有"（裁定）与"**有没有**"（实测）拆成两个字段（`needs_channel_of_branch`），
   新算出来的差集默认**不进气泡待裁队列**，先回查是否已有裁定。
4. 顺手两条纯环境的：**宽 `except Exception` 会把 bug 洗成"降级运行"**（真实原因是忘 `import io`，
   表象却是"注册表读不到、按兜底判"）⇒ 异常分档、第三档标 `code_error` 带类型；
   **Windows 子进程 `text=True` 默认按 cp936 解 UTF-8 中文 JSON** ⇒ 父进程 `encoding` ＋ 子进程
   `PYTHONIOENCODING` 两边都要钉，只钉一边仍然炸。

**Why:** 这一晚最危险的错仍然全部来自我的测量方式而不是被测系统；而"读不到就兜底"这个设计
（我为了防静默失效而加的）本身成了新的静默失效入口——**兜底必须自己可被证伪**（藏起注册表重跑，
看降级 warn 真出现才算数）。

**How to apply:** ① 任何计数出口前问"这是从结构解析的还是从字面量刮的"，刮字面量的先确认示例文字不贡献匹配；
② 判据重构后必须重新验证**它还能不能刮到东西**（跑一遍看命中数是否突降为 0）；
③ 新字段/新算子改动了"待裁／待办"集合时，逐条回查是否已有裁定，别让用户被自己造的问题淹没
（见 [[feedback-human-decides-values-not-rules]]、[[feedback-collaboration-style]] §34）。

## 同族⑮—⑳（2026-10-03 一天内，批 13—15）：改判据链上我又犯了／抓到这六类

⑮ **偏离登记必须写清"偏离落在哪一层"（文案／模板／闸／产物）。**

⑱ **同一个"几份"可以有两种分母——引用不带范围就是错。**
"库里 29 份"＝只算 ComfyUI 两个 prompt 目录；全盘口径（含 `E:\创作` 项目稿）＝**33 份**，会被新闸拦 21 份。
而"21 份要改"里还有 **1 份是派生合订本**（`三阶打斗_提示词全集.md` 由 `pack_p_prompts.py` 的 `OUT` 生成，
按规矩只能重生成、不手改）⇒ 真正改面 20 份。**批量改动前先把派生件从名单里剔出去。**

⑲ **一致性守卫"只比前半段"＝尾部篡改测不出来（假阴）。**
词表对照表的 `--check` 第一版比较 `text.split(生成时刻)[0]`，我拿"在文件末尾手加一行"去自证，**它绿了**。

它当场抓到我把 `0.0–1.1 秒` 写成 `0.0-1.2s`（真笔误，会让人按错的节拍铺镜）。

**How to apply:** 生成式改写一律过"数字保真＋受控值域"两道检；批量落盘走**按句 id 替换**（键＝段文本哈希），

## 同族㉕（2026-10-04 实例）：把"我写了这段代码"说成"这个防线在生效"，比不写更贵

给生产站加了登录限流后，我在汇报里写了一句"同一来源 IP 每分钟 15 次失败就 429"。
**那时我只有代码，一次都没打过。** 用户回「先把安全漏洞补上嘛」，我当场打 20 发才发现真相：
`1–15:401 · 16:429 · 17–20:502` —— 502 是因为我在 429 之后又发了一次 401，
Node 对已结束的响应再写＝`ERR_STREAM_WRITE_AFTER_END` 未捕获 ⇒ **进程直接退出**，
systemd 三秒后拉起。也就是**任何人发 16 次错口令就能把全站 API 打下线，比没有限流更糟**。

- **Why:** 他这次的触发方式很有代表性——我不是被"你测了吗"问出来的，是被他**把话题推回这件东西本身**
  （"先把漏洞补上"）逼得我不得不去打一遍。我的措辞（"有 15/min 限流"）听起来像已验收的事实，
  如果他就信了、不再提，这条自伤会一直挂在生产上。
- **How to apply:**
  1. 汇报里凡是"**有某道闸／某个防线生效**"的句子，出处必须是一次当场打过的证据（状态码序列、PID 未变、
     `NRestarts` 未增），否则就写"代码写了，**没实测**"；这条与他立的元规则 M1 同源——**没测的不算事实**。
  2. 防线类改动一律配一条**"防线不能自伤"的回归用例**：判据写成形态而非计数（"全程无 5xx／401 转 429 后不回退／
     正确口令在窗口内仍能过／打完监听 PID 不变"），因为前面别的用例会先消耗计数器。
  3. 响应发送类代码要有**单发护栏**（`headersSent||writableEnded` 直接 return）＋外层 try；
     "已发过 429 又发 401"这种双发路径是进程级崩溃源，不是小瑕疵。
  4. 我埋的坑要**在第一句就点名是我埋的**，并给出故障时间窗（这次是 05:17:07 起约 3 秒），不写成"发现一个问题"。

**立住的那把**：改成**真值已知的自造输入**——我自己合成一张结构已知的深度图（矩形位置我先定），
再配一句**与它结构相冲突**的提示词当探针（"混凝土墙占满画面、无任何景深线索"），
这样基线必然落在零，控制一有效就会在已知坐标上长出边界。结果：基线 1.01x、挂估计深度 1.02x、
挂合成深度 **2.42x**。

- **Why:** 前两把尺子的共同毛病不是"不够准"，是**分母里混进了被测对象自己的模式化偏好**——
  相关类指标在"所有样本都长那样"的域上天然高，于是零效应也能读出正效应。
- **How to apply:**
  ① 任何相关／重合／相似度类读数，**先排一张"无关对"矩阵取地板**，读数不过地板就明文写"这条没测出来"，
     不许顺势说"有改善"（同族⑳ 分母、㉖ 空结果不等于没掉帧）；
  ② 测"控制／干预有没有效"，优先**自造真值输入 ＋ 与真值冲突的基线条件**，
     而不是拿真实样本做 A/B——真实样本里提示词／先验常常已经解释了大半，增量必然小到读不出
     （同一天我在 canny 那组也栽过一次：p3a 增量小不是控制弱，是那条样本本来不需要控制）；
  ③ 边缘／断缝这类**薄结构**做交集必须给膨胀容差（我两次都是 0 % 命中＝无容差比 1px 线）；
  ④ 尺子废了要**在结论里点名它是废尺**，不能只留下"读数低"这个数字当发现。
关联 [[reference-local-image-chain]] 12、[[feedback-prompt-iteration-priors]] ㉓。

**同族㉘（2026-10-04）：外部 API 的过滤参数被**静默忽略**时，返回的是一份看起来正常的通用列表——比报错危险得多。**

我在 civitai 上用 `GET /api/v1/models?search=midjourney&sort=Most Downloaded` 搜 MJ 风格的 Z-Image LoRA，
拿到 25 条结果、全是 SD1.5/SDXL/Pony 的十年老件，于是差点写成"搜过了，没有"。
实际是 **`search=` 这个参数被接口忽略**：换两组完全不同的关键词，返回**逐条一模一样**（同一张全站下载榜）。
换成 `query=` 才真过滤，当场命中 **3 件 Z-Image 底的 MJ LoRA**，头名 16,008 下载——
而我上一轮基于"HF 搜不到"刚说过"Z-Image 的 LoRA 生态很小"，**那句也是同一种错：单源当全貌**。

- **Why:** 报错会逼我换路，**返回一份结构完整但没被过滤的列表不会**。
  它同时满足"我查过了"和"结果是空的（对我要找的那类而言）"两个心理确认，所以最容易直接写成结论。
- **How to apply:**
  ① 用任何过滤参数得出**否定结论**前，做一次**阳性对照**：换一个已知必然命中的词跑同一参数，
     看返回是否随之变化；不变＝该参数没生效，换参数名（这里是 `query=`）再跑；
  ② 更省事的判据是**看返回是否"过于整齐"**——一份 Top-N 通用榜长什么样，一眼就该认出它不是搜索结果；
  ③ "某生态大不大／有没有 X"这类判断，**必须多源**（HF ＋ civitai 是两个互不覆盖的库），
     单源结论只能写成"在 <那一源> 上没有"，不能写成"没有"；
  ④ 同族⑭（grep 0 ≠ 没实现）的镜像形态：**查询返回了东西 ≠ 查询按你的条件过滤了**。
  详见 [[reference-civitai-access]]。

**同族㉙（2026-10-04，许可面）：别人替你标的许可不算许可。**
civitai 原作者页 `licensing` 为 `null` 的 16k 下载 LoRA，在 HF 上有个转帖仓标着 `license: apache-2.0`——
但**标的人不是权利人**，而且那个仓是**空壳**（只有 `.gitattributes` ＋ `README.md`，没有任何权重文件）。
⇒ 判许可要核到**原作者口径**；镜像仓的 frontmatter 只能当"这个人愿意这么标"，不能当厂商承诺。
同族⑨（同源机器一致≠证据）在授权链上的变体：**两个来源都写 apache-2.0，可能只有一个人在说话。**

**同族㉚（2026-10-14，评分口径）：召回类指标的分母是"有效样本数"，不是"跑了几次"。**
六臂对照里我把"漏检数 ÷ 3 次"当均值，结果 **GLM 默认档漏检 0.67 看着是全场最好**——实际它三次里两次没产出可用 JSON、根本没有可评的内容，那两次按"零漏检"混进了分子。
⇒ **失败样本会以"完美表现"的形式进入召回类指标**；正确写法是 `漏检 ÷ 有 JSON 可评的次数`，并把 n 标在数字旁边（n=1 的读数不能与 n=3 并列排名）。

**同族㉛（2026-10-14，重复次数的作用域）：同方向的偏差不靠重复收敛。**
MiMo-Flash 关思考档三次全漏同样两件道具（「墨」「欠条」），三次输出 1197／1187／1164 字——**稳定，但稳定地错得一样**。
⇒ 重复采样只压方差、不修偏差：**"三次结果一致"既可能是"可靠"，也可能是"同一个盲点被复现三次"**，这两种在均值打分里长得一模一样。判"稳"要看**漏的是不是同一批**，不是看方差。
