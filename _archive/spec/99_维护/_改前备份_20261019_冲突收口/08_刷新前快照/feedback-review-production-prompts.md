正式产出（生产阶段实际用于生成视频/图片）的提示词，必须先发给用户审一遍、确认无误后再跑。验证/对照/试配方阶段的提示词可自行拟定直接跑。

**Why:** shot04 神态提示词我按"被打疼"写（蹙眉吃痛），用户指出这镜其实是"砸晕"——我对镜头戏的理解会偏，而神态/动作这类细节会直接落进成片，理解偏了就是整批返工（¥6.4/次 × 批量）。用户明确要求"后边实际用于生成阶段的提示词也要给我先审一下"。

**How to apply:** 开工批量前，把每个镜的提示词（动作 + 神态 + 场景 + 风格）整理成清单先交用户审；用户点头后再用 `seedance_r2v.py` 批量跑。试新配方、做对照测试（如"文字驱动表情能否到位"这类）不受此限，可先跑再汇报。关联 [[feedback-test-with-manual-prompts]]、[[feedback-character-reference-image]]。

**审查稿＝桌面的提示词文档，脚本改了必须整份回写同步（2026-09-13）**：用户实际审的是**放到桌面的那份提示词文档**，不是脚本里的字符串。只改脚本、不回写文档，用户审的就是旧稿，等于白审——用户直接指出"桌面的提示词我看还好多地方没改"（当时文档里还留着襦裙、器材词、四段结构，全是早就推翻的旧内容）。**Why:** 交付物与真源不一致会让"先审再跑"这道闸门失效，而且用户不知道哪份才算数。**How to apply:** 提示词只要有实质改动（角色锚定 / 措辞 / 分镜结构 / 参考素材配法 / 路线切换），就把桌面那份文档**整份重写**（别只追加、别保留"原文/建议修改"两栏旧稿），保证与脚本一字不差；改完主动告诉用户"已同步"，让用户审的那份永远是真源。

**只留最新版，旧版直接删（2026-09-13 用户定）**：用户原话「**提示词里边只保留最新的版本，之前的版本直接删掉**」。当时脚本里堆了四段硬切的 05A–05D、段落式的 05FULL、两个别名（05CHAR / 06 与 03 重复）、以及我误写的一整套园林四小镜——用户要求清掉，只留现行版本。

**Why:** 多版本并存会让"哪份算数"再次变模糊（正是上一段那个坑的成因），而且旧版里的措辞（襦裙、器材名词、旧画风）随时可能被下一次复制粘贴带回来。他要的是**一个镜一个版本，没有歧义**。

**How to apply:** ① 提示词**不并存多版本**——新版取代旧版时直接删旧条目，不留"存档/对照"（顶多在交付说明里提一句改了什么）；② 删除要**从脚本真源删**，不是只在文档里隐藏；③ 顺带清掉相关残留（别名 key、旧注释、`.bak`、渲染目录里作废的产物、桌面上作废的预览文件），并告诉用户清了什么——他把"删干净"当成交付的一部分。

**真源生成器：曾议未落地（2026-09-14 实查修正）**：原记录说"文档由 `gen_prompt_doc.py` 从 `seedance_r2v_rest.py` 的 PROMPTS/CONFIGS 渲染生成、机制保证逐字一致"。**2026-09-14 实查：这两个文件都不存在**（`D:\AIWorkflow\tools\`、`E:\创作\无音项目\工具\`、桌面全盘查无；桌面 `shot04_seedance\` 下只有 `seedance_r2v.py`）。所以现状是**两条人工同步的副本**：可运行真源（`prompts\shot0X_ref2va.txt` / 脚本里的 PROMPTS）+ 桌面审阅文档，靠"改完记得回写"维持一致 —— 也就是回到上面那个"改脚本不改文档"的老风险上。**How to apply:** 别再把生成器当既有资产引用；真要机制保证一致，得先把生成器建起来（见桌面 `无音_事件线与状态传递_工作流规划.md` Phase 0：`gen_shots_doc.py` 从 `shots.yaml` 单向生成）。在此之前，每次改提示词都要显式做一遍文档回写。

**提示词"不要直接改"——改动必须先把全文贴给用户审、批准后才动脚本（2026-09-13 用户强调）**：用户原话「**提示词不要直接改，改动必须让我先审**」。镜1/镜2 改提示词时我直接去写 patch 脚本，被拦下；正确流程是**先在对话里贴要写进脚本的完整最终文本（不是只贴"改了哪几处"的片段），明确说"这就是要落盘的版本"，等用户回"落盘/可以/按这版改"再 Write/Edit**。
**Why:** 前面"先审再跑"防的是"理解偏了整批返工"；这条更进一步——**脚本真源本身也不该在用户看过全文前被改动**（哪怕还没跑），因为一旦写进真源，用户下一份要审的稿就是被改过的版本，等于把"审"往后挪了。**How to apply:** 改动前贴**完整文本**；用户批准完整文本后可直接落地，不需要二次确认；已批准但还要写辅助脚本时，也只在批准的文本范围内动手。
