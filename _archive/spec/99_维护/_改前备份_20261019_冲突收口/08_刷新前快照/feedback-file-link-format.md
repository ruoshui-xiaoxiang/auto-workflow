**递本地文件链接的固定写法**：`[文件名](<E:/路径/文件名.md>)` —— **URL 用尖括号包住、用正斜杠**。
**不要**写 `[文件名](E:\路径\文件名.md)`：反斜杠不合法，而且路径里的**成对下划线会被当成斜体标记**（`_待审文档\通用角色库_` 正好配成一对 `_…_`），整条链接被渲染器吃掉、点了没反应。

**Why:** 2026-09-28 我把《通用角色库·批次一》待审文档的链接写成 `(E:\创作\_待审文档\通用角色库_批次一_待审_20260928.md)`，用户点不开，直接问「**文档怎么删除了**」——一次误判成"文档被删"的来回。文件从头到尾都在盘上（138 行 / 19,704 B / sha256 `35dc262f…`）。同一轮里我给他 `_qc_sheet.jpg` 时特意转义了下划线、那份就没事 ⇒ **是我漏了，不是环境问题**。

**How to apply:**
- 递链接固定用 `[名](<盘:/路径/名.扩展名>)`；尖括号能吞掉下划线与空格，最稳。给多个文件时逐个这么写。
- **用户说"文件没了/怎么删了"时，先在盘上核实再说**：`ls` 字节数 ＋ 行数 ＋ `sha256`，把证据摆出来，再解释原因。**不要**顺着"可能真删了"去猜，也不要急着另存一份。
- **不要为了"保险"在别处再存一份副本** —— 他定过"交付物与真源不一致会让先审再跑这道闸门失效"（[[feedback-review-production-prompts]]），**他审的必须永远是同一份**。
- 顺带：往 E 盘写完文件后，用户那边**已打开的 Explorer 窗口不一定自动刷新**，主动提一句"按 F5"比让他怀疑文件丢失便宜。
- 同一类毛病的通用判据：**"用户说某物不见了"优先怀疑我给的指针/路径/格式，而不是怀疑东西真没了。**
