# 指定角色出图必带参考图

**规则**：生成/锁定某个具体角色（沈无音等）的图时，**必须先带角色参考图**（如 Seedream `--input @定妆图`、即梦 `--image` 参考、FLUX/FaceID 参考图），**再确定提示词**；不能只靠纯文字描述出角色。

**Why:** 纯文生图出的脸是"通用脸"，不是角色本人那张脸——文字锚定只能锁住服装/配饰/发型，锁不住五官身份。2026-09-12《哑女·废土》火山方舟出图时，我先纯文字出了两版，用户指出"是不是没有用参考图"，确认漏带。

**How to apply:** 指定角色出任何图（首尾帧/定妆/角色镜）＝ 角色参考图 + 定妆锚定文字（服装配饰发型）+ 场景/动作/光影/风格句；参考图是身份来源，锚定文字是服装配饰来源，两者都要。选型靠同帧实测 + 用户盲选，比价只做初筛。相关：[[reference-wuyin-character-design]]（沈无音定妆）。

**视频同样适用（2026-09-12）**：Seedance r2v 用 `reference_video` 只锁动作+机位，**锁不住脸/服装**（灰模 previz 无外观信息，外观全靠 prompt 文字）；要锁角色脸必须把定妆图作 `reference_image` 与 reference_video 并存（文档支持；仅 i2v 首尾帧+reference_image 被禁）。

> ⚠️ 下面这条"服装配饰逐字全带"自 2026-09-15 起被**限定**——只在用户明确要求"这一处要符合人设"时适用，默认口径见文末「服装默认不锁死」。

**服装/配饰锚点必须逐字全带，小道具也是"重要人物锚点"（2026-09-13 用户强调）**：沈无音腰间的**米色小布袋**不是可省的道具，是重要人物锚点——所有提示词、参考图、定妆派生图都必须写上，**写漏了整条重来**。同理"交领汉服"是定稿服装说法，不能写成"襦裙"。**Why:** 2026-09-13 shot05 改稿时用户说"她的袋子也不在"，我误解成"删掉袋子"，反而把人设里的袋子抹了——用户纠正"不是删掉袋子，是在提示词加上袋子""这是人物的重要锚点"。**How to apply:** ① 用户说"XX 不在/也没有"时，先判是"**漏写了**"还是"**从设定里删掉**"——默认按"漏写"处理（补进去），要删必须用户明确说"不要了/删掉"再动；② 写无音提示词时对着 [[reference-wuyin-character-design]] 逐项点一遍（年龄/发型/银步摇/蓝花钗/朱砂莲钿/交领汉服/淡蓝织带/米色小布袋），别手写缩写。

**参考图还会连"画风"一起带 —— 锚点本身风格与目标画风不一致时，必须在提示词里显式声明（2026-09-13）**：沈无音的定妆锚点图是**国漫立绘风格**的四格角色图，而废土幕要求"电影级写实 CG"。挂上去后即梦出的图仍可能是写实 CG（本次 22 张实测成立），但**不能靠运气**——必须在提示词里写明「**参考图仅用于锁定人物五官、发型、服装与配饰，画风一律按 <目标画风> 渲染，不得把立绘/插画的绘画感带进来**」。**Why:** 参考图同时携带身份信息与画风信息，模型分不清"我要这两个里的哪个"；不声明就由它自行取舍。**How to apply:** ① 挂锚点前先问"这张锚点的画风跟目标画风一致吗"；② 不一致就在参考句之后立刻补画风约束句；③ 兜底顺序：正向句加码 → 换同画风的参考图 → 取消锚点（代价是配饰会丢，见下条）。注意即梦 CLI **没有负面词参数**（见 [[reference-dreamina-cli]]），画风约束只能正向写。

## 服装默认不锁死（2026-09-15 用户定，与上条并用时以本条为默认）

**规则**：角色图的参考图**只锁面容身份（脸是硬锚）**；**服装不要定得太死**——除非用户**特别强调"这一处要符合人设"**，其余场合服装可以自由得多。
**Why:** 用户原话：*"不用把衣服定的太死了，除非我特别强调需要符合人设的情况，其他时候衣服可以自由得多，比如在现代，完全可以穿短裙，这不是什么问题"*。起因是我把"她领口比定妆低"当成缺陷、准备写死一条"交领必须闭合、不得低胸"的约束去压——用户直接否掉了这个方向。过度锁服装既限制创作，又会把画风/场景的自由度一起压没。
**How to apply:** ① 挂锚从句里**只写锁面容/发型**，服装交给每一镜自己的文字描述；② **别把"偏离定妆"当 bug**——领口高低、裙长、露肩、换装都不是缺陷，不要主动去"修"；③ 只有当用户点名"这里要符合人设/照定妆来"时，才恢复逐字锁服装配饰（那时照上一条办）；④ 同一条也约束我写**画风锚**的职责句——不要为了防服装泄漏而反向把服装写死。
相关：[[reference-wuyin-character-design]]（沈无音定妆，属"用户强调人设"的场景）。

**★双锚拆分＝造型全自由的正确做法（2026-09-15 实测有效，12/12）**：要让角色"换发型/换服装/换时代"但**脸和随身道具不变**时，**不要挂整张定妆图**（整图会把古装一起带过去，12 个造型全被拽回同一个样子）。做法：从定妆图上裁出**两张互不重叠的窄锚**——① **脸锚**（脸+颈，切掉交领以下）只给面容骨相；② **道具锚**（那件随身小物的局部特写，如米色小布袋）只给道具的样式/颜色/材质；两张一起 `--input`，提示词里写明「参考图1＝唯一面容依据」「参考图2＝那只小布袋，样式颜色材质完全一致，只有挂法随本镜服装与时代变化」，再加一句「发型、发饰与服装全部按下文重新设计，不得继承参考图的古装发式与服饰」。实测 12 款跨现代/民国/唐风/仙侠/武侠/港风/科幻/蒸汽朋克，**脸都认得出、布袋全在、没有一款被拽回古装**。**Why:** 锚点带什么由"图里有什么"决定，文字压不住；切掉就等于不提供。**How to apply:** 任何"换装不换人"的探索批次都按这个双锚（脸锚＋道具锚）搭；道具锚缺失时道具会丢，所以重要随身物必须单独裁一张。

**★借「设计语言」≠ 复制角色：第三方／版权素材的正确用法（2026-09-16 用户问，已跑通）**：用户拿 4 张剑星（Stellar Blade）游戏内拍照截图问"能不能用这套服装和武器当参考生成不一样的"。**可以，而且这条路比"借脸"干净得多**，但有两条铁律：
- **① 绝不把整张截图／立绘挂上去**——锚点带什么由图里有什么决定，整图会把人物长相＋场景＋甚至游戏 UI 一起带进来。做法＝先裁**无脸窄裁切锚**（本轮裁出 `锚_服装.png` 1280×495、`锚_武器.png` 1100×320，服装那张下沿特意切在 UI 之上）。同 [[feedback-cross-shot-continuity]] 那条"抽帧含写实人脸会被真人检测拦→裁掉脸"。
- **② 职责句写"重新设计"而不是"采用"**。✅「参考图只提供这套服装的**材质语言与配色母题**（半透明多层白纱层叠、银白蕾丝、紫色晶体、翼状甲片），**款式、剪裁与配饰全部按下文重新设计**；不采用参考图中的人物长相、姿态、场景、镜头与界面元素」。❌「采用参考图中的服装」＝1:1 复刻。**这四个字就是"借鉴"和"抄袭"的分界**，出来的东西归属也是两回事。（实测 C1：同设计语言、款式/配色/人物全变。）
- **版权线**：游戏角色的**设计语言**（材质／配色／造型母题）可借，**脸不可借**；第三方 MOD 改的服装同理。产物分"内部审美打样／对照"与"要发布"两种用途——内部可以，发布不行（同 [[reference-local-face-swap-capability]]「发布＝侵权，内部对照性质不同」）。这条对用户主动提的版权问题要**如实说、不回避也不说教**。

**★风格锚只能用原始素材，不能用派生物——二手锚链逐代掉质感，最后漂成卡通（2026-09-25 实测，一条批次的返工换来的）**：《武昭君仪》里"画风变卡通"我一开始归因到措辞，错了。真实链条是：用户给的画稿 → 挂它出的乙批（质感最好）→ 从乙批裁出 77 号当脸锚 → 后面几批**只挂这张派生脸锚**（质感＝二手）→ 再把某张派生全身图升成造型锚（二手的二手）→ 六张一起漂成游戏概念图／卡通。**风格信息不在"脸"里，在"那张原始画稿的渲染质感"里；你不挂它，就没有任何输入能承载它，文字补不回来（我写了"不要平涂／不要厚描边／不要赛璐璐"全部无效）。**
- **Why:** 模型的风格是从输入图继承的，派生物每过一道手就掉一档；而"变卡通"这种退化是**渐进的**，所以我在第三批上才察觉，已经隔了两代。
- **How to apply:** ① **画风／质感锚永远挂用户给的那张原图（或你自己从零生成的风格基准图），不要挂任何"从它派生出来的图"**；派生图只配当**脸锚／道具锚**这种窄职责锚。② 一旦用户说"画风漂了／变卡通了"，**先查锚链是第几手**，别急着改措辞——措辞大概率不是原因。③ 配方写进文档时明确写成"每张进片的图挂哪几张原图"，不要写"挂角色锚"这种会被派生物顶替的说法。

**★连"原始风格锚"自己画里的具体物件也会漏，禁令压不住——要改就把它裁出画框（同日）**：把原始画稿请回来后质感确实回来了，但那张画稿里的人物本身穿金属披膊，于是我写了"全身金属只有发簪＋一枚腰銙＋衣缘银线，不要肩甲／披膊／胸甲／鳞甲／护臂"，**六张里五张肩上还是有甲片**。同一条也解释了上一批"矛头带侧刃月牙"。**⇒ 职责句能挡住"排版／多视图／景别／面容"这类抽象属性，挡不住锚图里一个显眼的具体物件。** 真要拿掉，唯一有效手段是**把那个物件裁出锚图画框**（如裁到只剩织物与皮肤），不是再加一条禁令。

**★锚点身份可以写进 sidecar 卡，让机器核对槽位而不是靠我记得（2026-09-20 起约定）**：给锚点图配一个同名 `<图>.anchor.json`，内容 `{"character": "薇拉", "role": "face|costume|scene|style", "source": "原片9.30s裁切", "note": "仅锁面容"}`。跑前自审闸据此判"提示词声明的角色 vs 实际挂在槽 N 的图"是否一致（9-18 那批"声明薇拉、挂的是白玖璃"就是靠这个当场拦住的）。**没卡片的槽位只能报"机器判不了、需人工核对"——不要为了让闸通过而瞎猜标签。**
> 同一条也提醒：**`role` 决定要不要量脸**。造型/道具/场景/画风锚的脸只有几十像素是正常设计，量脸只对 `role=face` 的槽报"偏小"，否则全是噪音。

**⚠️ ~300px 这条线是启发式，不是硬界（2026-09-20 复核）**：原话里那个"80×94px"来自我手工指定的裁切框、不是检测测量。YuNet 实测一组：真脸锚 189px 仍保住身份、128px 那档偏弱。⇒ 报阈值时必须带"启发式/经验值"限定，**别把它说成模型硬约束**；判"能不能用"给实测数字＋限定词，不给绝对结论。

**★锚点的人脸像素下限（2026-09-16 实测，判"能不能当脸锚"用）**：**先量再挂**。本轮 4 张 4K 游戏截图（3840×2159）看着很"清楚"，但人物整人在画面里只占约 1100px 高，**脸实际只有约 130×155px**——这个尺寸当不了脸锚，放大也补不回来。**判据：脸 <约 300px 就别当脸锚用**；整人 <画面高的一半时优先重拍，别硬跑。**要跟用户说清"不是不清楚，是人物太小"**——解法是**拉近 + 关 UI**（拍照模式 `Shift+U`），不是提高分辨率。同理，任何"角色很小／在远景"的立绘或截图都不适合当身份锚。
> **2026-09-16 复查（按上面办法重拍后）**：用户重拍了 28 张（关 UI + 推近），用 YuNet 量出最大脸 **445×631**（另一批无眼镜的最大到 536×866）——这个尺寸就很好用。**说明"重拍拉近"是有效解，不是敷衍**。顺带：本机 `cv2` 5.0.0 无 `CascadeClassifier`，但**有 `FaceDetectorYN`（YuNet）**，扫一批截图找脸/量脸就用它。

**★"上庭精密小物件"是结构性必需品，不是装饰（2026-09-16 用户纠偏，我判断反了）**：这套剑星造型里那副细金丝眼镜，在拿到"去眼镜版脸锚"之后，用户主动回头说 *"我感觉这个眼镜对她这个脸加分很多的"*——**他是对的**。拆开看，它干的是四件结构性的事：① **给眼睛加框**——强项是眼睛，但眼睛上方没有过渡，两条细金线强制把视线拉过去；② **全脸唯一的强横线**——脸型/发流/头饰/颈饰全是纵向，靠它破单调；③ **一繁一简**——头饰服装是"有机的、珠宝式繁复"，眼镜是"精密的、细金属、克制的"，繁简对位才有层次，否则全是珠宝会腻；④ **气质**——疏离 + 斯文。
**How to apply:** ① 出一张"漂亮但平"的脸时，先看**上庭有没有压住视线的东西**，没有就补一个精密小物件（细金属额饰／极细压发链／眼镜／单片镜），别只在那儿调五官；② **换副眼镜 ≠ 抄角色**——眼镜是通用配饰，不构成角色识别（不像脸和服装造型），真正要躲的是"这张脸＋这套衣服＋这副眼镜"三件套同时复现；③ 用户先接受、后反悔这类事，按新结论改并把职能拆给他看，别辩解。相关：[[user-visual-taste]]。

**★挂脸锚 vs 纯文字靶：实测差异很小，脸这条线可以走纯文字（2026-09-16）**：同一套骨相/光影文字描述，A 组（纯文生图）与 B 组（额外挂那张脸图，并写明"只提供渲染质感与光影处理手法，不采用其长相/五官比例/发型/配饰"）各出 3 张。结果：**B 组没有一张被拽回原角色**（声明管用），但 A/B 两组差异也不明显——说明**骨相文字已经把方向定死了，挂锚的增量有限**。
**How to apply:** 做"全新脸"探索时**优先纯文字**（更干净、无版权牵连），只在需要精确复现某张脸的**渲染质感**时才考虑挂质感锚。反面同一条：**想靠堆描述去逼近一张参考脸，收益递减很快**——写到"骨相 + 光影"这一层基本就到顶了。

**★别照抄参考图的发色（2026-09-16 踩到）**：我把参考图的"银白色长发"原样写进脸靶提示词，结果**6 张候选脸全是银白发**，等于把整批绑死在同一个色系。
**How to apply:** 写角色派生提示词时**逐字段问一句"这是参考图的特征，还是这个新角色该有的特征"**——发色/瞳色这类高辨识度字段最容易顺手抄过来；一个批次里要有意拉开色系，否则出来的只是同一张脸换角度。

**★参考图可以反过来当"图像编辑"用（2026-09-16 实测）**：`arkcli +gen --input "@原图"` + 编辑指令（"把…去掉，还原被遮挡的部分；严格保持长相/发型/姿态/光位/背景不变；不要新增任何配饰"）＝ 干净的局部编辑工具。本次用它把脸锚上的眼镜抹掉（眼睛与眼周皮肤还原自然，连雀斑等细节都保留）。本机**没有** flux-fill / iopaint / lama 这类本地 inpaint（ComfyUI 侧也没有），走云端这条路最省事。契约见 [[reference-ark-account]]。

**参考图会连"姿态"一起带，"挂锚点"必须选裁切范围（2026-09-13 即梦 A/B 实测）**：同一条提示词、同一张灰模帧，三版对照——① **只喂灰模帧**：姿态最贴灰模（平躺/头下脚上保住），但背景被抹成素色、**腰间米色小布袋丢了**；② **灰模帧 + 整张立姿定妆锚点**（四格角色图）：造型/服装/袋子/场景最准，但**人物被拽成站立**（平躺没了）；③ **灰模帧 + 锚点"面部局部裁切"**：姿态保住、袋子也在，代价是背景偏素。**Why:** 参考图是"以图为唯一依据"，锚点图里的**姿态、构图、配饰会被一起继承**——整张立姿立绘当然把平躺拽成立姿（同 [[feedback-video-quality-standards]] 第26条"立姿定妆拽姿态"）。**How to apply:** ① 配饰（袋子这类重要锚点）**靠锚点图带，不挂锚点就会丢** → 锁造型必须挂锚点；② 姿态与锚点冲突（平躺/蹲/卧）时把锚点**裁到脸/上半身**再挂，别把整张立姿图丢进去；③ 姿态与场景不能兼得时宁可先保姿态（姿态错了整镜废，场景可靠提示词补）。

**★「六宫格设定表／角色卡」不能当脸锚，但是最好的造型锚（2026-09-18 实测）**
一张 1000×772 的正式角色设定卡（主立绘 + 4 个细节小图 + 中文档案表 + 色卡），**主视图的脸实测只有 80×94px、右上头像格 102×100px**——远低于上面那条 ~300px 脸锚线，**当脸锚必糊**。但它有别的锚点给不了的东西：**干净灰底 + 中性站姿 + 全身可见的服装真源**。
**How to apply:**
① 设定表**只当造型锚**，而且**必须裁掉排版**（只留主立绘那块），否则"六宫格＋文字格＋色卡"会被整张编码进去——同"参考图永远赢过文字"，模型会把"这是一张中性站立的设定图"压过提示词里写的动作；
② 需要**动作镜**时，造型锚用设定卡（中性站姿）比用成片抽帧**更好**——成片帧会把它自己的腾空/受击姿态一起带进新镜；
③ 脸锚另找：优先目标片的**特写帧**（本轮白玖璃特写实测脸 **370×540**＝达标），中景帧只有 **180×220**＝偏弱。

**⚠️ 我打算「弃用用户递来的素材」时，先量再判——他手里常有正确答案（2026-09-18 连错两次）**
同一轮里我错了两次：① 断言"薇拉根本没有定妆图"→ 其实有（s05–s07 ＋ 正式角色卡B），只是生成时没接上；② 提议"薇拉镜改用 s05–s07"→ 又错，那套是**金色板甲＋大天使翼的圣骑士**，跟目标片里的**白纱裙＋紫晶胸甲＋小肩翼**根本不符，而**用户的角色卡才是对的**。
**Why:** 用户反问「这两张角色卡不能直接用么」＝**大概率我漏看了它的可用面**，不是他不懂锚点规则。他对自己的素材库比我熟，我的"不能用"经常只对一半。
**How to apply:** ① 否掉一件素材必须给**实测数字**（脸多少像素、什么景别、排版里有什么），不给"我觉得/一般认为"；② 回答结构＝**先答他那一句"能不能用"**（能不能），再给量出来的边界（当什么锚不行、当什么锚正好）；③ 发现自己前一轮的判断被推翻时**明确撤回并说清错在哪**（同 [[feedback-collaboration-style]] §3），别悄悄改方案。

**★★胸像定妆是结构性缺口：全身比例／持剑手每次现编（2026-09-21 实测）**
《烬骨辞》两张脸锚 `char_shenqingci.png`／`char_xiaojinyan.png` 都是**胸像/半身**（1584×2816，脸很大、锁脸实测 0.922 完全没问题），但**没有全身、没有持剑的手、没有兵器**。后果：任何双人全身镜里，身高、臂长、袍摆、"他的剑尖够不够得到她"全部由模型当场编——**所以"两人隔三步、剑尖够不到她"这类几何约束无论怎么写、怎么画线稿都锁不住**。
**How to apply:** ① 接动作／双人全身戏之前先问"锚点有没有全身"，没有就**补两张全身定妆当造型锚**（同脸、可见全身比例与持剑手），别指望文字补；② 判"这张锚够不够用"要按**这一镜需要什么**判——胸像当脸锚很好、当造型锚等于没有；③ 同 [[feedback-animation-decomposition]] 那条"六宫格设定表当造型锚"是一个道理：锚点带什么由图里有什么决定。

**★★线稿／宫格当参考图喂云端 i2i：只被读成语义，不被读成几何（2026-09-21 花钱实测，别试第二遍）**
Seedream 5.0 pro 上做了三组对照，同一镜同一提示词：① **宫格一张输入**（上排两张定妆＋下排三格动作分解线稿）；② **线稿＋脸锚分挂两张**；③ 纯文字。结果：
- **两种喂法都没锁住几何**——线稿明确画着"剑垂在身侧、光带单独悬在半空、两者之间一段空白"，出图一律变成"举剑、剑尖发光抵向她"。模型把线稿读成"这里有个持剑的人、一道光"，不是构图约束。
- **宫格比"分挂两张"更差**（距离塌得更狠、姿势更偏），但**宫格不会被画成分格拼贴**这点是干净的。
- 参照本机出图侧 ControlNet 的旧实测（边缘覆盖 73% vs 纯提示词 15.6%）⇒ **真要按线稿的形走，得 ControlNet lineart，不是挂参考图**；而 lineart 又锁不住脸（本地 Redux 封顶 0.49）→ 构图与脸分属两条管线，别指望一张参考图同时办成。
**How to apply:** ① 需要锁构图时，先想**能不能把冲突元素拆到不同镜**（打戏的正解就是把施术者从命中镜里整个拿掉，见 [[feedback-combat-shot-grammar]]），这比加锚便宜；② 线稿／宫格留作**给我们自己看的动作分解表**和评审沟通物，不当控制信号；③ 构图线稿用代码画（PIL 数值定死站位），零成本可复改。

## 造型锚 ≠ 首帧来源（2026-09-24 剑阵灭世 v5 实跑）

## "画风漂了"不一定是锚链二手——多锚颜色冲突 + Seedream 渲染词错位是两个常被忽略的真凶，视觉 QC 必备（2026-09-25 dz0b' 实操）

**规则**：用户反馈"画风变了/不对"，**视觉 QC 必须由能看图的模型或人执行**——机器层 QC（SCRFD/ArcFace/Lab/水印/烧字）判得了脸对不对、字干不干净，判不了"画风像不像"。机器层全过≠画面没漂。

最常被忽略的两类漂源：

**① 多锚图颜色冲突**：脸锚与造型锚各自带的可见服装颜色不一致（典型坑：脸锚领口露奶白+朱砂、造型锚是深海蓝+银），Seedream 同时读两个信号，文本又写了奶白+朱砂——三处一致的颜色会赢，造型锚的深海蓝被完全压掉，整张调色板翻盘。
- **检测方法**：所有锚点图过 arcface 量脸同时**目视一眼衣领/肩部颜色**——脱锚脚本不量色。
- **正解**：让脸锚与造型锚的可见颜色一致。① 直接从造型锚同色系的脸部单独裁一张当脸锚；② 用**生成造型锚的同款工具（即梦）重出一张脸锚**——同只手画的风格不打折；**Real-ESRGAN x2/x4 超分是兜底但不如重出**（GFPGAN/CodeFormer 会"补"五官细节，身份会漂，绝对不能挂脸锚）。

**② Seedream 渲染词错位**：写"35mm 定焦质感/细颗粒/无镜头光晕/次表面散射"是摄影/电影质感词，会把即梦那种"3D 半写实国漫插画"推向"游戏 CG / 武侠手游"——同一条"半写实"在两套词库下读法不同。dz0b' 实测：皮肤偏塑料、衣褶偏硬、明暗反差偏大、明度高光晕开、整体像国产武侠手游立绘。
- **检测方法**：出图后目视皮肤质感（次表面散射 vs 平涂塑料）、衣褶走向（垂坠 vs 硬切）、明暗过渡（柔长 vs 硬边界）——这三条直接判"3D 插画 vs 摄影/游戏 CG"。
- **正解**：删干净摄影/电影质感词，只留一句"渲染风格完全按第二张参考图"，让锚图自己说话。

**Why:** dz0b' 三张产物 ArcFace 0.56/0.60/0.60、水印干净、字干净、SCRFD ≥0.7——机器自检全过；用户肉眼一句"这怎么画风都变了"就把整批打回。换带视觉的模型才把两条漂源看出来。**机器层 QC 在"画风"这一维度上是瞎的，视觉 QC 必备，不能省**。

**How to apply:**
- 出图批次提交前自检：**视觉 QC 与机器层 QC 同等重要**——挑 1-2 张亲自看图（人审或带视觉的模型跑 `Read`）。
- **"画风漂了"归因顺序**：① 多锚颜色冲突 → ② 渲染词错位 → ③ 锚链二手（见前条 ★规则）→ ④ 锚图本身问题。按这个顺序查，**别先改措辞**——措辞大概率不是原因。
- **即梦 image2image 重出脸锚比超分干净**：同只手画的风格不打折；Real-ESRGAN 只放大不变模糊但跨管线；GFPGAN/CodeFormer 身份会漂。同源这条优先于一切"超分更清晰"的诱惑。
- 模型选型附注：**MiniMax-M3 有视觉能力**（其他模型 Read PNG 直接报"does not support reading image files"）。视觉 QC 必须用有视觉的模型跑，或由用户亲自看图。

- **★2026-09-25 深夜实测：把整张设定表换成"单格裁切版"能物理消掉两类污染，但有边界。** `jm_9862` 整张带烧录中文标签＋一杆露刃金属矛，靠职责句"不要采用它的标签／那杆露出金属的长枪"挡——**而那句免责句本身在点名**（见 [[feedback-prompt-iteration-priors]] 第 9 条）。换成按列裁出的 `9862_p01.png`（原图像素裁切、非二次生成，所以仍算"原始素材"，不违反上面那条二手锚规律）后：**① 标签没了 ② 三格武器全裹无金属 ③ 装饰密度不掉**（同一人物归一到 1000px 高量衣料边缘密度：整张 70.3 vs 裁切格 69.6，背面 59.9 vs 62.0）。**但"多视图"这条消不掉**：三视图格的多视图是它的构造，按列墨量切单格会切进邻格（纱氅互相叠压，切不出干净单人）。⇒ **要彻底去掉"多视图"点名，只能另找单人图，而单人图往往装饰档次更低**（本项目 `9374_p01` 是单人正面但是简款劲装）。⚠️ 这种"锚对锚"的纹理密度比较合法，**拿裁切格跟 1536×2688 的产物比仍然反向**（分辨率那条规律不变）。

**★当首帧／身份锚的图，"脸被照亮且完整"优先于"这张最好看"（2026-10-01 即梦 v7 批实判）**
同一批四张里，**最好看的两张恰恰不能当锚**——editorial 硬光把她半张脸沉进黑里、其中一张眼睛那一块是一整片黑。
这种光法当海报很好，**当首帧＝下游没有身份载体**，H3 从第 0 帧就接不到脸，跑起来长相必漂。
⇒ **筛首帧／脸锚的顺序：① 脸亮不亮、完不完整（眼睛那块不能是黑的）→ ② 脸够不够大（见上文 ~300px 线）→ ③ 起手姿势对不对 → ④ 最后才比好看。**
"我推这张因为它最好看"是错的排序；报候选时要把"出局原因＝光把脸吃了"单独讲出来，别只给推荐号。
同族：[[feedback-previz-closeup-limitation]]（特写镜三层质检）、[[reference-minimax-h3-local]]（锚只钉几何不钉长相）。

## ★通道边界（2026-09-30 实测）：即梦／Seedance 视频通道上"必带脸锚"**不是硬前提**

同一晚纯文生视频（不挂任何参考图）跑 Seedance 2.5／720p／15 秒，一份 598 字八镜投喂版里两个自拟角色

（同族反证：09-28 即梦纯 t2i 中位 0.280 锁不住跨批复用，但**批内自洽**能锁住——见 [[reference-local-face-identity-transfer]]。）

**⚠️ 反向的坑（同日 2.5 实跑抓到）**：不挂锚虽然锁得住人，但**只写"怒视／杀意"这类情绪词会让瞳孔变红发光**

## 外部调研：「人和武器一起锁」还剩哪三条没走过（2026-09-27 网上检索，未实测）

**根因（外部共识＋本机实测对得上）**：细长裹布杆＝**低先验目标**，扩散模型会把它"吸附"到刀/剑/手枪这类高先验类别（本项目的 长杆→刀、→子弹、裸杆头 全属此类）；而脸是身份向量，参考图注入封顶弱（本机 Redux 0.49 / H3 保持 0.57）。**⇒ "锁人＋锁武器"是一个请求里塞两种模态的约束，外部文章的结论与本机一致：分两条管线，别指望一张参考图同时办成。**

**网上还会反复推、但本机已花钱/实测否证过的，别再当新方案提**：① 挂线稿·宫格当参考图锁几何（只被读成语义，2026-09-21）；② 整幅参考 i2i 改机位（机位被锁死，2026-09-24）；③ 禁令句（＝点名，R5 v2.1）；④ 换脸/超分产物当锚（二手锚掉质感）。

**没走过的三条（按性价比）**：
1. **权重层＝把"角色＋道具"当同一个主体一起训（不要分开锁）**。⚠️ 2026-09-27 追问"有没有成熟方案"时查清的关键修正：工业侧写角色一致性的文章**通篇只讲角色、没有一篇讲道具**，真实生产里道具是**跟着角色一起进训练集**的（训练图里人一直拿着它）⇒ 道具变成身份特征的一部分被同一个 LoRA 记住。**这解释了本机"武器单独挂锚总失败"——在参考图路线上双锚拆分是对的，但在训练路线上分开锁是反的。** 外部口径："一致性从概率问题变确定性问题"；训练集下限 **20–50 张、多角度多表情**，Rank 8–16、lr 1e-5–2e-4、Epochs 5–20，**固定 seed 是整条产线的定海神针**；风险项＝"人物复制粘贴感"。IC-LoRA＝为"上下文一致性"专训、全局生效、但高度依赖结构化提示词。**本机这条管线已经验证跑通（见 [[user-research-ai-profile]] 的 LoRA 段），缺的从来不是能力，是训练集。**
2. **真几何层＝3D 灰模/depth 条件，不是画出来的线稿**。外部管线：Blender 摆真几何 → CG 片段当 **dense conditioning stream**（LTX 2.3 + 3DREAL adapter），修法叫 **"crop your refs"**（参考素材裁到与灰模帧匹配）。⚠️ 与已否证那条的**分界**：否的是"云端 i2i 挂线稿"，不是"结构注入"——本机自己量的 ControlNet 边缘覆盖 73% 就是结构注入有效。
3. **编辑派生＝一张"人和武器都对的母图"逐镜改，而不是每镜重画**。新渠道 **`qwen-image-edit-max`**（百炼官方标注"角色一致性更强"，输入 1–3 图，可指定 512–2048、按 16 对齐，按张计费）；Seedream 4 多图融合官方口径 **2–8 张、最佳 2–4 张**且逐元素写职责。⚠️ 限定：**改细节/服装/背景可行，改机位仍撞 09-24 那条**。

**★改"起拍动作"之前，先看那张首帧画的是起态还是末态（2026-09-27 实查，武昭君仪 H13）**：fl2va 的首帧是硬几何锚，第 0 帧的姿态会强拉第一拍。H13 借来新起拍「刀尖先朝她面门扎过来」后我去看 `kf_out/H13b_s0.png`——图里**对手已经坐地、短刀已经落在地上、他还攥着杆的另一端**（那是上一镜的共持关系）。⇒ **这张首帧画的是本镜的末态，跟旧词第一拍就已经冲突，与新词更冲突 ⇒ 与借不借编排无关，必须重出首帧。** 而 H12 那张（她双手持杆、杆尾拖在他脚边、他双手空着站在杆端旁）与新起拍"伸手攥住杆身猛扯"正好兼容。
**How to apply:** 动任何一镜【事件脚本】的第一拍（或最后一拍）时，把那张首帧调出来对一遍"图里的人正在做哪一拍"；**首帧画成末态＝这条镜直接不可渲**，属花钱前就能免费发现的缺陷。同族：[[feedback-video-quality-standards]] 的"不冲突首帧"。

**流程层（外部两篇独立强调，与本机做法同构 ⇒ 说明方向对）**：① **"武器也当角色管"**——给道具单独建主体资产（多角度/多握持/布纹特写/两端打结特写），与角色同级；本机角色有 26 件资产包，武器只有 2 张线稿，这是缺口。② **canonical style paragraph 全片一字不改** ＝ 本机"基调逐镜带上"。③ **先锁静帧再让它动**（外部称"通用保底，模型换几代都成立"）＝ 本机现行架构。

**纪律不变**：以上都是外部结论、**未本机实测**；选型靠同帧实测＋用户盲选，比价只做初筛（[[feedback-cost-consciousness]] [[feedback-low-expectation-external-capability]]）。

## ★"定风格"先问是哪一层：渲染流派（分类级）≠ 校色（参数级）；资产包内部常跨多个流派（2026-09-27 武昭君仪）

用户说"后续所有画风都按现有资产图的画风来"。我先去量亮度／饱和／暗部 —— **问错层了**，被他纠正："不是这些细节上的画风，是风格，比如真人和高精度半写实3D的区别。"
- **教训**：接到"定风格"先确认层次。**渲染流派（真人实拍感 ↔ 3D 渲染感 ↔ 2D 绘画感）是分类级、决定成败**；曝光／饱和／对比只是同一流派内的校色。先答上层，再量下层。
- **一套"资产包"不等于一种画风**：实测 41 张，角色/道具设定组是灰棚底平光（亮度 140–160、饱和 0.09–0.13），场景组是压暗高对比（亮度 41.2、暗部 60.5%、饱和 0.39）；**同组内部还跨流派**（主角图皮肤高频 2.85–4.49＝渲染感，配角图 5.78–11.57＝真人照片感，差 4 倍）。⇒ 用户说"按资产图"时必须先量出**有几派**再让他定档，不能直接抄一句基调。
- **真人感锚 ⇒ 真人感产物，这是因果不是巧合**：`CAST_ANCHOR` 把两张真人感配角图挂成 H12／H13 的脸锚，而全批首帧里唯二偏真人感的正好就是这两张。**⇒ 修法是换锚，不是改措辞**（同上文"风格信息在图里不在文字里"）。写"不要真人实拍"还违反"负面表述激活概念"，只能正向写渲染语言自己的物理特征：`3D rendered CGI character, soft pore-free subsurface-shaded skin, stylized-realistic game cinematics look`。
- **可机检的代理判据（有限适用）**：真人皮肤有毛孔级高频＋传感器噪点，3D 渲染是平滑着色 → 量脸中央皮肤区 `std(img−gaussian1.2)` 与 `std(img−median3)`。**只在"图 vs 图"层有效（资产图、首帧、静帧）；判不了成片**——成片的高频损失分不清"风格变了"和"被低分辨率＋视频编码糊掉"。成片那层要换语义裁判（VL 问"真人实拍还是 3D 渲染 CG"）。
- **落地位置要说清**：`.anchor.json` sidecar 只是留痕与机器核对，**真正决定挂哪张的是代码里的锚点映射表**；只改卡片等于没改。降级某张图时两处都要动，且改映射表属生产提示词改动、要先给用户看（[[feedback-review-production-prompts]]）。

## ★LoRA 现状与"锁武器"的成熟度边界（2026-09-27 查本机 safetensors 头＋外部）

- **本机 SDXL 没有"高精度 CG 半写实（3D 渲染）"风格 LoRA**：`国风_明制SDXL_v1` 的训练底模是 `chinese-hanfu-sdxl-v20`，**那个底模已经不在盘上**（只剩 sd_xl_base / majicmix_realistic_v7）⇒ 挂上去属跨底模未验；`add_details` 是通用细节增强、`ip-adapter-faceid-plusv2_sdxl_lora` 是 FaceID 配套、`RealSkin_Flux`（dim 2）方向相反（推向真实皮肤）。外部侧：liblib 上量最大的"国漫 3D 人物 CG"其实是 **FLUX.1-dev** LoRA ⇒ **真要挑风格 LoRA 挑 FLUX 侧，不是 SDXL。**
- **★训练集 caption 里带背景／布光标签，LoRA 会把棚拍感一起学走**：`faceA_sdxl_v1` 元数据标签频率含 `"plain light grey studio background"`、`"soft frontal studio lighting"` ⇒ 以后训角色 LoRA，**背景／布光要么从 caption 去掉、要么显式标成变量**，否则资产展示图的灰棚底会被记进权重。
- **"锁人"有成熟配方（角色 LoRA＋IP-Adapter＋三视图底图＋固定 seed），"锁武器"没有**：工业侧文章通篇只讲角色；真实生产里道具**跟着角色一起进训练集**（人一直拿着它）⇒ 道具成为身份特征的一部分。**这解释了本机"武器单独挂锚总失败"：参考图路线上双锚拆分是对的，训练路线上分开锁是反的。**
- **不建议为画风去下载现成风格 LoRA**（撞上 [[feedback-evidence-loop-trap]] 的"买素材≠能力转移"）：风格 LoRA 给的是"某一类 3D 渲染感"，不是"我们那批资产图那一档"；载体仍应是那张原始资产图。

## ★换锚会「整幅重掷」：输入端单变量 ≠ 输出端单变量（2026-09-27 arm6 实测，武昭君仪 H12／Seedream 4-0）

按上一条的教训重做的干净臂：**提示词逐字不变（脚本 assert sha）、seed 不变、锚的张数与尺寸不变，只把第 5 张锚从真人照片感配角卡换成同设定的 CG 渲染感卡。**

- 结果：皮肤两项代理指标全线下降，**连根本没被换的主角区一起降**（男性区高频 6.52→5.34／噪点 2.81→1.97；主角区 9.46→6.37／4.48→2.98，降幅 18–33%）⇒ 方向上支持"**真人感是锚带进来的、不是对象先验带进来的**"。
- **但同一张图里：左右站位翻转了、配角头发没了（变秃）、义肢丢了。** ⇒ **同 seed 下换任一张输入图＝整幅重掷**，"渲染流派"不是唯一动了的输出变量。**n=1 的换锚对照只能给方向，不能算归因。**
- **★由此得出的操作规则：做任何锚点／输入图 A/B 之前，先量"同配置重掷"的方差**（同 prompt 同 seed 换一张无关紧要的输入、或同配置重跑 ×3）。不知道噪声底，"换锚有效"和"重掷碰巧"分不开。**这条优先于继续加臂。**
- **反例侧证**：撤**道具**锚的两臂保住了原站位，撤／换**配角**锚的两臂各自翻成新构图 ⇒ 锚的影响面不等大，但都不是"只影响那一个对象"。
- **弱载体陷阱**：新出的 CG 版配角卡本身只是"比原卡干净"，离基线那档平滑着色还有一截 ⇒ **用弱风格载体测"锚决定画风"，效应会被系统性低估**。测之前先确认锚自己到位没有。
- **派生卡的自洽性要逐视图核**：那张四视图卡正视图没画义肢、背视图画了两条 ⇒ 下游 arm 里配角丢义肢是**卡的缺陷**，不能算进画风判据。**拿设定表当锚前，先逐视图读一遍它自己讲不讲得通。**
