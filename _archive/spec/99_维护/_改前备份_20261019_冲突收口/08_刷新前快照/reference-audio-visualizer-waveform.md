# 音乐反应波形层（叠加到任意画面上）

2026-09-21 为用户的 `E:\星涌_MV_h264.mp4`（3:18 / 1920×1080 / 30fps / AAC）做"随音乐变动的波形动态"时趟出来的。工具脚本 `C:\Temp\make_waveform.py`（参数化：`--wav --out --fps --limit`），可搬去任何项目。

## ★最反直觉的一条：时域包络画出来"不动"

第一版按经典做法做——取 |音频| 的峰值包络（10ms 窗 / 2.5ms hop）、快攻慢放平滑、按全曲 99.5 分位归一，再镜像成柱子。**结果屏幕上是平顶的一块"透镜"，看着完全不随音乐跳。**

**根因不是参数，是选错了量。** 成品音乐经过响度战争，**在 5–10ms 尺度上的峰值包络几乎是常数**（处处贴 1.0）——包络本身就没有信息量，再怎么调增益/幂次/归一都救不回来。

**正解＝用分频能量，不用时域包络**：
- 每视频帧一次 2048 点 Hann STFT（hop = sr/fps，一帧一谱）；
- 40 Hz–14 kHz **对数**切 320 个带，带内取幅度均值；
- **每个带按"自己那条时间轴"的 92 分位归一** ← 这一步是关键。不归一的话低频永远顶格、高频永远贴地，画面看起来还是死的；
- 再乘一个全局响度因子（让安静段整体收小，不是只有鼓点在跳）；
- 逐带快攻慢放（上升 30ms / 下降 170ms）→ 有弹性不抖。

另配一条低频段（前 12 带）均值单独做 **bass pump**：只调制整体高度，不改形状。

## ★第二反直觉：`blend=all_mode=screen` 会把整幅画面染成品红

波形层渲成**纯黑底**视频，再用 ffmpeg `blend=all_mode=screen` 叠到画面上（加性发光、不用 alpha、不用把画面解码进 python）——思路对，但**默认 blend 工作在 YUV 空间，会把 U/V 色度平面也一起 screen**（128 为中心，screen 后 ≈192）→ **整幅画面色相偏移、发品红**，波形本身反而看不出问题。

```
[0:v]format=gbrp[a]; [1:v]format=gbrp[b]; [a][b]blend=all_mode=screen,format=yuv420p[v]
```
**先 `format=gbrp` 转到 RGB 再 blend。** 任何"两个视频做 screen/multiply/addition 混合"都适用，不只波形。

## 画面构成上的几条经验

- 柱子用**镜像**（上下对称于基线）、基线放在 **0.72×高**，别居中，否则挡住主体。
- 两端**余弦淡出**（`cos(linspace(-π/2,π/2,N))^0.9`），否则边缘硬切很廉价。
- 辉光＝半分辨率 `GaussianBlur` 后放大回原尺寸相加（权重 ~0.5–0.6），比全分辨率模糊省一大截时间。
- **颜色分档的阈值要按实际分布调**：默认把"暖金"设在 amp>0.45，结果峰值几乎染不到金 → 降到 0.30 才有高光层次。调色板直接从用户给的参考图取（深蓝→青→暖金）。
- 5940 帧 1080p 在 `python_embeded`（numpy 2.5.1 + cv2 5.0 + scipy 1.18）里逐帧 numpy 画 + 管道喂 ffmpeg ≈ **3–5 分钟**，不慢，不用另装库；**没有 soundfile，读 wav 走 stdlib `wave`**。

## 两条 numpy 硬坑（都白跑过一轮）

- **滑窗峰值别用花式索引**：`a[np.arange(win)[None,:] + np.arange(n)[:,None]*hop]` 在 9.5M 帧上会**一次要 68GB** 直接 `ArrayMemoryError`。改用 `np.lib.stride_tricks.sliding_window_view(a, win)[::hop].max(axis=1)`（视图，不物化）。
- 逐帧切片时 `Ecol[s:c1]` 长度是 `COLS-1`（差一），要么写 `Ecol[s:s+COLS]`，要么先 `c1 = min(c1, len(Ecol)-2)` 兜住尾部。**批跑到最后一帧才崩最坑**，长度保护写在循环里。
