## 1. 分层判据

### 主判据（一句话）

> **这句话能不能从一个没看过我们片子的人嘴里说出来？**
> 能 → 通用层（本层）。不能 → 项目层（`30_项目层\`）。

### 三个辅助测试（主判据判不动时按顺序用）

| 测试 | 做法 | 判读 |
|---|---|---|
| **T1 名词剥离** | 删掉角色名／道具名／画风名／项目代号／镜号，看规则是否仍完整可执行 | 仍完整＝通用；残缺＝项目。**剥离出来的那一坨登记为通用规则上的"填充槽"**（见 §3） |
| **T2 换项目是否需重做** | 问"新项目要不要重新实测／重新设计才能用这条" | 要＝项目层；只是换个参数值＝通用层带槽 |
| **T3 是否被机器写死** | 值出现在 `config.yaml`／workflow yaml 默认值／`prompt_rules.py` 词表里 | 属项目层；且额外标 ⚠「机器侧仍按上一个项目写死」——这是**风险登记**，不是分类 |

### 两条边界（最容易判错的地方）

- **参考机条件 ≠ 项目专属。** s/帧、耗时、显存悬崖、额度上限这类**绑机器不绑剧本**，属通用层，但必须标
  「参考机条件：RTX 5060 Ti 16GB + 32GB 内存，**换机必重测**」。
- **审美口味 ≠ 项目专属。** 用户对"清冷素净／东方剪影／排斥好莱坞模板"的偏好跨项目成立，属通用层（`R10`，见 §5 注），
  但具体某个角色的定妆词属项目层。

## 2.0 元规则（优先级高于本节其余全部内容）

**M1 所有顶层规则修改必须有事实证据支撑，且必须经过人审同意后才能修改生效。**

> 用户原话（2026-10-02）：「补充一条元规则：所有顶层规则修改必须有事实证据支撑，
> 且必须经过人审同意后才能修改生效。」
> 本条自身的落盘授权＝这一轮裁定；此后任何修改（含修改本条）都走下面的生效顺序。

- **顶层规则的范围**＝`20_通用规范层\` 全部文件（含本索引）＋ `30_项目层\` 里标了 `上位` 的条目。
  `01–10` 存档层不适用（它本来就只许追加勘误注记、不许新增规则）。
- **什么算事实证据**＝盘上可复跑的实测数据、可指认的文件/代码位置、或用户原话。
  **推理、类比、"看起来更规范"、外部方案的权威度都不算证据**，只能作为提案理由写进待审文档。
  证据必须同时写明：怎么测的、样本量、口径边界（乐观值/冷启动/页缓存热等）、能否复跑。
- **什么算人审同意**＝用户在对话里明确点头，或批准了含该条改动的待审文档。
  **agent 不得代登记；批次授权只覆盖执行，不覆盖改规则。**
- **生效顺序**：提案（落 `E:\创作\_待审文档\`）→ 人审 → 改本层 → 同批改机器执行者脚本 →
  `check_layers.py` ＋ `check_tables.py` ＋ `build_manual.py --check` 三绿 ⇒ 才算生效。
  未走完这条链的改动**视为未生效**，引用时按改动前口径读。
- **派生的机器化**（10-02 落地）：`E:\若水AI电影\system_manifest.json` 的每条 gap 必须带
  `evidence`（盘上存在的路径）或 `missing`，由 `E:\若水AI电影\99_维护\scan_system.py` 自己复核，
  复核不过标 `evidence_broken`。
  ⇒ "有事实证据"从口头要求变成一个可复跑的检查。
  ⚠ 该 manifest 与本层的关系是**只登记现状、不拥有规则**；它若与本层文字冲突，以本层为准，
  并把冲突记为一条 gap，不许改本层去迁就它。

## 2. 权威与写入方向（**违反这条就等于把本层变成第二个漂移真源**）

机器闸（`check_preflight.py` 词表/结构闸、`h3_rule_gate.py`、`prompt_rules.py` 法条、`prompt_lint.py` 字面闸）
**读的是上游文件，不是本层**。上游降级后若不守顺序，本层会与闸悄悄分叉。

**改规则的唯一正确顺序：**

1. 改本层对应条目（`20_通用规范层\R*_*.md`）；
2. 若该条「机器执行者」不是 `[人]`／`[废]` → **同批改那个脚本**（词表、判据、结构要求）；
3. 跑 `py -3.12 "E:\本地工作流规范手册\99_维护\check_layers.py"` 确认两层仍对得上
   （10-02 落地。**必须写绝对路径**——原来这条写的是相对路径，从手册根以外目录跑必失败，
   而且该脚本 09-27 时还不存在，这条命令自写下那天起就是死的。
   **当前行为＝只报不拦，默认退出码 0**；要机器拦得加 `--strict`，而 `--strict` 现在**没接进任何闸门**）。
   并跑 `py -3 "E:\本地工作流规范手册\99_维护\check_tables.py"`（09-28 新增，**只读**）确认自写文档的表格没被单元里的裸 `|` 劈列——
   本层大量规则靠表格承载列级语义（判据／执行者／槽），**错一列＝错一条规则**，而这种缺陷肉眼读源码看不出来。
4. 上游存档**只允许追加勘误注记，不允许新增规则**。

**每条规则必须登记机器执行者**，取值沿用你已经在用的六态标记（出处：`H3提示词规则_现行合并版` 状态图例）：

| 标记 | 含义 |
|---|---|
| `[拦]` | 机器命中即拒绝出表／拒绝提交（写脚本名 + 判据名） |
| `[报]` | 机器只提示不拦（warn/info） |
| `[拼]` | 编译时逐条自动拼进提示词，不靠人记 → 不会被漏 |
| `[人]` | 机器判不了，只能人判或生成后 VL。**这类条目是本层最易腐烂的部分**，要写清由哪个关口触发人审 |
| `[废]` | 已被覆盖，保留只为防止有人再引用 |

⚠ **没标执行者的条目视为 `[人]`，且视为"现在没人管"**——这是合并版原话「没标'已执行'的等于现在没人管」的延续。

## 3. 通用层不是"删掉项目内容剩下的"，而是**带空槽的规则**

每条通用规则若在项目里被填了具体值，本层要写出**槽名**，项目层负责填值并登记关系。

**样例（槽 = `道具锁·尺度与封口描述`）**

- 通用层 `R4-09`：道具锁必须带**尺度线索**与**封口描述**。
  机制：只锁"形态数量"不够——当镜内出现"尖端朝镜头 + 手部特写"时尺度线索消失，模型会按**小物体**重解释该道具。
  出处：`02\H3提示词规则_现行合并版` §二 不变量层（`SPEAR_LOCK` 条）；反例见该条 H07。
  执行者：`[拼]`（各项目编译脚本自行拼接，本层只规定"必须拼且必须带尺度"）。
- 项目层填法：
  - 武昭君仪 → 「长度与她身高相当、粗细如她手腕、通体一层布到端、两端只把布收细打结、此外没有开口或缝隙」
  - 新项目（道具是外露金属长剑）→ 槽里换成完全不同的值，甚至 `R4-09` 的"封口"子句整条不适用。

⇒ **换项目带走的是槽里的值，不是规则本身。** 如果某条规则一换项目就整条失效，说明它**不该在本层**，应下移项目层。

## 4. 项目层回溯用的四元关系（定义必须统一）

| 关系 | 定义 | 例 |
|---|---|---|
| **补充** | 通用层没规定，项目层新增 | 仙女星系「帝国与联邦」舰桥尺度口径 |
| **收窄** | 通用层给了范围，项目层选一个**更严**的子集 | 通用允许"正向描述可见材质"，武昭君仪禁到"只许写布、不提里面是什么" |
| **例外** | 通用层有规则，本项目**反向**成立，**且必须给实测理由 + 生效剧情段** | 通用「进片视频首帧一律走云端」；无音 09-24 之前的历史片首帧是本地 FLUX 出的 |
| **冲突** | 两层说法不一致**且未裁** | —— |

⚠ **冲突项不许留在项目页里当规则用**：一律上移到 `R_作用域与例外登记表.md` 的待裁队列，正文处标 ⚠ 并禁止引用。
`check_layers.py` 第 4 项校验这一条。**10-02 实测更正**：原来这句写的等式（`关系=冲突` 条数 **必须等于**
未裁项数）**不成立，脚本已按三个数分开报、不凑数也不假装通过**——
实测三个数＝项目层 `关系=冲突` **1** 条／登记表 §一 含「冲突」 **2** 行／登记表 §二 `未裁|未修|未验` **8** 行，
两侧 3 vs 8 不等。原因是 §二 队列比「冲突」宽：它还收 `未验`（等实测，如 C4）与 `未修`（文档自相矛盾，如 C15），
这两类在项目层 `关系` 列**不写"冲突"**。⇒ **等式成立的前提是"只有冲突才进队列"，与本层现行口径不一致；
要不要收窄 §二 口径属顶层规则修改，走 §2.0 M1，未裁之前脚本继续分开报。**

**作用域强制（本层最重要的一条纪律）**：
凡是"锁某个道具／服装／场景当前状态"的句子，写的时候必须带上**它锁的是哪一段剧情**。
跨段复用时先问"这个东西在故事里变了没有"。
出处：`02\H3提示词规则_现行合并版` §十；该节预言的坑——「若不标作用域，下一个人会以为'这项目不许出现枪'」。

## 5b. 旧名→新名映射（10-03 批 7-3：通用层换成 `R_` 命名空间）

**为什么换**：`G` 这个前缀以前同时指**机器闸**（`G1…G13`）和**规则文件**（`G2/G4/G5`），
两份文档互相引用时要靠上下文猜。换完之后：**`G` 只属机器闸，`R` 只属规则层**。

**机器闸编号 `G1–G13` 一个都没动**（它们长在代码里：`check_preflight.py` 的 `ALL_GATES`）。

| 旧名（历史写法） | 现行名 | 说明 |
|---|---|---|
| `G2-xx` | `R2-xx` | 提示词结构与接口契约 |
| `G4-xx` | `R4-xx` | 一致性与锚点方法 |
| `G5-xx` | `R5-xx` | 关口与授权 |
| `G_作用域与例外登记表.md` | `R_作用域与例外登记表.md` | 同一份文件，只是前缀换了 |
| 计划中的 `G1/G3/G6…G10` | `R1/R3/R6…R10` | 还没成文，改名不影响"未成文"这件事 |

### 书写约束（新撞字，必须照此写）

换完之后 `R` 这个字母**同时有三家在用**：规则文件号（`R1…R10`）、登记表自己的行号（`R1…R10`）、
以及 H3 侧早已存在的提示词规则编号（`R1–R22`，见 `02_H3提示词规则`）。
所以引用时必须靠**形状**区分，这条是硬约定（先例：`R5-05` 对 `H3` 与模型名撞字的处理——
写清约束，不把别人的编号重新改一遍）：

1. **指通用层某一条** ⇒ 一律写带连字符的 `Rx-yy`（例：`R4-17`）。这是唯一合法的条目形状。
2. **指通用层整份文件** ⇒ 写全名 `Rx_名称.md`（例：`R5_关口与授权.md`）。
   **裸 `R5` 不许出现在正文里**——它同时可能是登记表第 5 行或 H3 第 5 条。
3. **裸 `G数字`**（`G1`…`G13`）从此**只表示机器闸**；`G9`／`G10` 仍是"编号跳空"那个事实，别拿来占位。
4. **H3 自己的规则编号**一律写成 `H3R17` 这种带引擎名的形式（项目层已经这么写）；
   裸 `R17` 出现在 H3 文档里属 H3 命名空间，不进通用层的引用检查。
5. 登记表行号（`R1…R10`）与规则文件号重叠，所以引用登记表某行时要写成
   `R_作用域与例外登记表 第 R10 行` 这种带文件名的形式。

**本层已裁的两件（10-03 逐题）**：① 后期岗草案九条编号跟着改成 `R8-01…09`（`G8` 只剩机器闸）；② **登记表行号不另起前缀**，就用 `R1…R10`——它与规则文件号同前缀这件事，交给上面的形状约束去挡（条目必带连字符、整份文件必写全名、裸 `R5` 不许出现在正文、H3 一律 `H3R17`）。
  理由：`R5-05` 对 `H3` 撞字的先例就是**写约束、不动别人的编号**；而且 `check_layers.py` 的第【3】【4】项拿登记行号做配对与孤儿检查，改前缀得连它一起改并重建反向验证，收益只是「看着更分」。

**历史与在审文档不回改**：`E:\创作\_待审文档\*`、`00_读我\重构方案_两层分离_待审.md`、
各 `_改前备份_*` 里仍写着 `G4-17`（现 `R4-17`）这类旧名——那是当时的原话，改了就等于篡改举证。
它们靠本表消歧。机器侧的对应检查是 `check_layers.py` 第【6】项（**只扫现行真源**，
「待审」文件计数并打印，不静默豁免）。


## 6. 现在就能用的三条自查

写完一条规则，问自己：

1. 它里面有没有**只有看过那片的人**才懂的词？有 → 挪到项目层，本层留槽。
2. 它的执行者是 `[人]` 吗？是 → 补一句"由哪个关口触发人审"，否则它会腐烂。
3. 它带状态吗（某道具现在是裹着的／某人现在穿灰蓝短衣）？带 → 必须写作用域到哪一段。
