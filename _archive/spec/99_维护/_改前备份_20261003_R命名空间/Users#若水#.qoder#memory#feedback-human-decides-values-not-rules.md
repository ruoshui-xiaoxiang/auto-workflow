**规则**：凡是"两种选择都合理、取决于这一次要什么"的东西——审美口味、画风基调、画幅、分辨率档位、
要不要音频、要不要 LLM 润色——**值归人，规则只管留痕**。具体三条硬约束：

1. 规则／注册表里**只声明槽，不写取值**：出现 `default`／`suggested`／"必须选 X"这类字段就是机器又替人决定，
   只是换了个形式（我在 `check_registry.py` 里加了 [F] 项专门查自己这一点）。
2. **空槽＝报错，绝不代填**。报错文案要指名"哪个槽、为什么必须你给"。宁缺不猜（G4-06）的延伸：
   脚本在没人填的时候填默认值＝把"没决定"伪装成"决定过"，比不记更坏。
3. 绕过时记 `bypass`（谁授权、关到哪天、为什么），不许记成缺项——否则事后看不出是绕过还是忘了。

**Why（他原话，2026-10-02 连着三次纠正同一件事）**：
- 「**音频这个问题这个不要设置成硬规则，这个需要按需要调整的**」——我把可灵 `enable_audio` 默认 true
  写成"要么显式关掉、要么…"的规定口吻。
- 「**我们这个框架，这些参数应该是前期由工作流对用户提问来确定的吧？**」——点出更深一层：
  值不该住在规则里，该在运行时问。
- 「**优先复查一遍，把应该人定的全部交给人类，不能由机器定，比如审美，画风这种机器不擅长的和人类主观意图的，
  这些全都需要先对用户提问，再定**」。
根源同他 09-27 那条：「不能认定一个规则定死，不然中途出偏移不知道哪里的原因」——**他要的是可归因，
一次被写死的取值就把变量从台账里抹掉了**。

**How to apply**：
1. **G10 审美写成必填槽表，历史口味只作"候选答案"呈现**（他 10-02 选的就是这档）：
   "清冷靠素／排斥好莱坞模板"这类偏好**不被引用就不生效**，新项目开工先答一轮槽。
2. **改稿授权改成对称**：补词与删词都**不许静默执行**，一律先给 diff＋一句理由再动
   （旧规则"删要授权、补不要授权"已作废；单向保护会让机器把用户故意不写的东西补回去）。
3. **有代价的兜底最后一步必须停下来问**：画风翻盘的前两档（正向句加码、换同画风参考图）可自动走，
   第三档"取消锚点"代价＝配饰会丢 ⇒ `[人]`。
4. 判据式问法：动笔写规则前先问自己"**这一格两种选法都合理吗？**" 是 → 只做留痕与槽声明；
   只有机械事实（尺寸是不是 32 倍数、锚图在不在盘上、角色有没有挂脸锚）才允许写成 `[拦]`。
5. 机器不擅长的维度别装能判：画风像不像、质感对不对、好不好看——G4-08 已定"机器在这维是瞎的"，
   挑图只做机械筛查，结果由他报号（见 [[feedback-i-am-not-the-beauty-judge]]）。
