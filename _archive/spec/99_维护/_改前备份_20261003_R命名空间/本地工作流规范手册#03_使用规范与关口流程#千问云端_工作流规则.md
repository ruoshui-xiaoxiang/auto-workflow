> **适用**：**千问云端**通道——经 `qianwen` CLI 与 QianWen Skills Hub（`qianwen skills search / install / pack-install`）

## 五、已知缺口：机器还不认这条通道

`check_preflight.py` 的 `channel_of(kind, provider)`（`:558`）目前只归出 **`h3 / cloud / image` 三条**，
`FMT_CHANNEL`（`:113`）也只有 `h3_skeleton / h3_ref2va → h3`、`sd_tenblock → cloud`、`plain → image`。

⇒ **后果（09-28 同日复核时把这段的因果改对了，初稿写错，见冲突表 风险 28）**：
`channel_of()` 的兜底是 `else "h3"`（`:573`）——只有 `provider ∈ {ark, cloud}` 或
`kind ∈ {cloud, sd, seedance, ark, kling, vidu, hailuo}` 才归 `cloud`。所以千问稿**默认落进 `h3` 通道**，
然后 `detect_format()` 按内容认格式，两条路都是**拦死**：

| 千问稿写成什么 | `fmt` | 命中分支 | 结果 |
|---|---|---|---|
| 普通文本（通义/千问 skill 常见形态，无 H3 指纹、无中文块名） | `plain` | `:674` | **error**「本地 H3 视频提示词认不出格式：既无官方三字段也无六段指纹」 |
| 套了中文十块（SkillHub 上若干 `@bailian/*` 模板就是分块写法） | `sd_tenblock` | `:668` | **error**「混用：中文十块出现在本地 H3 视频提示词里」 |
| 有人显式 `--channel cloud` 且写成十块 | `sd_tenblock` | `_g7_tenblock` | 按**云端 SD** 判据放行/拦（缺核心五块 error、器材名词按 `cloud` 降 warn）——**这才是"拿别的通道的实测替千问做决定"** |

⇒ 结论没变、但理由要改对：**不是"悄悄按云端判"，而是默认被 H3 判据 error 拦死**；
只有手工声明 `--channel cloud` 时才会发生跨通道套用判据。两种都不是本裁定要的状态。

**处置（有意暂不改代码）**：新增第四通道 `qianwen` 需要一条**可判的格式契约**才能落地，
而 §三 记录本通道实测为零。为一个还没跑过的通道建机检分支＝只建机器不出交付物
（冲突表 风险 21 与"completed ≠ confirmed"同族）。因此本条先登记为 **风险 28**，
并在开工 checklist 里加一条动作：**真要走千问云端出片前，先补一次同帧实测，再动 `channel_of()`。**

在那之前的临时口径（可用、且不伪造判据）：千问通道的稿子**不过 `preflight` 的 G7**，
只走共性坑以外的其余关口；如需机检，用 `--channel image` 会误标，**别用**，宁可人工过一遍并留痕。
