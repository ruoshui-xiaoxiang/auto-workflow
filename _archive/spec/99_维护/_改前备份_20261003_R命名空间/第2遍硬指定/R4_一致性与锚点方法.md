## R4-01 指定角色必须先有真实参考图，再写提示词

**判据**：生成或锁定某一**具体角色**的任何图（首帧／定妆／角色镜），输入顺序固定为
`角色参考图 → 素材职责句 → 动作/场景/光影/风格句`。纯文字只能锁骨相方向，锁不住那张脸的身份。

**机制**：文字锚定的有效面是服装／配饰／发型／骨相走向；五官身份是**图像信号**，无图像输入时无来源。

**出处**：`08\feedback-character-reference-image.md` 首条（2026-09-12《哑女·废土》两版纯文字后被用户指出漏带参考图）；
`04\character-anchoring.md` 锚定规则第 1 条。

**执行者**：`[拦]` `check_preflight.py: g7b_character_needing_anchor` —— 提示词点名了角色、却没挂任何参考图即拒提交。
生效名单来自 `05\engine_config.yaml: characters_needing_anchor`。
⚠ 该名单是**项目值**（现指向上一个项目的角色），见 `30_项目层\…\真源指针.md` 的 T3 风险登记。
⚠ 且 `auto_draft / character_sheet / image_draft_batch / previz_control` 四条图片链的 gate 步骤写 `characters: none`，
**把这条硬闸手工解除了**（登记在 `R_\作用域与例外登记表.md`）。

**槽**：`身份锚清单` ＝ 本项目哪些角色算"指定角色"（进 `characters_needing_anchor`）＋ 各自的脸锚文件路径。

**边界（同条自我限定，别用过头）**：做**全新脸**探索时优先纯文字——实测同骨相文字下"挂脸锚 vs 不挂"差异很小，
而挂别人已有的角色脸会带版权牵连。⇒ 本条适用于"**复现已定角色**"，不适用于"**设计新角色**"。
出处：同上文件「挂脸锚 vs 纯文字靶」（2026-09-16）。

## R4-02 锚点按职责拆分，五类不许混用

**判据**：一个锚点只承担一类信息，五种职责互不替代：

| 职责 | 只给 | 常见误用后果 |
|---|---|---|
| **脸锚** `face` | 面容骨相身份 | 挂整张立绘 → 服装/姿态/背景一起被继承 |
| **造型锚** `costume` | 服装款式、装饰密度、配色 | 挂派生物 → 掉质感（见 R4-04） |
| **道具锚** `prop` | 单件随身物的样式/颜色/材质 | 不单独裁 → 换装批次里该道具整批丢失 |
| **场景锚** `scene` | 站位布局、空间关系 | 职责句写宽 → 面孔被场景图带跑 |
| **风格锚** `style` | 渲染质感、影调、媒介感 | 挂派生图 → 整批逐代漂成卡通 |

**机制**：模型从图里继承什么，**由图里有什么决定，文字压不住**。切掉＝不提供。

**出处**：`08\feedback-character-reference-image.md`「双锚拆分」「六宫格设定表」「参考图会连姿态一起带」三条；
`04\character-anchoring.md`「脸锚、造型锚、道具锚不混用」。

**执行者**：`[报]` `check_preflight.py: g3_identity` + sidecar（见 R4-06）；脸锚尺寸量测见 R4-05。
职责句本身是否写窄＝`[人]`，由 **H2 锚点选定** 关口触发人审（⚠ H2 尚未接进引擎，见 `G5`）。

**槽**：`锚点清单` ＝ 本项目每个槽位挂哪个文件、`role` 是什么。

## R4-03 裁切范围就是职责边界；整幅图＝整幅构图

**判据**：需要限定锚点继承范围时，**用裁切来限定，不要靠免责句**。
需要姿态自由 → 裁到脸/上半身；需要保住配饰 → 那块必须留在框内；
**不想要锚点里的某个显眼具体物件 → 把它裁出画框，而不是再加一条禁令。**

**机制（两层，都要记住）**：
1. 职责句能挡住**抽象属性**（排版、多视图、景别、面容归属），**挡不住锚图里一个显眼的具体物件**。
   实测：原画稿里人物本身穿金属披膊，写"不要肩甲／披膊／胸甲／鳞甲／护臂"→ 六张里五张肩上仍有甲片。
2. 整幅参考图做 i2i 会**把机位一起锁死**。实测：给造型锚＋写明「只取造型，不要它的构图/云层/机位」，
   四段派生**全部沿用锚点构图**，太空与地面根本没出来——`do NOT take` 无效。

**出处**：`08\feedback-character-reference-image.md`「连原始风格锚自己画里的具体物件也会漏」（2026-09-25）、
「造型锚 ≠ 首帧来源」（2026-09-24）、「参考图会连姿态一起带」（2026-09-13 即梦 A/B 三版对照）。

**执行者**：`[人]` + `[报]`。裁切由人选，`[报]` 只能提示"锚点里可能有你不要的东西"（如检出人脸／检出武器），不能替代判断。
⇒ 落 **H2 锚点选定** 人审。

**推论（禁句）**：**免责句本身就是点名**。写「若参考图里有 X 则不采用 X」＝把 X 又喂了一遍。
出处：`08\…character-reference-image.md` 末段（`jm_9862` 整表带烧录标签＋露刃金属矛那例）；
同 `02\现行合并版` §六 法条 R5。⇒ 职责句只写**正向取用**。

## R4-04 风格／质感锚只能挂原始素材，挂派生物＝二手锚链逐代掉质感

**判据**：画风／影调／媒介感的锚**永远挂用户给的那张原图，或你自己从零生成的风格基准图**。
派生图（从成片抽帧、从锚图再裁、超分/修脸产物）只配当**脸锚／道具锚**这类窄职责锚。

**机制**：风格信息不在"脸"里，在"那张原始素材的渲染质感"里；不挂它，**没有任何输入能承载它，文字补不回来**
（实测写"不要平涂／不要厚描边／不要赛璐璐"全部无效）。派生每过一道手掉一档，且退化是**渐进的**，
往往到第三批才察觉，此时已隔两代。

**归因顺序（用户说"画风漂了"时按这个查，别先改措辞）**：
① 多锚**颜色冲突** → ② **渲染词错位** → ③ **锚链是第几手** → ④ 锚图本身有问题。

**出处**：`08\feedback-character-reference-image.md`「风格锚只能用原始素材」（2026-09-25，一条批次返工换来）＋
同文件「画风漂了不一定是锚链二手」（同日补充，给出 ①② 两个更常的首因）。

**执行者**：`[人]`（机器判不了"像不像同一画风"，见 R4-08）。
③④ 可半自动：sidecar 里记 `source` 字段（见 R4-06），`check_layers.py` 可查出"被声明为 style 的锚，其 source 是不是某个派生文件"。

**两个具体禁项（实测）**：
- **GFPGAN／CodeFormer 修过脸的图绝不能当脸锚**——它们会"补"五官细节，身份必漂。要提清晰度用 Real-ESRGAN（只放大不改内容），
  但**更干净的做法是用出造型锚的同款工具重出一张脸锚**（同只手画的风格不打折）。
- **超分在链条里的位置**：超分在前、修脸永远最后（见 `G1`）。

**槽**：`风格基准图` ＝ 本项目那张"原始"素材是谁、放在哪；以及全片统一的基调句（逐字复用，见 `G2`）。

## R4-05 能不能当脸锚，先量有效像素再判

**判据**：**先量再挂**。整图分辨率与"脸能不能用"无关，要看**脸框的有效像素**。
经验线 **~300 px**；⚠ **这是启发式，不是硬界，报数必须带限定词**。

| 实测点 | 结论 |
|---|---|
| 脸 **189 px**（真脸锚） | 仍保住身份 |
| 脸 **128 px** | 偏弱 |
| 脸 **80×94 px**（六宫格设定表主视图）／ **102×100**（头像格） | **不能当脸锚** |
| 脸 **370×540**（目标片特写帧） | 达标 |
| 脸 **180×220**（同片中景帧） | 偏弱 |
| 脸 **445×631**／**536×866**（关 UI 重拍拉近后） | 很好用 |
| 造型锚脸 **33 px** | **正常设计**，不是缺陷 |

**判"整图很清楚但用不了"**：人物整人只占画面约 1100 px 高时，脸实际只有约 130×155 px ⇒ 当不了脸锚，**放大也补不回来**。

**解法不是提高分辨率，是拉近 + 关掉界面元素**（要跟用户说清"不是不清楚，是人物太小"）。
实测：重拍 28 张（关 UI + 推近）后最大脸从 ~155 px 涨到 631 px。

**量脸工具**：`cv2.FaceDetectorYN`（YuNet）。⚠ 本机 `cv2 5.0.0` **无 `haarcascade_frontalface_default.xml`**，
`CascadeClassifier` 是空的。测量要用带 insightface 的那个 Python（见 `G6`）。

**出处**：`08\feedback-character-reference-image.md`「锚点的人脸像素下限」＋「~300px 是启发式」（2026-09-16／09-20 复核）；
`08\reference-ffmpeg-location.md`「cv2 5.0 无 haarcascade → 量脸用 FaceDetectorYN」。

**执行者**：`[报]` `check_preflight.py: g3_identity`，常量 `FACE_MIN_PX = 300`。
⚠ **只对 `role=face` 的槽报"偏小"**——`role` 取自 sidecar；没 sidecar 的槽只能报"机器判不了、需人工核对"，
**不许为了让闸通过而瞎猜标签**。

**槽**：无（本条是全项目通则）。但"本项目每个角色的脸锚分别是哪张、量出来多少 px"属项目层。

## R4-06 每个锚点配同名 sidecar，让机器核对槽位而不是靠人记

**判据**：锚点图旁放 `<图名>.anchor.json`：

```json
{ "character": "…",            // 这张图是谁；场景/风格锚填 null
  "role": "face|costume|prop|scene|style",
  "source": "原片 9.30s 裁切",  // 第几手，R4-04 靠它
```

## R4-07 多锚颜色冲突是"画风翻盘"的首因

**判据**：脸锚与造型锚**可见服装颜色必须一致**，否则模型同时收到两个颜色信号，
而"三处一致的那一方"（两个锚 + 文字）会赢，另一张锚的整张调色板被压掉。

**检测**：所有锚点过 arcface 量脸的同时**目视一眼衣领/肩部颜色**——脱锚脚本不量色，机器查不出。
**正解优先级**：① 直接从造型锚同色系里单独裁一张当脸锚；② 用出造型锚的同一工具重出一张脸锚；
③ 超分只兜底（见 R4-04 禁项）。

**第二种漂源＝渲染词错位**：给"3D 半写实国漫插画"风格写"35mm 定焦质感／细颗粒／无镜头光晕／次表面散射"，
会被推向"游戏 CG／武侠手游立绘"。同一条"半写实"在两套词库下读法不同。
**正解：删干净摄影/电影质感词，只留一句"渲染风格完全按第 N 张参考图"，让锚图自己说话。**

**判"是插画还是摄影 CG"的三条目视尺子**：皮肤（次表面散射 vs 平涂塑料）／衣褶（垂坠 vs 硬切）／明暗过渡（柔长 vs 硬边界）。

**出处**：`08\feedback-character-reference-image.md`「画风漂了不一定是锚链二手——多锚颜色冲突 + 渲染词错位」（2026-09-25，dz0b' 三张产物机器自检全过、用户一眼打回）。

**执行者**：`[人]`（或带视觉的模型）。⇒ 与 R4-08 绑定执行。

**槽**：`调色板一致性表` ＝ 本项目"脸锚该穿什么颜色 / 造型锚主色"对照。

## R4-08 视觉 QC 与机器 QC 同等必要；机器层在"画风"这一维是瞎的

**判据**：**机器层全过 ≠ 画面没漂**。出图批次提交前必须挑 1–2 张**亲自看图**（人，或带视觉的模型）。
机器判得了：脸对不对、字干不干净、水印在不在、颜色分布。机器判不了：**画风像不像、质感对不对**。

**出处**：同上（ArcFace 0.56/0.60/0.60、水印干净、SCRFD ≥0.7，机器全过；用户一句"这怎么画风都变了"整批打回）。
同族：`04\script-and-qc.md`「所有小样都交用户审，非只审标红项」；`08\feedback-evidence-loop-trap.md`「裁判打分只能说 completed、人审过才 confirmed」。

**执行者**：`[人]` ⇒ 落 **H4 看片挑号**／出图批次呈审（`make_review_sheet.py` 生成编号静帧表 + 并排短片）。

## R4-09 道具／服装／场景的状态锁必须带剧情作用域

**判据**：任何"锁某物当前状态"的句子，**写的时候必须带上它锁的是哪一段剧情**。跨段复用时先问"这个东西在故事里变了没有"。

**为什么这是通用条而不是项目条**：它不含任何项目名词，只规定"必须写作用域"这一形式。

**机制／反例**：把某项目"裹布阶段"的道具禁词与封口锁当成全片纪律，会与后续"亮枪/不裹布"那段**正面冲突**——
等于用词表闸改写剧情；而不标作用域，下一个接手的人（或工具）会以为"这项目不许出现枪"。

**道具锁的最低内容**：`形态数量不变` + `尺度线索` + `封口描述` + `不露本体`（若该段设定为遮蔽）。
只锁"形态数量"不够：镜内出现"尖端朝镜头 + 手部特写"时尺度线索消失，模型按**小物体**重解释，道具会变形。

**同一物体的两个部件要拆成两件事各写各的**（例：背某物的**带子**与该物本身的**包裹层**是两件东西，
合写会互相污染：一条把带子画成从物上拖到地的白长条，看着像包裹层散开 → 顶到"全程不拆开"）。

**出处**：`02\H3提示词规则_现行合并版` §十 作用域表、§二 不变量层（尺度、两部件拆分两条）；
`R_\作用域与例外登记表.md` 会逐项目登记谁收窄了本条。

**执行者**：`[人]` 为主；形式校验可 `[报]`（句子是否含"第 X 章／段 Y"这类作用域标记）——⚠ **目前无脚本做此校验，本条暂为 `[人]`**。

**槽**：`作用域段表` ＝ 本项目分几段、每段该物的状态是什么（这是项目层最要紧的一张表）。

## R4-10 "换装不换人"＝脸锚 + 道具锚两张互不重叠的窄裁切，一起挂

**判据**：要让角色换发型／换服装／换时代，但**脸和随身道具不变**：
**不要挂整张定妆图**（整图会把原服装一起带过去，实测一批造型全被拽回同一个样子）。
正确做法＝从定妆图裁出**两张互不重叠的窄锚**：① 脸锚（脸 + 颈，切掉领口以下）；② 道具锚（那件随身物的局部特写），一起挂，
职责句分别写明"唯一面容依据"与"样式颜色材质完全一致、只有挂法随本镜服装与时代变化"，
再加一句「发型、发饰与服装全部按下文重新设计，不得继承参考图的发式与服饰」。

**实测**：12 款跨现代／民国／唐风／仙侠／武侠／港风／科幻／蒸汽朋克，**脸都认得出、道具全在、没有一款被拽回原古装**。
⇒ 本条是本层里**少数带明确通过率证据**的组合拳（12/12）。

**裁切操作口径**：裁切框按脸心定量，左右各取 **1.35 倍脸宽**；锚图里**绝不能留武器**。

**出处**：`08\feedback-character-reference-image.md`「双锚拆分（2026-09-15 实测有效 12/12）」；
`08\reference-local-face-identity-transfer.md`「第十条」裁切口径。

**执行者**：`[人]`（裁哪两块由人定）＋ `[报]` `g2_md5_slots`（两张锚误取同一区域时 md5 会撞，当场拦）。

**推论**：**重要随身物必须单独裁一张道具锚**——缺道具锚时该物会整批丢失。
（同族教训：用户说"XX 不在／也没有"时，默认按**漏写**处理、补进去；要删必须用户明确说"不要了"。）

## R4-11 借第三方／版权素材＝借设计语言，不借脸

**判据两条铁律**：
1. **绝不把整张截图／立绘挂上去**——先裁**无脸窄裁切锚**。另：抽帧含写实人脸会被云端真人检测拦，也要先裁掉脸。
2. **职责句写"重新设计"而不是"采用"**。✅「参考图只提供这套服装的**材质语言与配色母题**（…），
   **款式、剪裁与配饰全部按下文重新设计**；不采用参考图中的人物长相、姿态、场景、镜头与界面元素」。
   ❌「采用参考图中的服装」＝1:1 复刻。
   ⇒ **"重新设计"这四个字就是借鉴与抄袭的分界**，产物归属也是两回事。

**版权线**：设计语言（材质／配色／造型母题）可借，**脸不可借**。
产物分「内部审美打样／对照」与「要发布」两种用途——内部可以，发布不行。
被用户主动问到版权时**如实说、不回避也不说教**。

**另**：**别照抄参考图的发色**等高辨识度字段。逐字段问一句"这是参考图的特征，还是这个新角色该有的特征"；
一个批次里要有意拉开色系，否则出来的只是同一张脸换角度。
**眼镜这类"上庭精密小物件"是通用配饰、不构成角色识别**（真正要躲的是"脸 + 这套衣服 + 这副眼镜"三件套同时复现）。

**出处**：`08\feedback-character-reference-image.md`「借设计语言≠复制角色」（2026-09-16 已跑通）、「别照抄参考图的发色」、「上庭精密小物件是结构性必需品」；
`08\feedback-cross-shot-continuity.md`「抽帧含写实人脸会被真人检测拦」。

**执行者**：`[拦]`（写实人脸输入的云端拦截：`InputImageSensitiveContentDetected.PrivacyInformation`，属外部闸非本机闸）＋ `[人]`（职责句措辞）。

## R4-12 构图与身份分属两条管线，别指望一张参考图同时办成

**判据**：**线稿／宫格喂云端 i2i，只被读成语义、不被读成几何。**
实测（同一镜同一提示词三组对照）：线稿明确画着"A 垂在身侧、B 单独悬在半空、两者之间一段空白"，
出图一律变成"A 举起、B 被 A 抵住"——模型读成"这里有个持物的人、一道光"，不是构图约束。
宫格比"分挂两张"更差（距离塌得更狠），但宫格**不会**被画成分格拼贴这点是干净的。

**真要按线稿的形走 → 用 ControlNet lineart，不是挂参考图**
（本机实测边缘覆盖：**lineart 73%** vs **纯提示词 15.6%** vs Seedream i2i 45.5% vs depth ≈37.8%）。
但 **lineart 锁不住脸**（本地 Redux 身份相似度封顶 **0.42/0.49**）⇒ **构图与脸是两条管线**。

**便宜的正解**：需要锁构图时，先想**能不能把冲突元素拆到不同镜**（打戏的做法就是把施术者从命中镜里整个拿掉），这比加锚便宜。

**纪律**：构图线稿留作**给我们自己看的动作分解表**和评审沟通物，不当控制信号；
要画就用代码画（数值定死站位），零成本可复改。

**出处**：`08\feedback-character-reference-image.md`「线稿／宫格当参考图喂云端 i2i」（2026-09-21 花钱实测，"别试第二遍"）；
`04\previz-control-referee.md` 边缘覆盖率；`08\feedback-local-first-generation.md` Redux 封顶。

**执行者**：`[人]`（选型决策）。机器层：`[报]` 可查"该镜是否同时要求了锁几何与锁脸却只给了参考图"——⚠ **目前无此脚本**。

## R4-13 跨镜承接靠图像，不靠文字；首帧不许与第一拍冲突

**判据**：
- 跨镜一致性**只在首帧层锁**，不在文字层重复描述场景（文字与锚图会打架）。
- 优先抽**上一镜成片的末帧**当本镜首帧（硬几何锚）；代价是**一镜内的缺陷会沿整条链往下传**。
- **重渲某段 → 凡首帧抽自该段末帧的后继段必须一起重渲**（把"上游末帧 vs 下游首帧"拼左右对照先自查）。
- **改任何一镜【事件脚本】的第一拍（或最后一拍）之前，先把那张首帧调出来对一遍"图里的人正在做哪一拍"**。
  首帧画的是本镜的**末态** ⇒ 这条镜**直接不可渲**——这是花钱前就能免费发现的缺陷。
- 场景一致性要抽成"场景锚定段"**逐镜一字带上**，光影分层写（近暗／中亮／远雾化）。
- **跨镜道具从上一镜成片抽帧当 reference_image 锁形，提示词必须跟成片实际样子走**（不是你记忆里样子）。

**出处**：`02\H3提示词规则_现行合并版` §二 末条；`08\feedback-cross-shot-continuity.md` 全篇；
`08\feedback-character-reference-image.md`「改起拍动作之前先看首帧画的是起态还是末态」（2026-09-27）；
`08\feedback-video-quality-standards.md`「场景一致性只在首帧层锁」「不冲突首帧」。

**执行者**：`[拦]` **管线闸**——凡手塞首帧，必须能追溯到本管线生成过的首帧提示词
（实测：一张旧时间戳的首帧绕过管线，直接把道具渲成裸杆头）；
`[人]` 末帧/首帧对照。⚠ **注意"上游末帧 vs 下游首帧"这一步没有机器闸**，靠人。

**双向性提醒**：通路连通要分方向且当场测——"首帧能承接"不等于"末帧能被正确抽出来喂下一条"。

## R4-14 脸检测的适用边界：报"判不了"之前先跑一次检测

**判据**：**"CG/风格化脸判分不可用"只对偏卡通的 CG 脸成立**，不是所有非写实脸。
实测点：游戏捏脸 SCRFD **0.877**、ArcFace **0.712**（可用）；偏卡通 CG 脸 SCRFD 检出 **0**（不可用）。

**并且：检脸数只触发检查，不等于事实。**
双人镜只检出一张，可能是漏检／遮挡／出画，也可能是真只有一个人；器物镜检出脸，可能是真新增人物，也可能是误检。
**必须打开画面确认**，不能把检测数直接当事实，也不能从"检脸零/低出"推断"画面里没有人"。

**出处**：`08\feedback-character-reference-image.md` 第八条／第九条限定（2026-09-25）；
`04\character-anchoring.md` 双人多人镜第 4 条；`04\previz-control-referee.md` 禁令。

**执行者**：`[报]`（检测本身）＋ `[人]`（结论）。

## R4-15 两条关于"失败结论"的防腐条款

**判据**：
1. **历史失败 ≠ 永久不可行。** 方法、模型、锚图或脸尺寸任一项改变后，旧结论需要**小样重验**；
   不许把"某个本地方法在某个风格化角色上测过不佳"写成"所有锁脸只能走云端"。
   也不许未经用户同意继续在已判定失败的路线上投入。
2. **判"这张锚够不够用"要按"这一镜需要什么"判。** 胸像／半身锚当脸锚很好，**当造型锚等于没有**——
   没有全身就没有身高比例、臂长、袍摆、"两件东西够不够得到"这类几何，模型每次现编，
   **这类几何约束无论怎么写、怎么画线稿都锁不住**（实测）。接动作／双人全身戏之前先问"锚点有没有全身"。

**出处**：`04\character-anchoring.md`「路线选择与局部证据」；
`08\feedback-character-reference-image.md`「胸像定妆是结构性缺口」（2026-09-21，《烬骨辞》两张脸锚 1584×2816、锁脸 0.922 却仍缺全身）。

**执行者**：`[人]`。⇒ 落 **H2 锚点选定**：本项目要出全身动作戏时，H2 必须检查"有无全身造型锚"。

## R4-16 同镜内画风统一；锚点风格与目标画风不一致时必须声明

## R4-17 两套元数据档各有字段表：身份卡（图级）与资产档（资产级）

**为什么现在必须立**：批 3 已经把东西做出来了——`.anchor.json` 13 份、`<ID>_asset.json` 10 份，
但**没有一个地方规定过它们允许哪些字段、哪些值**。实测后果已经摆在盘上：
资产档里 `class` 出现的是 `vehicle/scene/prop/layout` 四个值，
**`character` 和 `lora` 这两个显然该在的值一次都没出现过**，而它们是不是合法值谁也说不清。
⇒ 再往下铺（约 1,000 张待立档）等于在字段表没定的情况下写 1,000 份，必然重演
本轮 sidecar 那出——为了统一两套同义字段名（`role` vs `anchor_kind`）做了一次全量强制迁移。
**现在只有 10 份，是定表成本最低的时刻。**

⚠ **本表取值一律以盘上实测为准**，我新提的另立一栏标「新立·待认」——不许把设计意图写成既成事实。

### 一、身份卡 `X.png.anchor.json`（图级：这张图是谁、锁什么）

| 字段 | 合法取值 | 实测现状 | 出处／状态 |
|---|---|---|---|
| `character` | 角色名，或 `null`（场景／风格锚） | 11/13 份有 | 本条原四字段约定（09-20 起） |
| `role` | `face`／`costume`／`prop`／`scene`／`style`／`layout` | 实见 face 5、costume 4、prop 2、scene 1、style 1；**`layout` 0 次** | 枚举来自 R4-06-v2；`layout` 是为站位锚补的（见 R4-18） |
| `source` | 自由文本，但**必须写"第几手"**（原片裁切／几倍放大／谁衍生） | 3/13 | R4-04 靠它判二手链衰减 |
| `source_model` | 底模 ID 字面值 | 身份卡里 **0 份**；D 盘 tmp 41 份里有 6 份，全是 `doubao-seedream-4-0-250828` | **新立·待认**（依据＝它已实测是脸层唯一杠杆之一） |
| `lock`／`unlock` | **短句数组，每项一个可核对的职责**；⚠ **不许把证据塞进项里** | 身份卡 0 份；tmp 里是 `"不锁机位不锁构图——实测挂整幅锚点做 i2i 会锁死机位"` 这种**断言＋理由混写** | **新立·待认**，且带下列拆分规则 |
| `unlock_why` | 自由文本，装上面那句里"——"之后的实测理由 | 0 份 | **新立·待认**（拆分是为让 `unlock` 能被机器逐项核对，理由不该妨碍核对） |
| `style_baseline`／`style_offbaseline` | 布尔 | 各 4 份 | 09-27 画风离群裁定实践，本轮收编 |
| `role_was` | 一个 `role` 值（改判留痕，**原值不许丢**） | 4 份 | 实践在先，本轮收编 |
| `note` | 自由文本 | 3 份 | 原约定 |
| `asset_id` | 见 R4-18 的复合键 | 身份卡 0 份 | **新立·待认**：图级卡指向资产级档，两头才连得起来 |

**`lock`/`unlock` 的拆分规则（本条里最容易做错的一项，单独钉）**：
tmp 那批的写法信息量很足，但**核对不了**——机器要判"这张卡说锁了画风，实际提示词里有没有画风声明句"，
就得先把 `"剑阵造型与画风"` 这种自造短语对上受控维度。⇒ 规则：
**`lock`／`unlock` 每一项只能写"锁哪个维度"，维度取自 G4 已有点名过的这几类——
`身份/面容`、`服装`、`画风`、`特效形态`、`道具形态`、`尺度`、`颜色`、`机位`、`构图`、`场景布局`；
实测理由一律挪进 `unlock_why`。** 短语自造的（如"剑阵造型语言"）判**不合规**，不判"通过"。

### 二、资产档 `<资产ID>_asset.json`（资产级：这件资产的权威锚是哪几张）

### R4-17-v 视频件要不要进档：10-02 已裁「要进」，本轮只定字段表

**用户裁定**（问题 3）：视频**属于**资产档，但本轮**只把字段表定下来，不给存量建档**——
建档跟资产档铺开一起做（那是 GAP-A7 那条进度条），别和"结构闭合"混成一件事。

⚠ 现状如实（实测，出处＝`E:\\创作\\_资产总索引\assets_registry.json` 与项目资产目录）：
现存 **10 份档全是图片类**，视频**一份都没有**；存量那 24 个视频编号（S01–S13／T01–T11）
在档这一侧是空白。⇒ 下表**全部是「新立·待认」**，没有一份档用过这些字段，别当已落地引用。

| 字段 | 为什么要它（图片档那套为什么不够） | 取值口径 | 状态 |

| `model`／`provider` | "哪条通道出的"决定可复现性与判据归属；通道现由注册表管，档里只记结果 | 注册表 `channels[].id` 的字面值 | 新立·待认 |
| `seed` | ⚠ **有的通道不支持**（Seedance 实测不支持 seed），没支持要写 `null`＋理由，不许留空当"忘了" | 整数／`null`＋`seed_note` | 新立·待认 |
| `anchor_refs` | 视频由哪几张锚图生成——这是跨镜连续性唯一可追的线索 | 身份卡／资产 ID 列表，走 `项目/编号` | 新立·待认 |

## R4-18 资产编号：项目内唯一，跨项目一律用「项目/编号」复合键

**判据**：
1. 编号**项目内唯一**，不追求全库唯一（那要给 5,008 张图逐张重编号，不可能）。
2. ⇒ 任何跨项目引用**必须**写 `项目/编号` 复合键（落地见 `_资产总索引\assets_registry.json` 的
   `assets[].key`，形如 `仙女星系战争项目/SHIP-XURI-01`；人读的总表行首列也是它）。
   **裸编号在跨项目语境里是错的**，因为"A01"已经在两个项目里指两个东西。
3. 前缀含义见下表；**新前缀不许自己造**，要加得先改本表。
4. **状态图**（同一角色多个状态，如 A01/A02/A03）各占一号，但它们**是同一份资产档的三张锚**，
   不是三份资产档——资产档挂在角色这一级，状态号出现在 `views`/`canonical_anchors` 里。

| 前缀 | 含义（这句是规则） | 实测用例（这句是证据，出自项目层） |
|---|---|---|
| `A` | 角色状态图 | 武昭君仪（A01–A10） |
| `P` | 道具 | 武昭君仪（P01–P05） |
| `SC` | 场景 | 武昭君仪（SC01–SC08） |
| `ST` | 站位锚——**只锁布局不锁脸** | 武昭君仪（ST01）、仙女星系（ST-STANCE-01） |
| `S`／`T` | 视频片段 | 武昭君仪（S01–S13／T01–T11） |
| `C` | 镜号（实验件用，配 `.shots.json` 绑定记录） | 烬骨辞（C01–C05） |
| `SHIP-`／`STAR-`／`SCENE-`／`PROP-` | 语义式"类-专名-序" | 仙女星系（10 份档） |

5. 🆕 **新项目默认走语义式前缀**（`<类别>-<专名>-<序>`，如 `CHAR-XURI-01`／`SCENE-CANYON-01`）。
   **存量一律不重编号**——2026-10-02 用户裁定（问题 2 选「存量不动，新项目默认语义式」）：
   重编要动 40 多个在引用中的编号＋身份卡＋`.shots.json`＋资产档＋脚本常量，
   收益（人读不靠上下文）抵不过风险（改漏一处就是新死链）；
   跨项目歧义本来就由 `项目/编号` 复合键消掉（判据第 2 条），不靠统一风格。
   ⇒ 两套并存是**被裁定的过渡态**，会随存量淡出自然收敛，不是没人管。

⚠ **两套风格并存是事实**（现已裁为过渡态）：武昭君仪用"单字母＋两位序号"，
仙女星系用"类别词＋专名＋序号"。本条只规定了**唯一性作用域、复合键、不许自造前缀**这三件，
**统一到哪一套已裁**（10-02 问题 2）：存量不重编，**新项目默认语义式**（见判据第 5 条）。

⚠ **`ST` 为什么单列**：实测 ArcFace 0.297–0.301，撑不起身份判定 ⇒ 站位锚的身份声明一律 `layout`，
挂它只锁布局。**这一条在两个项目各自成立过，本轮才第一次写成通用规则。**

**执行者**：`[拦]` `build_asset_registry.py` 的自证第 3 条（复合键全表唯一，重复即索引生成失败）；
`[人]` 新立编号时是否合前缀表——**目前无脚本**，登记进下面的"待建校验"清单，不虚报。

**槽**：`<项目>` ＝`E:\创作` 下一级目录名；`<编号>` ＝项目内唯一串。
