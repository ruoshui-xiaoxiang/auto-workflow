# G5_关口与授权

本文件管两件事：**哪些东西机器会替你拦下来**（关口），以及**什么情况下 agent 可以自己往下走**（授权分级）。

⚠ **本文件按盘上实测写，不照抄任何文档声明。**
以前各处（含本层索引 §5 旧行）写的关口体系是「`G1–G12` ＋ `H1–H7`」，
实测对不上，而且**名实不符一旦成文就会被当成规则固化**，所以本文件的每一个编号都有出处可查：

| 声明 | 实测 | 差异 |
|---|---|---|
| `G1–G12` | `ALL_GATES` 实测**没有 G9、G10**，且 10-02 起多了一个 `G13`（现清单以代码为准，本行不抄计数） | **编号跳空**（不是漏实现就是编号错）＋**清单会长**：文字里那句「G1–G12」本身就已经是过期声明 |
| `H1–H7` | 17 份 yaml 里**只有 `H3`、`H4` 两个**人工关口 id | **H1／H2／H6／H7 零处存在**；`H5` 只活在文字里（见 R5-08） |

**权威方向：代码是事实，文档是声明。** 本层其余文件与本文件冲突时，以
`D:\AIWorkflow\tools\check_preflight.py` 的 `ALL_GATES` 与 yaml 的 `task: gate` 步为准，

## R5-10 通道未裁不等于通过，也不等于拦死

**判据**：`channel_of()` 遇到**非空且未登记**的 kind（例：`qianwen`／`jimeng`／打错字的

## R5-11 授权分级：批次授权只覆盖执行，不覆盖改规则

**判据**（元规则 M1 的落地，M1 见 `20_通用规范层\20_索引与分类判据.md` §2.0）：

| 档 | 覆盖 | 不覆盖 |
|---|---|---|
| **批次授权**（"后续你自主执行"） | 连续执行到批末、不必停在批次边界等"开跑" | **改本层规则**；改判定链默认行为；裁"未裁"项 |
| **人审同意** | 顶层规则修改生效（M1） | —— |
| **已裁** | 用户已明确裁过的项（如"暂时不改"） | **不得当成待审再问一遍，也不得借"自主执行"把它做掉** |

**未走完生效链的改动一律视为未生效**，引用时按改动前口径读。
每条改动都要能指出：怎么测的、样本量、口径边界、能否复跑；
**推理、类比、"看起来更规范"、外部方案的权威度都不算证据**。

**执行者**：`[人]`（授权由用户给，agent 不得代登记）。

## R5-13 运行决定单：值归人，机器只查「有没有人给过」，永不查值

| 路径怎么拼 | `engine/decision_sheet.py` 一处（根取自 `config.paths.creation_root`） | 引擎、扫描器、校验器都只调它 |
| **值本体** | `E:\创作\<项目>\_项目档案\运行决定单.json`（**只有人能填**） | G13 读，规则层不复述 |

⇒ 本层因此**不许出现任何具体取值**（"画幅用 9:16"这类）：写了就是第二份抄本，
将来单里改了，规则还替旧值说话。

**G13 的判据只有三条，全在留痕层**：① 必填槽每一个都得有人给过（**空槽即拦**）；
② 值的来路只能是 `sheet`（单里人填的）或 `args`（这批显式传的），出现第三种＝有代码在代填 ⇒ 拦；
③ 决定单本身读不出（缺／坏／项目未登记）⇒ 拦，不静默退成「这次没有必填槽」。
⚠ **本闸长不出一条"这个值看起来不合理"的判据**——机器在画风这一维是瞎的（R4-08 同源）。
想加值判据＝改顶层规则，必须走元规则 M1（事实证据＋用户点头），不是顺手写个 `if`。

**分界（10-02 用户原话划的，不由脚本猜）**：项目级＝开工填一次、运行期沿用
（改动只能"用户明确指定"或重填，**按批传参不算指定**）；运行级＝每批重新确认
（存进单里也不采用，否则就变成"沿用上次的"＝机器替这批做决定）。

**留痕的两条硬规矩**：① 改项目级槽要留**旧值＋新值＋时间＋by: human**，旧值不许被覆盖
（不然"这次为什么变了"无法复盘）；② 台账里这批的决定按**内容摘要**绑定
（`gate_key(project, workflow, G13, digest)`），提示词／参考图／尺寸一变 digest 就变，
上一批的值不会被这一批悄悄沿用——同人工关口那条规矩。

⚠ 一条实现层的坑写进规则，因为它是**裁定级**的：判"槽给没给"只看**在不在**，不能看真值。
`enable_audio=false` 被命令行 `auto_cast` 成 `False` 之后，写成"取真值判断"就把 false
当成没给 ⇒ 「不润色也要显式写 false」这条裁定会被静默吃掉，逼人写 true 才能过闸。
（钉在 `engine/tests/test_run_decisions.py::test_false_is_a_decision_not_an_empty_slot`。）

**"显式"这两个字是有牙齿的**（10-02 批 5-2 实测出来的洞）：`run.py` 的参数是
`args = yaml 默认 ∪ --set 覆盖`，合在一起之后**分不出哪个人动过**。
现役 `image_draft_batch.yaml` 的 args 里就写着 `use_llm_polish: false` ——
如果"参数里存在"算"人给过了"，那这批压根没做过任何润色决定也能过闸。
⇒ 规矩：`run.py` 另外记下**这批显式给过的键**（`ctx["explicit_args"]`，
= `--set` ∪ `--resume` 回放时人给过的值；这键同时进保留字表，防被同名步骤 id 顶掉），
G13 只认这份清单里的值。**yaml 的流级默认值不算这批的决定**，撞上就 error 并提示本批补给。
裸 CLI 自审没有这份清单 ⇒ 降级为"存在就算给"，但**必须 warn 出来**，不许静默
（`explicit_marker: absent`）。

**同一个决定在现役流里有两个键名**：润色＝`use_llm_polish`（4 份流）与 `use_llm`（1 份流）。
现状登记在 `channels_registry.run_slots[].accepts`，不替谁改名——
改名要动 5 份现役流＋webui 白名单＋测试，属改行为，**等人裁**。三条规矩：
① 别名与正名**任一**给了都算人给过，台账里存正名；
② 两个写法同时给了且值不一致 ⇒ **报错**，不静默挑一个；
③ 别名必须真是某份 workflow 里存在的参数名，`check_registry.py` [G] 抓到死别名即 error
（登记一条没人用的别名＝把名字分叉藏进表里）。

**免终端那条路也得能填**：`webui.py` 的表单/提交白名单**从注册表现推**这三个运行级槽
（不在 webui 里再抄一份槽名清单），进高级参数区且**永不预填**；
`selftest` 类流不加（自测不该被决定单绑住）。

**执行者**：`[拦]`（G13 error 即拒绝提交生成）＋`[人]`（值本身、以及"要不要改项目级槽"）。
**槽**：`决定单路径根`（config 的 `paths.creation_root`）、`必填槽清单`（注册表 run_slots）。

## R5-14 阈值必须有声明面，注册表里不许抄值（10-02 批 7-2 立）

**判据**：凡"拦人的数"（分辨率倍数、帧率、槽上限、响度目标、判分达标线、扫描上限…）
都必须能在 **`D:\AIWorkflow\engine\thresholds_registry.json`** 里找到一条，
每条写清四件事：**谁定的**（`decided_by`）、**管到哪**（`scope`：通用／通道／项目标定）、
**住在哪几处**（`places`，每处带读法 `kind`）、**有没有真在生效**（`enforced`）。

⇒ 关键约束：**表里不写值**。值一律由 `D:\AIWorkflow\tools\check_thresholds.py` 现读。
在本层任何文档里复述一个具体阈值＝造出第二份抄本，这条与 R5-13 那句"规则不复述值"是同一条线。

三种 `role` 的语义（这件校验器唯一会报 error 的地方）：
`authority` 说了算的那处；`mirror` 必须与它相等的复刻，**不等即 error**；
`reference_only` 只是旁证（实测带、记忆里的经验值），**不参与相等比对**但会被打印——
因为"目标 −16 LUFS"与"实测成品 −17 dB"这种混读，正是查出来过的真错。

`enforced=false` 是**合法状态**而不是缺陷（例：音频上限从未校验＝R10；qc 的绝对带按 10-02 裁定不接进引擎），
但必须**显式标出**——挂着数又不说没生效，比没数更坏。

**执行者**：`[报]`（校验器默认只报不拦，`--strict` 才有非零退出；扫描器把它派生成 `engine.thresholds`，
读出问题就报 `GAP-E7`）。为什么不做成 `[拦]`：阈值不一致**不代表这次出片会错**，
拦下来只会逼人绕闸；它的正确用法是改完必跑。
**槽**：`校验器清单`（第五件）／`阈值声明面`（这张表）。
**出处**：`D:\AIWorkflow\engine\thresholds_registry.json`、`D:\AIWorkflow\tools\check_thresholds.py`、
`D:\AIWorkflow\engine\tests\test_thresholds.py`（含两条反向验证：mirror 不等必须红、读法失效必须红）。

## R5-15 产物侧机检不是跑前自审：它按裁定只接了一把尺，关掉同样要留字据（10-03 批 7-4 立）

实测现状（不是约定，是 10-03 接线后的盘）：

| 面 | 落点 |
|---|---|
| 尺子 | `D:\AIWorkflow\tools\qc_batch_consistency.py`（批内 DINO 两两余弦） |
| 接线 | `engine\tasks.py` 的出图步 `t_comfyui`（产物过完"尺寸／纯色"两道之后） |
| 拦与放 | 最低 <0.75 **停批**；均值 <0.80 **只警示**；量不了 **记 `not_measured`** |
| 阈值权威 | 就在那两行常量；`thresholds_registry.json` 的 `qc_batch_dino_floor`／`qc_batch_dino_mean_warn` 记指针（`enforced: true`） |
| 开关 | `config.yaml` 的 `qc.batch_consistency`（默认 on），关 → 台账 `bypassed` 段留字据 |

**执行者**：`[拦]`＋`[报]` 两档同时用——最低线（<0.75）命中即停本步；均值线与"量不了"只写日志＋
本步返回值 `batch_qc`。最终"进不进片"仍是 `[人]`（H3／H4，见 R5-04），本条**不许被读成机检放行**。

三条规矩的来历，引用时必须带上：

1. **为什么只接这一把**：用户 10-02 批 6 问 4 裁「只接相对尺，绝对带只报不拦」。
   绝对带（`faceL`／`faceWhite`／`lpalex`／`gedge`／`faceHR`）是在**一个项目的 12 张人判样本**上标定的，
   10-02 实测拿去测另一个项目的未打回基线稿 ⇒ 3/3 全 FAIL。把它们接进引擎＝拿别的项目的尺子量本项目。
   `test_batch_qc_wiring.py::test_absolute_bands_are_not_wired_into_the_engine` 钉住"没偷偷接"。
2. **量不了 ≠ 通过**：这张尺的取法按脸归一，产物没脸就量不了（10-03 回放 18 个真批次：**13 个 not_measured**）。
   引擎必须写 `not_measured` 并进本步返回值 `batch_qc`，**任何一层都不许把它读成 ok**。
   环境缺依赖／模型不在也走这条，不抛错——一批 GPU 时间不该为量尺作废，但静默失效的裁判比没裁判更危险。
3. **过尺 ≠ 进片**：它只答"同批互相像不像"。10-03 实测人判打回的三批里它只抓到"画风漂"那批
   （0.770/0.728 → FAIL），"变白"（0.853/0.817）与"偏卡通"（0.846/0.824）**都过**。
   **必要不充分**；进片判定仍在 H3／H4 人工关口与人的眼睛那里（R5-04）。

写这条时顺手更正一句假话：`GAP-G3` 旧文本称标定原稿 `tmp/wzy/qc.py` "在未接线清单里"——
候选面只从 `tools\` 取 `.py`，那份从来不在候选表里。**结论对、证据链错**，已就地更正。
