### 3.1 模板清单与占位符（实测 13 份 json 在 `engine\comfy\`）

`draft_flux_api.json`／`draft_sdxl_api.json`／`draft_sd15_api.json`／`draft_upscale_api.json`／
`refine_usdu_api.json`／`flux_i2i_api.json`／`flux_inpaint_api.json`／`flux_outpaint_api.json`／
`flux_controlnet_lineart_api.json`／`flux_controlnet_depth_api.json`／`flux_redux_ref_api.json`／
`flux_cn_redux_api.json`／`sdxl_faceid_ref_api.json`

`tasks.py:build_graph_control()`（:1277）替换的键 ← 本轮 grep 实读：
`__GUIDANCE__`（:1298，默认 3.5）、`__DENOISE__`（:1304，默认 1.0）、`__GROW__`（:1305，默认 6）、
`__PAD_L__/__PAD_T__/__PAD_R__/__PAD_B__`（:1306 起，默认 0）、`__FEATHER__`（:1310，默认 40）、
`__DEPTH_RES__`（:1311，默认 1024）；`build_graph()` 侧另有 `__GUIDANCE__`（:386）。
`walk` 只替换**整值恰好等于占位符**的字符串 ⇒ 模板里写 `"__PAD_L__"` 才会被换，写在长句里不会。

⚠ **两个踩过的坑（都还在代码注释里）**：
1. `__GUIDANCE__` 原先不在 control 的替换表里（既有 lineart 模板把 guidance 写死 3.5 所以没暴露），
   不补会报 `Failed to convert an input value to a FLOAT value: guidance`。
2. **取数值参数别用 `or` 吃默认**——`pad_l=0` 会被 `or` 判成假值而换成默认值。
   这就是 `_pnum`／`_pint`（:1266／:1272）存在的原因。加新数值参数**必须走这两个函数**。

### 3.2 掩膜语义（inpaint／outpaint）

- **掩膜＝输入 PNG 的 alpha 通道**：`alpha=0`（透明）处才是要重画的地方，`alpha=255` 保留。
- ⚠ 若输入图**没有** alpha 通道，`LoadImage` 会给出全 0 掩膜 ⇒ 采样器什么都不重画、输出≈原图（**白跑一场**，
  而且看起来"成功了"）。这是本通道最容易静默失败的一处。
- 造掩膜三种办法（`image_inpaint.yaml` 注释里的原文）：① 画图工具把要换的区域抠成透明导出 PNG；
  ② python：`cv2.imdecode(...,IMREAD_COLOR)` → `np.dstack([img, alpha255])` → 目标区 `alpha=0` → `imencode` 存盘；
  ③ ComfyUI 里用 SAM／手动掩膜节点出"黑=mask0、白=mask1"的图再转 alpha。
- outpaint 的 `feather` 像素内 **mask>0 ⇒ 会被重画**，所以"原始区完整保留"只对 feather 之外的部分成立。

### 3.3 直驱（不经引擎）：`tools\comfy_run.py`

```
python D:\AIWorkflow\tools\comfy_run.py --workflow <json> --set KEY=VALUE … --ref <图> --n 3 --out <目录> --prefix p
```

- `--set` 映射到 `__KEY__`。
- ⚠ **`--set` 不会把文件拷进 ComfyUI 的 input，只有 `--ref` 会** ⇒ 要喂 `CTRL_IMAGE=xxx.png`
  必须**成对用**：`--ref <路径> --set CTRL_IMAGE=<同一个文件名>`。
- ⚠ `--set SEED=` 会被随机种子覆盖，**锁种子要用 `--seed`**（做对照组时必须锁，否则"差异"是噪声）。
- 直驱**绕过引擎的 gate 步** ⇒ 走这条路的出图**没有任何机械闸**。这是 GAP-S1 那一类洞的图片链版本，
  登记在 §八.2；要正式产物请走引擎流。

### 3.4 尺寸口径（G5 的边界，别拿它量错东西）

- **G5 管的是模型输入尺寸，不该量输出容器**。实例：`h3_one_click_movie` 默认输出 1920×1080，
  `1080/32=33.75` 不是 32 倍数 ⇒ 若给那条流补 G5 会**当场拦停现役流**，所以 10-02 批 1 刻意只补 G11
  （原文写在 `image_refine.yaml` 的 hint 里）。
- i2i 的 `width/height` **只喂跑前自审**；实际输出尺寸由 `src_image` 决定（`image_i2i.yaml` 注释原文）。
- ⚠ **文字与实数不一致的坑**：多份 yaml 的定稿提示词写着"竖幅 9:16 构图"，而默认尺寸是
  `2560×3840`／`832×1216`——**两个都是 2:3**。要严格 9:16 得改 `2160×3840`／`768×1344`。
  这不是笔误级别的细节：出图比例由尺寸决定，提示词里那句"9:16"对扩散模型**没有约束力**。

## 五、判据接口：`check_preflight.py` 的 image 分支（逐条，带行号）

**通道归属**：`channel_of()`（:562）里 `if k in ("image","img","picture","first_frame","t2i","i2i"): return "image"`（:583-584）。
⚠ 本通道声明的 kind 是 `image/img/i2i`，而代码还认 `picture/first_frame/t2i` ⇒
写 yaml 时用别的词也能被认成图片通道，但**别这么写**（口径散）。

**图片口径的判据与视频通道不同，逐条列**（都是本轮实读代码，不是转述）：

1. **无格式要求**（:692-695）：图片（首帧／定妆）没有格式标准，只查"会被实体化／字面化"这类共性坑。
   若内容被识别成视频格式（`fmt != "plain"`）⇒ **warn**「图片稿套用了视频格式——图片口径不要求分块/字段」。
2. **混用降 warn**（:724-730）：`ch == "image"` 时 mixing 残留报 **warn**，视频通道报 **error**。
3. **器材名词**（:732-746）：正面描述里出现运镜器材词＝**error**（会被实体化渲进画面）；
   **只写在禁令句里** ⇒ 图片／云端通道**降 warn**（否定式实测有效，出处见 §一），
   而 H3 通道**照拦**（禁令即在点名）。⇒ 这条差异是**刻意的**，不要在提示词层统一。
4. **120 字下限不适用**（:753）：`if ch != "image" and len(prompt) < 120` ⇒ 图片稿短提示词不会被念"像占位"。
5. **字面化风险词**（:750-752）：命中 `LITERAL_RISK` ⇒ warn（历史案例：『蝶形双翼』被渲成真实蝴蝶翅膀）。
6. **哑女／无声角色**（:747-749）：声明了但没写全「全程不出声、不张嘴」⇒ **error**（通道无关，会被开口）。
7. **提示词是字面量 `None`**（:755-756）⇒ **error**（历史上真出过这事故）。
8. **G5 分辨率**：管**模型输入尺寸**，不管输出容器（§三.4）。
9. **G11 项目段**：核 `output_root` 的项目段——**这是 9-18 仙戮四条串进无音批次夹那一类事故的正面拦截**，
   所以 10-02 批 1 给两条 manifest 驱动的流（`image_batch_draft`／`image_draft_batch_sdxl`）
   只补 `[G5,G7,G11]`、给 `image_refine` 只补 `[G11]`（它没有 prompt，硬塞 G7 会报"没有提示词可校验"＝打死流）。

**未裁不算通过**：`channel_of()` 认不出的 kind 返回`未裁`（记 warn、不打 ✓）。
本通道的 kind 词**机器认得**，所以不受这条影响；受它影响的是千问（GAP-C2，用户已裁"暂时不改"）。

## 六、做不到的（边界，别拿它当承重墙）

1. **depth／几何锁定不可用**。`DepthAnythingV2-L` 对**风格化 CG 帧**只给出糊团（权重是在真实照片上训的）；
   换成手搓高对比深度块后输出**仍是图案不是场景** ⇒ 问题不只在预处理器，
   **union 的 depth 模式号有没有真被切过去尚未证实**。未决判因实验：同一张已知好用的控制图，
   A/B 比「自定义节点 `FluxUnionControlNetMode` 传 2」与「核心节点 `SetUnionControlNetType` 传 depth(=1)」——
   ⚠ **两套编号不同**（官方 FLUX-Union-Pro：canny 0／tile 1／depth 2／…；ComfyUI 核心：openpose 0／depth 1／hed 2／canny 3／…）。
   **证实前锁构图继续走 Canny(mode 0) 那条已验证的链**（`previz_control`）。
2. **没有真·inpaint 模型**（FLUX dev 不是 inpaint 专用）⇒ 大区域替换仍偏弱。
   要更好得下 `flux1-fill-dev` fp8（≈11.9 GB，走 hf-mirror）。**本轮没下，别写成"已有"**。
3. **同一场景的多机位／多角度一致做不了**（"这个巷子的另一个角度"）：i2i 只保同一构图、
   inpaint 只改掩膜内、depth 那条又不通；云端 Seedream 侧有同样的实测（"i2i 锁不住机位"）。
   目前只能靠 Redux 挂场景参考给"像同一个世界的另一个角度"，或每张单独出、一致性靠人工挑。
4. **锁人物身份**：Redux／FaceID 挂锚**本机实测全败**，跨批次复用同一体也锁不住 ⇒
   锁脸走 **i2i 挂脸锚**（`G4` 那套），别指望模板在就能用。
5. **严格三视图／正交多视图**（同一角色正／侧／背严丝合缝）：纯扩散做不到，要 3D 或专门的多视图模型。
   ⚠ **"多套造型并排／转身图"能做，但那是"一张图里画几个样子"，不是几何一致的三视图**，别混为一谈。
6. **"保持这张图的场景，只把某个主体挪远／挪位"现在可以做**（走 inpaint：把主体 alpha 挖空，
   提示词描述远处的小主体）——这是 09-28 补模板才有的能力；此前一轮三试均败就是因为缺这一环，
   当时被误判成"本机图片链不行"。**这条记在这里是为了防止再误判一次。**

## 八、已知缺口与不做什么

1. **本文件补上之后，GAP-C1 的"零真源"那半闭了，"厚薄差"那半只剩两条通道**。
   GAP-C1 有两个判据：①零真源 ②厚薄差（真源合计 < 最厚那条 60.8 KiB 的 35%，即 < 21.3 KiB 判 thin）。
   本轮重扫实测：本文件 **23.0 KiB** ⇒ 图片链**已不在 thin 名单**，`missing` 栏也空了；
   GAP-C1 现在只剩 `cloud_sd`（4.1 KiB）与 `qianwen`（11.7 KiB）两条。
   ⚠ **但这不是一个干净的胜利，必须把判据的局限写在这里**：厚薄差量的是**字节数**，不是规则密度
   ⇒ 一条通道可以靠"写得长"逃出判据。本文件不是灌水灌出来的（23.0 KiB 里绝大部分是模板占位符表、
   实测数字表与判据行号），**但结果上它确实躲开了那个阈值**。所以：
   **别把"图片链不再 thin"读成"图片链的规则已经够了"**——它仍然没有自己的提示词写法规范（§一），
   depth 那条仍然不可用（§六.1），直驱仍然绕过所有闸（§八.2）。
   要真治这条判据，得把口径从"字节数"换成"每条链有没有对应的判据与实测件"，那是改判据＝要用户点头。
2. **直驱 `comfy_run.py` 绕过所有闸**（§三.3）。要堵得给直驱也接一道 preflight，
   这属于改现役行为 ⇒ **本轮不做**，只登记。
3. **`auto_draft` 与现行纪律冲突**：它默认让云端 LLM 生成／改写提示词并自动重试，
   而现行纪律是"验证／对照类出图一律手填 prompt、关 LLM 润色，正式生产才开"。
   ⇒ 用它之前**必须显式确认 `use_llm` 的取值**，别拿默认值跑对照实验。
4. **本通道没有自己的资产编号与 sidecar 口径**：那是资产层的事（GAP-A3／批 3），
   本文件不定义，只提醒"图片链出的图落进批次夹后要归资产层管"。
5. **不做**：不在本文件里写提示词写法规范（§一）；不抄别的通道的实测结论（§一）；
   不为了"看起来完整"而把 depth 那条写成可用（§六.1）。
