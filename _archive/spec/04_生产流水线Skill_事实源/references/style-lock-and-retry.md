# 风格基线保存与失败处理

视觉变化的专业判断维护在 [craft-foundations.md](craft-foundations.md) C；写词方式维护在 [prompt-injection.md](prompt-injection.md)。本文件只规定怎样保存已审基线、比对漂移和分类返工，不再另造全片光照禁令。

## 基线保存

先用已有项目的已审素材；新项目通过获授权小样建立基线，不要求总是拿故事的第一镜当风格样本。

保留已审参考图、采用版本、素材职责、适用范围与明确不采用的元素；可控的seed和参数只记录实际值，不把它们当一致性保证。使用现有审核文档／基线文件，无则在交付资产清单中描述，不强制另建固定JSON。

| 层级 | 示例 | 使用方式 |
|---|---|---|
| 全片／角色不变量 | 画风、材质语言、身份特征、载具主结构 | 只复用当前镜头适用且获批的部分，不让特殊动作／伤痕污染全片 |
| 场次条件 | 时间、天气、室内外光源、场景布局、剧情状态 | 按场次设定变化；不能因为锁风格就把室内暖灯搬到室外冷夜 |
| 单镜选择 | 机位、动作相位、表情、焦点、局部照明效果 | 为本镜意图服务；必要时与前后镜检查过渡 |

“光影句一字不改”不是通用规则。逐字复用只用于本次仍成立的不变量；场景或光源变了应写新的相应条件。具体判断与例外引用专业卡，不复制另一套定义。

批量检查时，将产物与适用于当前场次／镜头的基线并排比较；有剧情依据的变化不叫漂移，未获依据的偏离也不能事后美化成风格选择。

基线采用新版本后，按 [asset-and-resume.md](asset-and-resume.md) 复核相关依赖，不把所有旧素材直接判废。

## 失败先分类，不盲目重跑

| 情况 | 先做什么 |
|---|---|
| 服务内容审核拒绝 | 了解拒绝原因；仅在合法合规且授权范围内修改请求，不绕过安全限制、不重复相同提交 |
| 并发／排队／客户端超时 | 查任务状态与现有输出，不把客户端失败当服务端未执行，不重复提交运行中的任务 |
| 视觉偏离 | 对照本镜的适用基线与真实锚点，分辨版本选错、素材污染、提示矛盾或模型未执行 |
| 动作／接触不对 | 先查动作意图、相位、参考与接口条件；只有可见问题确需空间／动作条件时才考虑预演，不默认搭3D |
| 身份问题 | 按角色锚定规范查实际输入、有效脸部细节和检测局限，再决定派生参考或修改方法 |
| 剧情／信息不成立 | 回镜头功能与跨场信息检查，不能靠调色、锐化或堆音效补出不存在的信息 |

重试限额、80%提醒和预算上限只由 [production-protocol.md](production-protocol.md) 维护，执行授权按 [communication.md](communication.md)。本表不新增重试额度，不默认云端替代，不把“分类完成”当作新批次启动许可。
