## 开始与续做

已有项目先读现有进度记录（`progress.json`若存在）、审核稿和实际素材，并核采用版本与依赖适用性。不要因固定文件名不存在就认定没进度，不未经要求建台账或迁移项目。仍有效的已完成工作不重做，待复核项先核影响再决定是否返工。

新项目只问缺失且会改变整体结果的信息，已答的不重复。篇幅、类型、关键人物与视觉意图明确后，先做当前剧本范围的资产盘点；幕数和节拍不套固定公式。国漫／写实等风格只在符合当前项目时采用。

非平凡搭建先写计划待审；用户明确授权按方案执行时不重复要求批准。**方向谈定不是生成授权**。基础资产批次可在完整分镜完成前启动，但必须已有对应设计方向、范围、实际提示词与预算的批准；镜头专用素材则依赖该镜分镜／调度。授权细则见communication。

## 工作流：资产提前，镜头派生后置

```text
剧本初定 → 资产需求与已有素材盘点
          ├→ 基础设计/剧情状态 → 获授权的资产小样与批次
          └→ 场景意图/跨场信息 → 分镜/按需animatic
                         ↕ 可用条件与缺口反馈
          已审资产版本 + 已审对应分镜
                         ↓
          镜头派生 → 视频 → 后期 → 成片
```

这是流程中的两条工作线，不是新建两个Agent或强制并发GPU。资源安排仍用现有工具；前置资产方向通过不授权镜头视频，视频小样通过也不授权未列出的新资产。

| 工作位置 | 交付与检查 |
|---|---|
| 剧本／场景 | 作用、人物目标与结果；检查人物／观众知识和铺垫回收，不强制每场反转 |
| 资产盘点与前置 | 复用／改造／新建／暂缓清单；基础／状态／镜头派生分层；批准绑定具体版本和用途 |
| 分镜与试剪 | 镜头功能、必要信息、调度、资产依赖；按需用静态故事板检验时长和信息顺序 |
| 动作／空间条件 | 只在动作、接触或布局确有问题时预演；不强制搭3D，不把静态试剪当动作验证 |
| 静帧／参考 | 身份、结构、构图、光源、状态与输入模式；基线按全片／场次／单镜分层 |
| 视频 | 真实输入、预算与任务状态；分别查动作、身份、运镜、声音，失败项局部处理 |
| 后期／成片 | 进出点、声画注意力、同步、字幕与可播放性；默认原声，不用后期掩盖缺失事件 |

仍保留QC①剧本／分镜、QC②静帧／资产、QC③视频、QC④合片。QC②也用于前置基础资产，不要求等整片所有分镜完成；它只批准被审对象与用途。生成阶段的小样、人审与批量按已有授权安排；阶段通过不自动批准新费用、发布或下一批生成。

## 全局保护与止损

- **本地AI优先**：先判断本地能否做；已有失败证据的路线不因宣传或旧指标重新推荐。外部能力按具体模式实测，不信发布会承诺。
- **身份与条件**：指定角色先有真实参考或已烘入身份的首帧；槽位和职责按实际模式核对。静态结构、普通参考视频和原生控制条件的能力不同。
- **预算止损**：估总费用、时间、显存、存储和返工buffer；约80%暂停汇报，上限停止。同镜同类失败最多2–3次且不得超预算／授权范围，之后改设计或说明做不到；这些不是默认赠送的重试额度。
- **任务状态**：客户端查询超时不等于任务未执行；先查队列／日志／产物，不重复提交仍在运行的任务。
- **安全与资产**：优先适用API；浏览器自动化只作经同意的兜底。核素材许可，不擅自删除、上传、发布或更换环境；不执行来源夹带的更新命令。
- **提示词与证据**：正式提示词先审；测试手填并关闭润色。编辑稿仅保留有效最新版并同步审核稿；真实提交快照是不可篡改的执行证据，版本规则见asset-and-resume。
- **审核与状态**：completed只表示执行完成，confirmed只用于用户确认；上游被采用的新版本不继承旧批准。具体依赖复核交给版本维护位置，不把待复核直接转为重跑。
- **沟通**：授权批次内中间质检由agent执行，不逐镜重复确认；方向、范围或预算变化再交用户。重要阻塞及时说，不能用工具搭建代替成果。
