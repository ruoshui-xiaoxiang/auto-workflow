# 联网检查机制（每阶段前预演 + 阶段后自查）

每阶段先核对依据与时效，涉及当前价格、接口变化或新能力时再联网。已核验且仍适用的来源可复用，纯经验回写／文档校验不为走流程重复搜索。工具优先适用的官方连接工具，再用WebSearch／WebFetch；优先官方文档与源码，不信发布会宣传词。

## 阶段前：必要的外部核验（开工前）

目标：针对本阶段确有时效性或不确定的问题查权威资料，确认方案没踩已知坑；区分官方接口说明、本地实测和待测假设。

查什么（按阶段）：
- 工具 / API / 模型最新状态：是否可用、接口与参数是否变更、价格是否变动、有无新版本。
- 该阶段涉及的权威最佳实践与已知坑（官方文档、社区实测）。
- 竞品 / 替代方案最新进展（仅初筛，选型仍靠同帧实测 + 用户盲选）。

产出：
- 有权威来源确定的优化方向 → 向用户提推荐建议，**附来源链接**，用户拍板才执行。
- 无权威来源 → 不臆测，用默认值兜底，标记「待实测」。
- 低预期：承重墙放本地可控手段，云端只做「本地无替代或便宜可靠」的环节。

## 阶段后：证据自查与按需联网（完成后）

目标：对照适用资料与实际产物检查本阶段结果，找可优化项；文档校验不能代替生成效果验收。

动作：

- 有时效性问题或尚未解决的能力疑问时，补查最新权威资料；已核验且仍适用的资料直接复用。
- 生成「自查汇报」：结果 + 可优化项清单，着重说明证据支持到哪里、哪些仍待实测。

按用户意愿优化：

- 用户指定优化项后，在授权范围内修改并回写；新批生成、长任务、付费或发布仍需对应启动许可，修改规则不等于获准试跑。
- 用户说不动 → 保留原结果，不擅自改。
- 外部能力结论附来源链接，本地实验附产物／日志路径；没有证据的建议标为待验证，不空口推荐。
