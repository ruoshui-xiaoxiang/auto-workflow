# 首尾帧配对：约束端点，不保证中间动作

## 何时使用

先确定【事件脚本】的可画起止态，再判断是否需要锁定结束位置／姿态／物件状态。起止差异明显只是考虑尾帧的理由，不是自动加尾帧的充分条件。静物、微动和没有指定结束态的镜头通常只用首帧；动作强、资源紧或尾帧约束冲突时先小样比较。

首尾帧是边界条件，不是动作发动机。中间由模型生成补全，不把它称作保证正确的“自动插值动作”，也不把首中末相似度当运动路径验收。

## 接口边界

- **本地部署的 H3（示例）**：`<本机路径略>` 的 `MiniMaxH3ImageToVideo` 提供 `first_frame`、`last_frame`；脚本参数 `--last-frame`。当前节点首帧拉伸、尾帧居中裁切，提交前核对画幅与裁切结果。
- 当前脚本的 fl2va 与 ref2va 是分离路径；不能在未接支持的情况下同时宣称“首尾硬约束＋参考图锁身份”。ref2va 普通参考图不是首帧输入。此限制不推断到所有官方云端接口。
- 即梦 `frames2video`、Seedance 2.5 的首尾帧路线曾被记录；实际使用前重新核验接口规格，不能照搬本地参数或声称本轮已验证云端效果。

## 配图与事件设计

```text
开头：可定格的状态A，谁在哪、手中有什么、身体如何支撑。
中段：A如何到B；攻击／接触或落空／回收等关键事件及先后。
结尾：可定格的状态B，为下一拍留下明确起点。
```

首帧通过角色锚、场景锚、景别与画风基线派生。人物身份可以先烘入首帧，再走不带参考图槽的 fl2va，不要求在不兼容接口里重复挂图。

尾帧优先从首帧 i2i 派生，只改必要的动作状态。身份、服装设定、场景和光照保持一致；若镜头设计有位移／景别变化，应保留那项有意差异，不把构图也机械锁死。派生只能降低漂移风险，仍须两张都过 QC②，检查本人、肢体、道具、接触、结束态和光照。

## 拆段接续

同一完整招式优先一次生成。资源吃不下且用户同意才拆，详见 [本地预算](local-render-budget.md) 和 [武打连续性](combat-motion-continuity.md)。

- 后段优先继承前段成片实际结束态，而非重新生成设计中的理想尾帧。
- 检查末尾连续帧，选最后干净、动作状态合适的帧；不能固定要求倒数第2或第3帧。W链抽倒数第3帧只是一次实验实现。
- 记录抽取帧与剪辑点；前段播放至该处，再接后段，避免较晚状态退回较早状态。
- 静帧不携带速度；首尾对上后，还要看切点前后方向、速度、支撑脚与重心。不同景别继承状态而非强套同一张构图。
- 中间段是否挂尾帧按结束态必要性和资源决定。“只给最后一段挂尾”是长镜节省资源的一种策略，不是通用禁令。

## 验证分四层

1. **条件**：实际模式、首尾图路径、画幅、帧数、步数、seed和LoRA是否正确。
2. **端点**：抽成片首／末帧对照输入，相关度作为辅助；中帧不必在像素相似度上恰好居中。
3. **片内**：正常速度播放，再查关键事件前后连续帧；动作顺序、路径、支撑、接触、回收、肢体及身份不能跳变。
4. **接段**：查上段末态与下段首态及两侧运动趋势；没有重复起势、瞬移、光照／道具重置。机器完成不等于用户确认。

## 已有证据及限度（2026-09-21）

- 某短片G07，H3／576×1024／158帧：首／尾灰度相关约0.995，中帧对两参考约0.81／0.91。这证明本例端点贴近，不证明所有中间动作都正确。
- 某古装短片镜14记录端点相关约0.986；属于另一个端点验证，不扩大为武打验证。
- D1大幅尾帧：首尾参考人脸相似度0.885，但成片 `flow_mean=0.671`，低于B2的1.135。增加端点位移没有在这条实验中换来更大整体运动量。
- W1→W2采用前段实际抽帧接续，证明链式输入可生成；运动路径尚未完成人审。W2有低分身份抽样待复核，不能写“连招能力已提升”。
