# 武打动作与跨段连续性

## 使用范围与证据等级

用于双人攻防、连续招式、线稿指导和“动作像姿态展示”的诊断。先区分三个问题：动作设计是否合理、生成是否跟随、跨段剪接是否连续；不要一律归因于线稿不够细。

- **项目实证**：下列“某双人打戏项目”输入记录与切点有数据库、日志和成片抽帧交叉支持，只代表该批任务。
- **局部实验**：本地 H3 的首尾帧、shift、光流结果仅适用于记录的条件，未构成武打能力验收。
- **待测方案**：完整招式生成、连续姿态条件、去除参考图中无关姿态等须做小样对照，不承诺必然改善。

## 1. 先核查实际输入，不从界面名称推断能力

| 输入 | 可以提供什么 | 不能据此声称什么 |
|---|---|---|
| 单张线稿／整张九宫格，作为普通参考图 | 姿态、构图、角色关系的视觉提示 | 逐帧时间控制，或每一格都按序执行 |
| 首帧＋尾帧 | 起始与结束的画面约束 | 中间运动路径、接触和受力正确 |
| 骨架／线稿帧序列作为普通参考视频 | 动作时序参考；跟随强度由模型决定 | 专用逐帧控制或轨迹硬锁 |
| 模型原生 pose／scribble 等视频条件 | 对连续结构施加专用条件 | 自动保证身份、肢体拓扑、接触与动力学 |

检查实际请求的模型、模式、首尾帧开关、素材槽位、顺序、帧率、时长及裁切。项目日志／数据库只读读取；不要为探接口提交生成。每份参考写明“采用什么、不采用什么”，脸、造型、场景和动作职责分开。静态 FLUX ControlNet 只解决出图结构，不能当作 H3 已接时间控制的证据。

## 2. 以完整动作因果为单位，不以线稿张数切任务

先设计一招的闭环：起势 → 攻击路径 → 接触或落空 → 对方响应 → 回收 → 落地／下一招支点。动作节点只画需要确认的状态，不为凑数量加姿势。

```text
起势：A、B各在哪侧、朝向哪里；谁支撑、谁持什么道具。
发起：谁的哪只手／脚沿什么方向接近哪个可见目标。
交互：发生格挡／接触还是明确落空；B怎样响应。
回收：肢体和道具沿什么路径离开，重心转到哪只脚。
结束：两人站位、朝向、支撑脚、持握状态，下一招从这里开始。
```

这些是创作／检查槽位，不把不适用项生硬塞进每句提示词。先看动作是否说得通，再决定关键帧数量。回旋动作须能看出转髋／转身、支撑脚转向与回收；仅提膝→伸腿→收腿不足以说明“回旋”。

一条生成能吃下时，优先完成同一招的起势到落地。分镜切换不等于独立生成任务：必要切镜可以保留，但不能让模型在每段重新设计同一次起势。时长按动作节拍分配；每张线稿等时播放只是幻灯片，不是连续运动预演。慢镜只给明确的强调拍，不能让整招一直展示伸腿姿势。

## 3. 必须拆段时，传递实际状态

仅在资源或时长约束确实需要、且用户同意后拆，详见 [拆镜与预算](local-render-budget.md)。

1. 在动作完成／支点稳定／语义停顿处切，避免把一次踢腿的提膝、伸展、回收分别独立生成。
2. 先看前段实际成片，而非照抄方案终态。记录两人朝向、位置、支撑脚、手脚及武器状态、光位、运动方向和速度趋势。
3. 同视角接续优先抽前段末尾最后干净且状态合适的帧。倒数第几帧不是通用常量；W链用过倒数第3帧，仅是该次实现。
4. 只有实际支持首帧的模式，才能把它作为下一段起始条件；放到普通参考槽仅是软参考。不同景别另出首帧也要继承上述状态。
5. 静帧没有速度信息：检查切点前后连续帧，必要时选择稳定停顿。不要承诺“用了末帧就无缝”。
6. 若抽取点早于文件末尾，记录帧号与时间，剪辑点也对齐该处；不能前段先播放更晚状态，再让后段从较早状态起步。查看是否需去掉重复持帧，不机械重复首尾帧。

场景锚优先只携带所需空间／光照。带着交剑姿态的双人图不是纯空景锚；反复复用可能干扰新动作。可裁切、另制空景或限定职责，但“限定文字一定压住姿态继承”仍须验证。

## 5. 验证不只看“动得多”

先正常速度连看，再围绕出手、接触、转身、回收、落地与切点逐帧复核。至少分别报告：片内动作、跨段连续性、身份／肢体／武器、声音四项；未查的项写“未查”。

- 光流上升可能来自运镜、背景或衣物；不是连招正确的证明。动作验证可固定机位，见 [运动量尺子](local-render-budget.md)。
- 首尾相关高仅证明画面端点接近；不证明中间招式执行、受力、顺序正确。
- ArcFace低分先查脸大小、转头、模糊、遮挡和锚图基线；抽样低分不是整片换脸帧计数。
- 双人镜逐人对锚，查角色是否互换；骨架检不出先判不可测／需复核，不直接当不存在人。
- 机器测完标 `completed`；用户看过认可才标 `confirmed`。不能以分数代替人审。

最小对照：选一招，在同角色、风格、动作内容和预算下比较现有独立拆段与完整动作方案；资源吃不下则测实际末态接续。再决定是否测试更密线稿或专用时间条件。先写评价项与预期可见结果，手填提示词、关闭润色；获本次试跑授权后才提交，不借技能更新顺便开跑。

## 6. LoRA与其他路线的边界

- 当前未验证可直接用于本机 H3 的专用武打 LoRA。turbo8step 是加速 LoRA，不是武打能力权重；本地 ref2v 用途也不能自动解释成武术训练。
- FLUX／SDXL 静帧 LoRA 没有视频时间维度；Wan／HunyuanVideo LoRA 不能直接装到 MiniMax-H3。
- [VACE官方仓库](https://github.com/ali-vilab/VACE) 与 [官方UserGuide](https://github.com/ali-vilab/VACE/blob/main/UserGuide.md) 列出 pose、scribble 视频条件及参考图＋姿态视频组合。属于可核验接口路线，不是本机武打质量保证；本机效果、显存和速度尚待实测。
- MagicFight等研究可作为后续线索，不能把论文名等同于可下载、许可清楚、兼容H3的现成LoRA。推荐权重前核验来源、基模、版本、许可证、输入及同类动作样片，再获授权安装／测试。
