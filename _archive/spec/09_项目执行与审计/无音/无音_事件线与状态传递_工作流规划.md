# 《无音》事件线与状态传递 · 工作流规划

> 2026-09-14 起草，待审。
> 起因：讨论"AI 能不能接着已有片段续生成"→ 结论是视频生成目前只有**像素续**、没有**事件线续**；
> 而把"事件线续写"做出来，靠的不是更好的视频模型，是**把事件线显式化 + 打通状态传递**这两件事。

## 〇、修订 v2（2026-09-14 晚）——**架构从三层改四层，优先级整体重排**

### 新增的一层：**裁判层（L3）**

修订的直接依据是 Physics-IQ（DeepMind，WACV 2026）与 Physics-IQ Verified 榜单：

| 模型 | 输入 | Verified 分 |
|---|---|---|
| Magi-1 24B **+ GeoPhys（BoN）** | v2v | **58.2** |
| Magi-1 24B **裸跑** | v2v | 48.4 |
| Cosmos3-Super-Image2Video | i2v | 42.7 |
| **MiniMax H3 (FL2VA) ← 我们的模型** | i2v | **39.8** |
| 混元 Video 1.5 | i2v | 33.4 |
| **Sora 2** | i2v | **26.5** |

三条结论直接落到本计划上：

1. **榜首是靠"外挂裁判"拿到的**：同一个模型，挂上物理校验器 + best-of-N，从 48.4 → **58.2（净赚约 10 分）**。→ **先补裁判，比先补规划更值钱。** 这是本计划优先级重排的唯一理由。
2. **我们的本地模型在"物理一致性"上排 i2v 第 4，高于 Sora 2、混元 1.5、Wan 2.2** → **不必为了物理性换模型**，本地优先路线成立。
3. 语义层缺的不是可微性，是**语义本身写不出可微的 loss** → 所以只能用**判别器替代 loss**。裁判层的理论位置就在这里。

**两条裁判，两层各一：**

| 层 | 裁判 | 状态 |
|---|---|---|
| 语义层 | `check_continuity.py`（承接/道具/知情/时长 9 类校验） | ✅ 已建并跑出真问题 |
| 像素层 | 姿态误差（SDPose 提骨骼 vs previz 骨骼）＋ 物理一致性 | 🔨 本轮建原型 |

### 优先级重排（新原则：**先补裁判 → 再补派生 → 最后补保真度**）

| 新 | 内容 | 为什么在这个位置 |
|---|---|---|
| **P1** | **裁判层**：像素层裁判原型（用已有 canny/pose 冒烟产物就能第一次量化） | 榜单实证收益最大、且不需要新模型 |

## 二、目标 / 非目标

**目标**
- 事件线的**结构**变成机器可读真源（`shots.yaml`），桌面文档由它单向生成 —— ✅ 已达成。
- 建立**跨镜状态台账**（画面层），每镜定稿后回写 —— ✅ 已建成，待养成"定稿即回写"的习惯。
- 建**两条裁判**：语义层（自动查断链/错位）＋ 像素层（自动判废片、量化姿态误差）。
- **量化** L1 的状态传递保真度，用裁判（而不是眼睛）选主通道，再接进引擎。

**⚠️ 范围缩减说明（v2 审核时补，重要）**

原目标写"运行提示词也由 yaml 生成"——**这条没做，而且不该那么做**。提示词正文是 10 块模板的长散文（单镜 5–6KB），塞进 yaml 会让真源不可读。实际实现是：

- **结构**（场景/道具/承接/时长/状态锚）→ `shots.yaml`
- **正文**（长散文）→ `prompts/shot0X_ref2va.txt`

即**两处真源，各管一件事**。代价：漂移风险没有消除，只是从"整篇文档 vs 脚本"缩窄到"**正文 vs yaml 的结构字段**"。补法＝在校验器里加一条 **E10：正文与 yaml 的关键词一致性**（场景关键词、道具名、角色名是否在正文里出现），把"人工同步"降级成"人工写、机器查"。

**非目标（明确不做，理由见第七节）**
- 不做**云端**视频续写（Seedance extension 等）。
- 不追世界模型（Genie 类）。
- 不做"全自动 AI 剧组"。
- **不做 H3-World**（本机硬件不可行，见 §〇）。

## 三、架构：**四层 + 一台账**（v2）

```
L0  事件线（结构化，机器可读）        shots.yaml            ← 单一真源（结构）
      │                                  prompts/*.txt      ← 单一真源（正文）
      ├─→ 桌面分镜表与状态台账（.md，单向生成）
      └─→ previz 脚本骨架（生成，待做）
      │
L1  状态传递（3D 状态 → 可控结构）    Godot previz 骨骼/深度/姿态 → 控制通道
      │                                  ⚠️ 出图侧已通（canny/pose）；视频侧待验
L2  渲染（质感/光影/音频）            H3 本地（FL2VA/Ref2VA）/ Seedance 云端
      │
L3  裁判（自动判对错）  ┌─ 语义层：check_continuity.py（承接/道具/知情/时长）
      │                └─ 像素层：pose_referee.py（废片闸 + 姿态误差）
      │                     ↕  best-of-N（用裁判挑，不用眼睛挑）
台账 跨镜状态记忆                     state_ledger.yaml（画面层）＋ state_卷一/卷二.md（叙事层）
```

**四层怎么咬合**：L0 说"要发生什么" → L1 把它变成时空结构 → L2 渲染 → **L3 判对错，不对就回到 L1/L2 重来（best-of-N 或换通道）** → 定稿后回写台账 → 台账喂下一镜的 L0。裁判层不是末端质检，是**回路上的闸门**。

**为什么台账能治漂移**：下一镜的提示词不再由我手写、由你记忆校对，而是"上一镜定稿状态 + 本镜事件"结构化拼出来。道具在谁手上这种事变成**查得到**的字段，而不是两小时前的对话残留。

**为什么裁判层优先级最高**（v2 的核心改动）：语义层没有可微表述（"她愣住"写不出 loss），所以只能用**判别器替代 loss**。Physics-IQ 榜单实测：同一模型 + 外挂物理裁判 + best-of-N，48.4 → 58.2。也就是说**收益来自裁判，不来自更聪明的规划**。

- 引擎新增 `control` 型 task（depth/pose 预处理 + 注入，与现有 `video` task 并列）
- 镜头**分级投入**：只有动作戏/精细动作镜走 L1；静镜保持现在的首尾帧直出（沿用既有成本原则）
- 接进 `engine/workflows/*.yaml`，与 `localai.ps1` 链路上手

**验收门**：一条动作戏镜在引擎里端到端跑通（自动起服务 → 控制通道 → 出片 → 落批次）
**成本**：本地 0 元，开发约 1 天

### Phase 3 · 事件线的派生与校验（最后做）

**做什么**

**验收门**：新镜的提示词由 yaml 生成、人只审不再手写
**成本**：约 1 天
