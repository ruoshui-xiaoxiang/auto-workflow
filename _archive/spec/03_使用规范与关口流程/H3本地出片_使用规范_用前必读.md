## 0. 这是什么

在**本机消费级显卡上跑 MiniMax H3**（开源音视频联合生成模型），产出带原生音轨的视频镜头。

- 模型：MiniMax H3（开源，年营收 <$20M 可商用；**协议排除美/欧/英/韩地区，中国可用**）
- 硬件档位：RTX 5060 Ti 16GB + 32GB 内存
- 输入模式（官方五模式）：**T2VA** 无图 / **I2VA** 单首帧 / **FL2VA** 首尾帧 / **L2VA** 单尾帧 / **Ref2VA** 参考图＋参考视频＋参考音频
- 编排：单镜 / 无人值守批次 / 多镜一键成片 / 父段-续段接力
- 正式入口：**`D:/AIWorkflow/engine/run.py`**。ComfyUI 只是执行后端；`ComfyUI_H3/run_h3.py` 是旧排障脚本，**不是出片入口**。

具体项目落点由 `--project` 决定；本文不写死某个项目。

## 0.1 繁星入口（2026-11-02 起）

- **人类导航**：`E:\繁星\00_启动台\launchpad.json` 有 5 个白名单入口（娱乐流、agent 出片引擎、素材库、规范手册、创作工作区）；看板 `8777` 的 `/map3d` 是唯一 3D 星图，`/starfield`（8788）是主序星，`/launch` 是启动台。它们都是 UI/导航，不是新的 ComfyUI 端口。

## 2. 配方与模板（模式 ≠ 配方）

**五根正交轴**：输入模式 / 配方 / 几何 / 编排 / 档位。UI、摘要、manifest 都必须按实际值显示，不能用一个“标准 8 步”糊过去。

| 配方 | 步数与 LoRA | 入口 | 适用与边界 |
|---|---|---|---|
| **single8** | 8 步 + `fl2v_turbo_8step` | `h3_keyframe_modes`（T2/I2/FL/L2）、`h3_i2va_batch`、`h3_i2va_video` | 单遍主力；video/keyframe 链 LoRA 强度默认 **0.7**，batch 链 **1.0**（验收基准 v9）；按 YAML 实际值，不要手改 |
| **clean20** | 20 步，不挂 LoRA | `h3_keyframe_modes_clean`、`h3_ref2va9_clean` | 干净档；慢，但不用 Turbo LoRA |
| **ref2v4** | **4 步** + `ref2v_turbo_4step` | `h3_ref2va9_daily`（9图/3视频/3音频，总 ≤12）；旧 4 图兼容 `h3_ref2va_video` | 步数必须=4，配对由 RunPlan 硬拦；LoRA 强度默认 1.0 |
| **r3_two_pass** | base 8 + coarse 4 + refine 4；`fl2v_turbo_4step_alpha8-T8-convert` + learned upscale | `h3_two_pass_modes` | `scale_by` 默认 1.25；2.0×≥264 帧是已知崩溃边界，须 `confirm_big_scale=true`；只覆盖单镜中性档 |

> 命名提示：`--inspect` 摘要里的 `recipe_id` 是内部显示名（single8→`std8`、ref2v4→`ref2v4`、clean20→`clean20`、R3→`r3-2p...`）；矩阵列名和本文用 `single8`／`ref2v4`／`clean20`／`r3_two_pass`。两者指同一配方，不是两套口径。

### single8 参考图（现行模板已固化，手工连线仅排障）

```
[有图才接] LoadImage(首帧/尾帧)
  └→ MiniMaxH3ImageToVideo(clip, video_vae, 提示词, 宽, 高, 帧数, first_frame/last_frame)
        ├→ positive
        └→ av_latent
UNETLoader(fl2va_pruned_int8)
  └→ LoraLoaderModelOnly(fl2v_turbo_8step, 按 YAML 的 strength)
        └→ MiniMaxLowVRAMAttention(head_chunks=4)
              └→ MiniMaxH3DualClockSamplerT8(steps=8, shift_video=12, shift_audio=3,
                                              sampler=dual_clock_euler, scheduler=native_flow)
                    ├→ BasicGuider(model, positive) → guider
                    ├→ sampler / sigmas
RandomNoise(seed) → SamplerCustomAdvanced(...)
  └→ MiniMaxH3AVDecodeT8(av_latent, video_vae, audio_vae)
        ├→ frames → CreateVideo(fps=24, audio=generated_audio)
        └→ generated_audio ─┘
              └→ SaveVideo(format="mp4", codec="h264")
CLIPLoader(qwen3vl_nvfp4, type=minimax) / VAELoader(video fp16) / VAELoader(audio fp32)
```

**四条不可省**（按配方解释，不是所有配方都相同）：

1. **LoRA 必须与配方配对**：single8 挂 8 步；ref2v4 挂 Ref2V 4 步；R3 挂 alpha8-T8-convert；**clean20 明确不挂**。挂错 LoRA 或把 ref2v4 写成 8 步，RunPlan/配对检查会拦。
2. **必须走 T8 `DualClockSamplerT8`**；不要退回原生 `KSampler`（音频会噪）。
3. **音频走 `MiniMaxH3AVDecodeT8`**（同时出 frames + generated_audio）。
4. **视频合成走 `CreateVideo` → `SaveVideo`**，`format` 填 `"mp4"`；现行模板已固化，不要手改。

> Ref2VA 不是上面的单首帧图：它走 `h3_i2v_ref2va9_api.json`，按素材数动态注入 **9 图 / 3 参考视频 / 3 参考片原声 / 3 独立音频**，总文件 ≤12；提示词是官方六段，不是三字段。边界见 §3、§6。

## 3. 怎么跑（正式入口＝engine/run.py）

### 3.1 启动服务

```
双击 D:\AIWorkflow\ComfyUI_H3\run_H3_ComfyUI.bat
```

现行启动参数（`VERSION_LOG.md` 现读）：

```
python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build \
  --use-ck-attention --port 8189 \
  --output-directory D:\AIWorkflow\ComfyUI_H3\output --reserve-vram 6.0
```

服务起在 `http://127.0.0.1:8189`。首次出片慢（JIT/模型载入），第 2 条起变快。**8189 被占时不要改端口**：先查谁占着，按 §7 处理；本机只允许这一个 ComfyUI 实例。

### 3.2 先看计划，再出片

`--inspect` 只解析 RunPlan，**不建批次夹、不提交、不占 GPU**；先用它核对模式/配方/模板/几何/源稿：

```bash
cd D:/AIWorkflow/engine
py -3.12 run.py h3_keyframe_modes --inspect --project <项目> \
  --set input_mode=i2va \
  --set prompt_file="D:/.../prompt.txt" \
  --set ref_images="D:/.../first.png" \
  --set width=736 --set height=416 --set length=124 \
  --tier draft
```

确认无误后去掉 `--inspect` 真跑；`--tier` 可选 `play` / `draft` / `final`：

- `play`：娱乐流预览档；闸门 warn 降级、产物落预览区、不进资源池、不做 QC、不交付；
- `draft` / `final`：按正常落点与关口；**不要拿 play 档产物当交付**。

### 3.3 五模式的最短命令

以下只列与模式有关的差异；`--project`、`prompt_file`、宽高/长度/档位按实际补。

```bash

  --set prompt_file="D:/.../prompt.txt" --tier draft

# FL2VA：首帧 + 尾帧（顺序固定：第 1 张首帧、第 2 张尾帧）

  --set input_mode=fl2va --set ref_images="D:/.../first.png,D:/.../last.png" \
  --set prompt_file="D:/.../prompt.txt" --tier draft

# L2VA：只有尾帧
py -3.12 run.py h3_keyframe_modes --project <项目> \
  --set input_mode=l2va --set ref_images="D:/.../last.png" \
  --set prompt_file="D:/.../prompt.txt" --tier draft

# T2VA：零图（不要给 ref_images）
py -3.12 run.py h3_keyframe_modes --project <项目> \
  --set input_mode=t2va \
  --set prompt_file="D:/.../prompt.txt" --tier draft

# Ref2VA：9 图 / 3 视频 / 3 视频原声 / 3 独立音频（各自 ≤3，总文件 ≤12）
# 下面这条是 9+1+1=11 的合法组合；四类同时拉满会超 12，G4 会拒。
py -3.12 run.py h3_ref2va9_daily --project <项目> \
  --set prompt_file="D:/.../prompt.txt" \
  --set ref_images="D:/.../1.png,D:/.../2.png,...,D:/.../9.png" \
  --set ref_videos="D:/.../v1.mp4" \
  --set ref_audios="D:/.../a1.wav" \
  --set width=736 --set height=416 --set length=124 --tier draft
```

其它入口：

- **干净 20 步**：把 workflow 换成 `h3_keyframe_modes_clean` / `h3_ref2va9_clean`（参数同名，20 步、不挂 LoRA）。
- **R3 二采**：`h3_two_pass_modes`，`--set input_mode=t2va|i2va|fl2va|l2va|ref2va --set scale_by=1.25`；base/coarse/refine 默认 8/4/4，2.0 长镜未验收。

  人工看节点可打开 UI 画布 `ComfyUI/user/default/workflows/生图/E01_文生图_ZImageTurbo_1MP.json`（文生图，11 节点）或 `E02_图生图_ZImageTurbo.json`（图生图，12 节点；源图在 `LoadImage` 节点里点「选择文件上传」）。正式批量仍走 `run.py`，画布只供试参数/排障。

| `--set ref_video_audios=...` | 参考片原声（独立音频），≤3 |

## 4. 提示词要求（关键，易漏）

1. **【声音】段落必写**。H3 是音视频联合生成，不给音频指令它会自由发挥出杂乱噪声。模板：
   ```
   【声音】只有空旷的废土环境声：远处的风声、细沙流动的沙沙声、偶尔低频的风啸。
   ```

## 6. 踩过的坑（必读，踩一次记一次）

1. **comfy-kitchen 最低 0.2.26**。0.2.22 缺 `dequantize_embedding`，pruned INT8 模型加载直接报 `TensorWiseINT8Layout has no attribute dequantize_embedding`。本机现为 **0.2.39**；重装/升级前先看 `VERSION_LOG.md`，不要盲目回退。
2. **ComfyUI 版本看工作树，不看 `.git`**。H3 原生节点最低 0.30.0；本机工作树已是 **0.42.1**，但 `.git` 仍是 0.39 历史（tarball 覆盖）。版本看 `comfyui_version.py` 或 `/system_stats`；回滚用 tarball，不要只 `git checkout`。
3. **旧版 `SaveVideo` 只收 VIDEO 类型**（0.30.x 的坑）：不能直接接 `VAEDecode`（IMAGE），必须 `VAEDecode/AVDecode → CreateVideo → SaveVideo`，`format` 填 `"mp4"`。现行 0.42.1 模板已固化这条链；手工改图时照旧。
4. **输出位置由引擎 relocate 兜底**：ComfyUI 用 `--output-directory` 启动，但引擎不依赖它把文件写对；批次夹以 manifest 为准。旧 `run_h3.py` 的 `OUTPUT_DIR` 对齐问题只对旧脚本成立。
5. **音频必须在 T8 双时钟下采样**。原生 `KSampler` 是单一时基，处理不了 H3 的 AV 双流协议 → 8 步音频噪、要 20 步才干净；`MiniMaxH3DualClockSamplerT8` 8 步即干净且耗时不增加。
6. **分辨率必须 32 的倍数**，否则 `patchify_video` 崩（`shape invalid for input of size`）。
7. **本机不使用 sage**（2026-10-15 起）：启动参数固定 `--use-ck-attention`，**不要加 `--use-sage-attention`**，也不要把 sage 与 KJ patch 混开。旧“Sage 二选一”的口径已作废。
8. **长镜 VAE Decode 可能崩显存**：显存压力下在 Decode 前加 VRAM-Cleanup 节点缓解。
9. **LoRA 位置与配方绑定**：`LoraLoaderModelOnly` 插在 `UNETLoader` 与 `DualClockSamplerT8` 之间；加载后日志显示 `208 patches attached` 表示生效。clean20 不要把 LoRA 加回来；ref2v4/R3 不要挂 fl2v 8 步 LoRA。
10. **`ref_image_size` 是节点档位参数，不是素材槽**。现行 9 图模板已写死 `"max"`；不要把它塞进 `ref_images`，也不要靠它掩盖素材数量问题。参考图身份仍受分辨率/构图影响，`max` 不是万能。
11. **G6 帧数**：107–345 放行，吸附 17n+5；107–123 带训练区间外 warn；**362 已停用**，历史批次不重排。
12. **G7/中文**：中文正文在 draft/final 会被 G7 拦；要么 `use_llm_polish=true` 让引擎改写，要么自己写英文。play 档只是降级放行，不等于合规。
13. **G13 项目级六槽只能本人落单**：`--set` 传进去会被登记成 `rejected_args`，不算数；首跑前用 `decision_sheet.py` 填项目决定单。别改 `preflight: off` 绕。
14. **Ref2VA 额度**：9 图 / 3 视频 / 3 视频原声 / 3 独立音频，总文件 ≤12；音频“合计 ≤3”是官方 README 的解释口径，节点 schema 是每类各 3，默认 warn，`AW_H3_AUDIO_STRICT=1` 才按合计拦。9+3+3+3 同时给必超 12，不存在。
15. **D 接力**：`h3_relay_movie` 只接 CLI；硬条件＝服务**无 sage**、接力镜画布 **64 对齐**；manifest 的 `relay_pairs` 由人判。面板拒绝不是坏了。
16. **git 拉 GitHub 要绕代理**：本机 git 可能配了 `http://127.0.0.1:7890` 但代理常挂；用 `git -c http.proxy= -c https.proxy= clone ...` 直连。

## 10. 清晰度修复链（2026-09-13 实测，2026-10-24 命令已更新）

H3 本地出片的**脸/清晰度**按这个顺序榨；配方与命令按现行引擎改写：

| 手段 | 效果 | 代价 |
|---|---|---|
| 参考图 `ref_image_size=max` | 参考图用更长边，身份保真更好 | 5s 约 236s → 436s（≈1.8×；旧测量） |
| `--set width=1344 --set height=768`（可选） | 脸的像素更多 | 像素 ×1.75；16GB 卡注意显存 |
| **CodeFormer 逐帧修脸**（`face_restore.py`） | **明显** | **50–65 秒/条、零重生成** |
| 头 1s 不修 + 0.8s 平滑过渡（ffmpeg） | 修掉逐帧跳动 | 零 |

**推荐链**：`Ref2VA 满额度（或 4 图兼容）→ 4 步 + Ref2V 4 步 LoRA → T8 双时钟 + 原生音频 → face_restore.py → 头 1s 平滑`。

```bash
# 1) 出片：ref2v4 的步数必须是 4；现行 9 图模板已把 ref_image_size 写死为 max
cd D:/AIWorkflow/engine
py -3.12 run.py h3_ref2va9_daily --project <项目> \
  --set prompt_file="D:/.../shot0X_ref2va.txt" \
  --set ref_images="D:/.../1.png,...,D:/.../N.png" \
  --set width=1344 --set height=768 --set length=124 \
  --set steps=4 --tier draft

# 2) 逐帧修脸（CodeFormer，本地现成模型；路径换成引擎批次夹里的成片）
py -3.12 D:/AIWorkflow/ComfyUI_H3/face_restore.py <批次夹>/video/<成片>.mp4 \
  --fidelity 0.5 --out <批次夹>/video/<成片>_facefix

# 3) 头 1s 不修 + 平滑过渡（修掉开头逐帧跳动）
ffmpeg -y -i <批次夹>/video/<成片>.mp4 -i <批次夹>/video/<成片>_facefix.mp4 \
  -filter_complex "[0:v][1:v]blend=all_expr='A*(1-clip((T-1.0)/0.8,0,1))+B*clip((T-1.0)/0.8,0,1)'[v]" \
  -map "[v]" -map "0:a" -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a copy <批次夹>/video/<成片>_final.mp4
```

**跳动的成因与正解**：CodeFormer 是**逐帧独立**修复 → 帧间无连续性约束 → 会“跳”。**把片段切得更细治不了**（粒度不是原因）。真解两条：① 本节的“头段不修+平滑过渡”（帧级跳动局限在头段时够用）；② T8 的 `Face Refine Window`（让 H3 整段重生坏脸时间窗，天生连贯；缺的 T8 转码 LoRA 用仓库自带 `tools/convert_minimax_h3_lora_for_comfyui.py` 转换）。

**残留模糊＝固有上限**：`pruned 剪枝版 + 该分辨率`的合成上限。要突破只有三条：完整版 INT8（需 64GB 内存）、二次采样（补真细节，但要下 `minimax_h3_latent_upscaler_3d_fp16.safetensors`、EXP、本机很慢）、或脸关键镜走云端。**硬盘虚拟内存顶不了内存**（每步都要把权重搬进显存，落在页面文件＝每步读硬盘，慢几十上百倍）。

> 旧文里的 `--steps 8` + Ref2V LoRA 是错误配对；ref2v4 必须 4 步。旧 `--len 362` 也已停用（G6 上限 345）。

四条落规：

1. §4 那句“参考帧锁外貌、提示词负责动作与运镜”**不是风格建议而是硬约束**：正文里出现参考帧没有的外观名词（发色／服装／道具／背景建筑），模型会在 1~2 秒内用文字改写像素——同 seed、同参数、同首帧，只换文字就换人。

4. 别拿本节的 0.82~0.90 推翻“H3 锁不住脸”：这是**同一段内**接着首帧往下长，身份由像素惯性给；跨镜／跨生成仍是老结论（上限≈0.57，脸关键镜要换脸或走云端）。
