## 一、现行判据（用户 2026-10-30 裁定）

**只有两条硬限制，且都只判"功能能否实现"：**

1. **硬件跑不动，且软件层面无解**（量化／卸载／分块都救不回来）
2. **缺失节点全网拿不到，且无替代方案**

两条之外一律**不算**硬限制，不得据此删除：

| 不是硬限制的常见误判 | 为什么不算 |
|---|---|
| 权重还没下载 | 属软件层面可解决；已有同族件可替代的，连下载都不必 |
| 需要装某个节点包 | 只要包可从官方源或公开仓取得，就不算 |
| 需要喂入自己的素材 | 输入缺失不是能力缺失 |
| 纯后期件没有生成链 | **这正是它的正常形态**（插帧/放大/对比类本就无 UNETLoader 与采样器） |
| 本地缓存查不到节点名 | 缓存不是全网；必须做 GitHub／HF 检索并留证据 |

## 五、硬规矩（对本目录同样生效）

1. **这些画布不是出片入口。** 出片一律 `cd D:/AIWorkflow/engine && python run.py <workflow>`；
   禁止绕过 run.py 直连 8189 提交 `/prompt`。本目录只用于人工看图、比参数、抄写法。
   直连提交只允许经 `tools/comfy_run.py` 作排障／手工测量。
2. 新增包要重启 8189 才生效；重启前后确认队列 running/pending 为 0。
3. 判定"缺件"以运行中实例 `/object_info` 为准；`Note`/`MarkdownNote`/`PrimitiveNode`/
   `GetNode`/`SetNode`/`Label (rgthree)`/`Fast Groups * (rgthree)` 是前端或虚拟节点，
   不出现在 `/object_info`，不能据此判缺。
4. `mode=4` 只阻止执行，**不消除缺件**——节点类型未注册时画布照样一个红框。
5. 恢复链：所有删除件在 `_删除读数.json` 与 `_恢复台账.json` 里留有源路径与 sha256，
   可按路径原样恢复；归档区永不 rm。
