### 3.2 掩膜语义（inpaint／outpaint）

- **掩膜＝输入 PNG 的 alpha 通道**：`alpha=0`（透明）处才是要重画的地方，`alpha=255` 保留。
- ⚠ 若输入图**没有** alpha 通道，`LoadImage` 会给出全 0 掩膜 ⇒ 采样器什么都不重画、输出≈原图（**白跑一场**，
  而且看起来"成功了"）。这是本通道最容易静默失败的一处。
- 造掩膜三种办法（`image_inpaint.yaml` 注释里的原文）：① 画图工具把要换的区域抠成透明导出 PNG；
  ② python：`cv2.imdecode(...,IMREAD_COLOR)` → `np.dstack([img, alpha255])` → 目标区 `alpha=0` → `imencode` 存盘；
  ③ ComfyUI 里用 SAM／手动掩膜节点出"黑=mask0、白=mask1"的图再转 alpha。
- outpaint 的 `feather` 像素内 **mask>0 ⇒ 会被重画**，所以"原始区完整保留"只对 feather 之外的部分成立。

### 3.3 直驱（不经引擎）：`tools\comfy_run.py`

```
python D:\AIWorkflow\tools\comfy_run.py --workflow <json> --set KEY=VALUE … --ref <图> --n 3 --out <目录> --prefix p
```

- `--set` 映射到 `__KEY__`。
- ⚠ **`--set` 不会把文件拷进 ComfyUI 的 input，只有 `--ref` 会** ⇒ 要喂 `CTRL_IMAGE=xxx.png`

### 3.4 尺寸口径（G5 的边界，别拿它量错东西）

- ⚠ **文字与实数不一致的坑**：多份 yaml 的定稿提示词写着"竖幅 9:16 构图"，而默认尺寸是

### 四-补三、depth 通道定性实验（10-04 夜，带真值）

产物：`D:\AIWorkflow\tmp\Z-Image_深度_20261004\`。这一节的价值一半在结论、一半在**两把被当场做废的尺子**。

**废尺一：交叉相关。** 拿"输出图自身再估的深度"与"控制深度图"做 Pearson，量出 A 组挂控制 +0.082。
看着像正效应。但把所有深度图两两交叉排成矩阵后发现：**无关深度图之间的相关均值 = 0.719**，
而我所有读数（0.46~0.60）**全在地板以下**——连"喂进去的那张控制"对相关值都比不上两张没喂的无关图。
⇒ 单目深度估计器的输出高度模式化（都是"下方亮、上角暗"），**任何两个它生成的图都天然高相关**，
这把尺子从原理上就不能用来判"深度锁没锁"。A 组那个 +0.082 是噪声。

**废尺二：主体轮廓带富集（第一次尝试）。** 用源图 canny 闭包出主体轮廓带，量深度图梯度在该带内的占比。

且源图 canny 把背景岩石也算成"主体"），**不能用来下结论**，只能当旁证。

**立住的尺子：真值已知的合成深度图。** 我自己造一张深度图（地平线 40 %、地面二次曲线渐变、
左中一个近距白块、右侧一个中距灰条），布局是我定的，所以输出该在哪里长出边界是**先验已知**的。
再拿"提示词与深度结构相冲突"的句子（"清水混凝土墙占满画面、无任何景深线索"）当探针——
基线必然落在平墙上，控制若有效就会把两块板顶出来。

| 组 | 边界带梯度占比 | 随机带占比 | **富集比** | 读法 |
|---|---|---|---|---|
| B 基线（不挂控制） | 0.036 | 0.036 | **1.01x** | 零锁定 |
| C1 挂翻转极性的估计深度 s1.0 | 0.041 | 0.040 | **1.02x** | 零锁定（**不是极性反了**） |
| C2 挂合成深度 s1.0 | 0.081 | 0.033 | **2.42x** | **真锁上了** |
| C2 挂合成深度 s2.0 | 0.407 | 0.021 | 19.75x | 过驱：抄灰阶，不是锁空间 |
| 控制图自身（满分参照） | — | — | 50.51x | — |

**四条结论**：
1. **depth 通道是活的**（2.42x vs 基线 1.01x）。09-28 那句"手搓高对比深度块仍是图案不是场景"
   现在能定案：**FLUX union 的 depth 模式号没生效**，与深度图质量无关。悬案结掉。
2. **估计器出的深度图在这条路上等于没喂**（1.02x）。量化原因：DepthAnythingV2 的输出
   **锐边占比 0.00 %**（合成深度图 0.32 %），控制图走 VAE 编码，**没有断缝就没有信号**。
   ⇒ 这不是"CG 帧估不准"，是**相对深度图天生不带物体边界信息**，换任何一张估计深度图都一样。
3. **手工搓粗深度块是可用且零门槛的正路**：不必先装 3D 软件，画几个灰度矩形就能定机位与站位。
   `image_depth` 已按此改造成"深度图由调用方给"。
4. **depth 与 canny 的强度行为不同**：canny 到 1.5 只是无增益；depth 到 2.0 会**过驱抄灰阶**。
   **两条都停在 1.0。**

⚠ 本节样本数：C2 每组 1 张、单 seed。它证的是"通道有没有信号"这个二值问题，
不是"锁得多准"的刻度——要拿它进正式流程，得另做多 seed 标定。

**要复刻参考图那种风格，两条真路（各付各的价）**：
- **i2i 在参考图上低 denoise 重绘**：Δ IRE −1.67、Δ光比 +0.08、Lab 相关 **0.992**、

  但 **Lab 直方图相关 0.037**——颜色分布完全不像，肤色占比只有 4.6 %。
  ⇒ 提示词能调"明暗"这一根轴，调不出"那一族颜色"。

**本轮最大的新发现是一个稳定性坑，不是风格**：

| 跑法 | 纯控制臂（不挂 LoRA）成功率 |
|---|---|
| 纯控制**连跑** 4 帖 | **4/4 成**（稳态 11.53~11.55 秒） |
| 纯控制**夹在共存臂之间** | **0/3 成**（4.63~4.87 秒即崩） |
| `/free` 清缓存后再跑 | **2/2 成**（首帖 20.03 秒＝多付一次加载） |

崩点：`comfy/ldm/lumina/controlnet.py:29  c = self.before_proj(c) + x`
⇒ `RuntimeError: Expected all tensors to be on the same device, cuda:0 and cpu`——
控制分支的权重已退回 CPU，主干隐状态还在 GPU。矩阵里崩的 5 帖**全是不挂 LoRA 的纯控制臂**，
挂 LoRA 的 20 帖零崩。机制指向"跑过共存臂之后，纯控制臂复用了节点缓存里那个失效的控制补丁"，
ComfyUI 内部为什么让缓存失效我没继续挖（属上游 bug）。
**生产规则：一批只跑一种挂法；必须混跑就先 `/free`。**
⚠ 相关不等于因果：这里"夹着跑必崩／连跑不崩"是 3/0 与 4/0 的对照，样本小但方向干净。

**时间**：纯控制与共存稳态都是 **11.4~12.3 秒／张**（再确认 §四-补四：LoRA 不加价）；
i2i **5.18 秒**；崩帖 4.6~4.9 秒。

样本账：35 帖（10 配置 × 3~4 seed），单档提示词两组；判读用 `light_scopes`＋自加的

## 五、判据接口：`check_preflight.py` 的 image 分支（逐条，带行号）

**通道归属**：`channel_of()`（:562）里 `if k in ("image","img","picture","first_frame","t2i","i2i"): return "image"`（:583-584）。

**图片口径的判据与视频通道不同，逐条列**（都是本轮实读代码，不是转述）：

1. **无格式要求**（:692-695）：图片（首帧／定妆）没有格式标准，只查"会被实体化／字面化"这类共性坑。

2. **混用降 warn**（:724-730）：`ch == "image"` 时 mixing 残留报 **warn**，视频通道报 **error**。
3. **器材名词**（:732-746）：正面描述里出现运镜器材词＝**error**（会被实体化渲进画面）；
   **只写在禁令句里** ⇒ 图片／云端通道**降 warn**（否定式实测有效，出处见 §一），
   而 H3 通道**照拦**（禁令即在点名）。⇒ 这条差异是**刻意的**，不要在提示词层统一。
4. **120 字下限不适用**（:753）：`if ch != "image" and len(prompt) < 120` ⇒ 图片稿短提示词不会被念"像占位"。
5. **字面化风险词**（:750-752）：命中 `LITERAL_RISK` ⇒ warn（历史案例：『蝶形双翼』被渲成真实蝴蝶翅膀）。
6. **哑女／无声角色**（:747-749）：声明了但没写全「全程不出声、不张嘴」⇒ **error**（通道无关，会被开口）。
7. **提示词是字面量 `None`**（:755-756）⇒ **error**（历史上真出过这事故）。
8. **G5 分辨率**：管**模型输入尺寸**，不管输出容器（§三.4）。
9. **G11 项目段**：核 `output_root` 的项目段——**这是 9-18 仙戮四条串进无音批次夹那一类事故的正面拦截**，
