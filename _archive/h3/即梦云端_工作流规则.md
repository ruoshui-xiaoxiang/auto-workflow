#### 🔴 补一的**作用域限制**（10-01 当天下午被用户推翻的一半，必须读全再抄）

上面那批"磨损词"里，**只有用在皮肤／头发／光上的那部分是对的**。
**把磨损词搬到服装和武器上，会当场把"设计感"换成"实用感"**——用户原话：

> "你写的应该是偏向实际历史上存在的服装材质和样式，所以显得没有美感，偏向实用。
> 实际短片中更多是采用动漫或者游戏服装设计，不看实用性，只关注样式和材质的美观性。"

⇒ 逐词归类，**别整批照抄**：

| 词 | 该用在哪 | 不该用在哪 |
|---|---|---|
| 毛孔／颊侧细绒毛／干纹／不磨皮 | ✅ **皮肤** | — |
| 单向硬光／硬阴影／大面积暗 | ✅ **光** | — |
| 胶片颗粒／定焦／浅景深 | ✅ **镜头** | — |
| 划痕／氧化暗斑／磕碰凹点／接缝积沙／被沙磨脏的下摆／拉丝纹／旧崩口 | ⚠ 只可用于**背景道具**（岩台、沙地） | 🔴 **不要写进服装与武器**——它们是"真实旧物"叙述，会把造型拉回历史复刻与实用 |
| 以利骑乘／耐磨／铆钉缝合／鞣制牛皮／分片战裙＋马裤 | 🔴 **整类都不要**——这是**功能理由句**，从百度网盘库**平民／骑马**类目挖来的，本身就是历史实用语汇 | — |

**根因**：我 10-01 上午从 `中世纪欧洲人物`／`西方奇幻人物` 两库挖"武装女性下半身"时，
挖到的是**平民与骑马类目**的实用服装词（见 §四-补二），**那批词治好了"一圈一圈的裙子"，同时把整套造型变成了历史复刻**。
⇒ **挖词要先认类目**：要"样式美"就去**贵族／王后／神职／战斗法师**类目，**不要去平民、骑马、工匠类目**。

### 四-补三、动漫／游戏服装设计的四条写法（10-01 用户定调，v8 起用）

**服装只服务剪影与材质，不服务功能。**四个动作：

1. **夸张比例**——肩甲比肩宽出一倍、披风比人还长、裙摆拖地三米、腰封束到非人的细。真实服装不允许的这些，正是游戏造型的骨架。
2. **非功能部件**——悬空垂下的细银链、链端挂菱形金属片（不固定在任何地方）、大腿上一圈银环、胸口一枚大宝石徽章。**明确写"不固定在任何地方"，模型才不会试图让它合理。**
3. **材质本身要好看**——镜面抛光（故意亮，与 §四-补一 的"磨损"正相反）、丝绒配缎面拼接、银丝刺绣整圈镶边、珐琅与宝石。**不写它怎么做的、怎么穿脱。**
4. **纹样成系统**——甲缘、披风边缘、裙摆下缘、剑身那一列符文**是同一套纹样**。这一条是游戏角色设计的核心手法：**视觉系统统一＝造型立得住**，比堆装饰有效得多。

⚠ **渲染仍走写实**（胶片颗粒＋单向硬光＋皮肤毛孔全留）——要的是**"用实拍质感渲染一套非实用设计"**，即黑神话／FF16／鬼刀那个档位，**不是把图画成动画**。

⇒ **分片＝金属／皮革的竖条片，不是布料荷叶层**；装饰写在铆钉、皮带银扣、丝带、发箍这些**件数**上。
⚠ **只借结构词，不借画风**：这批是 3D 国漫渲染、且明写"非真人摄影"，与实拍档相反。
🔴 **10-01 下午追加限制（读这条之前先读 §四-补一 的作用域表）**：本节那套"分片战裙＋合身马裤＋高筒靴外翻靴口＋铆钉皮马甲＋以利骑乘"
是从**平民／骑马类目**挖来的，属**历史实用语汇**——它治好了"裙摆一圈一圈"，
但把整套造型做成了**历史复刻**，用户判"太保守、像旧时代、没有美感"。
⇒ **要"样式美"就换类目挖**：`中世纪欧洲人物` 挖**国王贵族**（不是平民）、`西方奇幻人物` 挖**法师／神职／王后**（不是佣兵工匠），
且只取**名词与件数**，**不取功能理由句**（"以利骑乘""耐磨""铆钉缝合"整类删）。写法改走 §四-补三。

## 五、视频侧写法（官方口径，出处 ②）

**骨架＝三段式**（把模型当视觉内容生产者，用导演的思维写结构化 Prompt）：

```
[一句话概述]  主体 ＋ 地点 ＋ 事件 ＋ 题材/风格 ＋ 特殊运镜
[具体情节]    用时间戳或「镜头 N」切分，逐段写 画面 / 运镜 / 动作 / 台词 / 音效，尽量正向描述
[结尾补充]    贯穿始终的细节：机位/运镜、环境/场景、声音、氛围
```

| # | 规则（官方原话要点） | 备注 |
|---|---|---|
| V1 | **素材指代**：按上传顺序编号（图 1／视频 1／音频 1）并写明用途；多主体**列清单**；分工具体到"参考什么"；部分参考要写"参考哪一部分" | 官方明确**不建议**只在图上写字然后 prompt 里直接叫名字 |
| V2 | **时间戳**以整数秒为单位；区间**必须连续**（不许 `0-3 秒…5-6 秒…` 跳）；**不建议**用时间戳控制频率（"一秒摇头 3 次"） | 官方同时支持「镜头 N」切分 |
| V3 | ★ **负向控制只支持两类：字幕、音频**。字幕：`不要字幕`／`不额外加入对白字幕`；音频可细分到 音效／BGM／对白：`无 bgm，只生成环境音和动作音`、`不要任何声音` | ⇒ **不是"随便写负面词"的通道**，见 §六-3 |
| V4 | **镜头语言**：通识词直写（景别／推拉摇移跟环绕俯冲／机位）；热门运镜直写（一镜到底、希区柯克变焦、航拍、FPV、子弹时间）；**过于小众专业的名词要转成「名词＋描述性解释」**（"移焦，画面焦点发生平滑转变…"） | |
| V5 | **动作**优先概括性描述（"双方展开近身搏斗"），只在有记忆点的动作上写细节，**不重复写相同动作**；**表情**用描述性语句、少用成语（"津津有味地吃饭"→"脸上带着满足的笑容，大口地吃饭"） | |
| V6 | **首尾帧**优先用参数 `role=first_frame/last_frame`（**会锁画幅**，严格对齐首帧图）；用 `role=reference_image` ＋ prompt 里指定也能做，但**不锁画幅** | |
| V7 | **帧数 8n+1**：编辑任务把输入视频帧数调成 8n+1，输出才能与原时长一致（官方例：161 帧＝6 s 17 帧） | 与本地 H3 的 `17n+5` 网格**不是同一套** |
| V8 | 音频约束要**在提示词开头与结尾各写一遍**，并**一次性穷举音乐类同义词**（音乐／背景音乐／BGM／配乐／器乐／旋律／合成器音效／氛围铺底音），否则模型换表述绕过 | 与本地 H3 的"十块元叙述句被当台词念"是**相反的**病 |

**常见坑（官方 FAQ，逐条都有优化前后对照）**：

| 现象 | 官方解法 |
|---|---|
| 情绪过度响应 → **瞳孔发光**（蓝光/红光/黄光） | 以**最高优先级**明确约束"人物为正常人眼、不发光"，限制环境光只作用于面部轮廓；把「狂热／极度震惊」改成「惊叹」等常规词 |
| **文字拼写错误** | 英文拆成独立字母并要求按序出现；把要展示的文字**做成图片**当参考素材 |
| **写了"不要字幕"仍出字幕** | 避免在台词后复述词语并追加语气/表情/动作描述；台词按 **`角色台词（情绪）：内容`** 格式拆分（例：`周女士台词（声音发颤）："太像了。"`）；确保参考视频本身不含字幕 |
| 编辑前后**时长差约 0.33 s** | 改用参考生成模式；或把输入帧数调成 8n+1 |
| **画面出现指纹状/鞋印状纹理**（草地树叶等密纹理区） | 把输入图尺寸调到**不超过输出分辨率**；输出 1080p 比 720p 概率低 |
| **背景音乐约束不生效** | 见 V8；或后期分离人声 |
| 复杂任务效果不稳定 | 拆成多个简单任务分次做，再后期整合 |

## 六、与本机现行写法的冲突点（★给本机用的一节）

**1. tag 式名词罗列是明确违规项（P2）**
本机旧稿里出现过「形制分解图」式的并列堆叠。官方反例就是这种形式。⇒ **服装句改写方向＝完整短句 ＋ 压缩名词短语**（后者的原生措辞样本见
`E:\创作\_待审文档\漫剧服装造型_提示词案例调研_20260928.md` §三，如「酒红色抹胸斜肩高开叉鱼尾晚礼服」「长款大拖尾鱼尾裙摆」）。

**2. 「简洁精确优于堆叠华丽」怎么读——不是"要写短"**
官方两条反例针对的是 **①tag 罗列 ②冗余画质形容词**（杰作／8K／极致／绝美类），而**不是"结构描述不许长"**：
- 官方自己的正例就是完整长句；官方文字渲染示例、平面图示例都很长。
- 即梦官方页面（③）明说**无字数限制**；真正硬的是工具契约 **2000 字**（§三）。
- ⚠ 社区流传的「关键词 20–40 字」**与官方页面直接矛盾**，**不采信**；若日后要裁，以"同帧 A/B"为准。
⇒ **本机现行口径据此收敛为：结构写细、形容词写少。** 这与 09-27 得到的"华丽＝装饰密度**逐项点名**（名词＋数量）"是同一件事——
点名的都是**名词与计数**，不是形容词。两条独立来源在此收敛，可信度较高。

**3. 负面词：本通道**基本不吃**（V3）**
官方**只**文档化了「字幕」「音频」两类负向控制。⇒ **图片侧一律把禁令改写成正向句**（这也与本地 H3 侧既有的"正向句承担"工艺一致）。
⚠ 两点留白：① 即梦**网页 UI 是否有独立的负面提示词输入框**，本轮**未在 UI 上核实**（标注 `[未核实]`，别写成"即梦没有负面词功能"）；
② 若发现 UI 有该入口，本条要当天改写并登记 C 号。

**4. 参考图的用法我们其实没照官方做（P5）**
官方范式是"挂锚图 ＋ 在提示词里指代"。本机现状是**不挂锚、纯文字重出**（因为 09-28 实测本机两条锁脸路线全败，见 [[reference-local-face-identity-transfer]]）。
⇒ 这是**有意的偏离**，不是遗漏；但它意味着官方 P1/P5/P8 关于参考图的那几条在本机**暂时空转**。

**5. 「同一份提示词换模型」在本通道内不成立**
图片侧 7 个 `seedream_*` 档位官方是**合并写在同一份指南**里的，但 §三 的分辨率/参考图上限**逐档不同**，
且官方明说"5.0 lite / 4.5 / 4.0 理解力更强、画面不再泛白"。⇒ 换档位＝换一次人审，不要默认"换个档位效果差不多"。

## 八、已知缺口与不做什么

**1. 即梦稿目前不进任何机检——这不一定是缺陷，理由要写对**
本通道当前是**人工执行通道**：生成由用户在网页画布上手动完成，agent 只做取回＋机检产物。
`check_preflight.py` 的 `channel_of()` 只认 `h3 / cloud / image`，**即梦稿不进 G7**——
但与千问通道（风险 28）不同，**这里不构成"被判错"的风险**，因为没有引擎调用会去判它。
⇒ **本通道暂无新增 `channel_of()` 分支的必要**；只有将来**改成 agent 代跑 CLI 生成**时才需要，
那时按 `千问云端_工作流规则.md` §六 的七步清单走一遍。

**2. ⚠ `seedance_2.5` 是两条通道共用的同一个模型，两套契约并存（未裁，冲突表 C84）**
- **云端 SD 通道**（`云端SD提示词模板_十块.md`）：中文十块。
- **本通道**：官方三段式（§五）。
同一个模型、同一份权重，本机却有两套写法契约，且**都没有同帧对照**。⇒ 登记 C84，**未裁**；
在裁之前，**不许拿任一通道的效果去证明另一通道的写法对**。

**3. 风险登记（冲突表 风险 30）**
即梦是当前**最主要的出图通道**，但它的提示词层**零 A/B 对照**：官方说"简洁优于堆叠"、
现役稿是 800–900 字长稿、社区又说"20–40 字"——三方口径互斥，而支撑现役写法的只有"用户觉得还行"。
⇒ **风险 30**：本通道存在"照官方改一遍会让已经还行的那批一起变差"的可能，
**动写法的同时必须留旧写法对照臂**，不许整批替换。
